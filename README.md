# dsh-memory · 稳定记忆系统

给 DSH（DeepSeek Harness）的 agent 一套**稳定记忆**：写得进、存得住、取得回、忘得掉，并且对时间有感觉。

> 设计的出发点不是「让模型多记点东西」，而是 `docs/0-起源.md` 里的那句判断：
> **利用有限的上下文，衍生出真正的智能**（起源 L33·第 7 条）。
> 上下文永远是有限的，所以记忆的价值不在于「记得多」，而在于**在该想起的时候想起该想起的**。

## 它解决什么问题

| 问题 | 对应起源 | 本系统的回答 |
|---|---|---|
| agent 没有时间观念 | L21（第 1 条·定闹钟） | 时间读数注入 + 到期主动提醒，到点无需用户输入自行接力 |
| 上下文塞满细节，反而变笨 | L11（细节会忘只留感受）、L17（上下文污染） | 抽取时只留结构化要点，细节进日志不进上下文 |
| 记忆无限膨胀，召回越来越慢 | L27（第 4 条·夜晚休眠整理） | 夜整理：去重、降权、归档；日/周/月层级压缩 |
| 想起一堆不相干的旧事 | L29（第 5 条·专注当前位置） | 焦点包 3~7 张卡，有阈值有预算，宁缺毋滥 |
| 不知道这个结论从哪来 | L19（感受经验） | 每张卡带来源指针与修订历史，可回溯到具体轮次 |

## 架构

依赖方向单向，绝不反向：

```text
core  ←  store  ←  consolidate  ←  host
  ↑
  └── time（时间计算，纯函数）
```

| 层 | 职责 | 关键约束 |
|---|---|---|
| `src/core/` | 契约、配置、文本、打分、抽取 | **纯函数**，禁止 IO、禁止依赖宿主（ST-1 确定性） |
| `src/store/` | 事件日志、持久化、重放、查询索引 | 只依赖 core；日志是唯一事实源，卡片是派生视图 |
| `src/consolidate/` | 去重、合并、降权、归档、层级压缩 | 只依赖 core + store |
| `src/host/` | DSH/Cordis 接线 | **唯一**允许 import 宿主包的地方 |
| `src/time/` | 时区、自然日边界、到期解析 | 纯函数 |
| `src/cli/` | 离线命令行 | 不需要 DSH 也能用 |

**事件溯源（Event Sourcing）**：所有状态变更先写 JSONL 日志（唯一事实源），内存状态与倒排索引都是日志的重放结果。这样崩溃后可以重建，也能回答「这条记忆是什么时候、因为什么变成现在这样的」。

## 快速开始

```bash
pnpm install
pnpm typecheck     # tsc --noEmit
pnpm test          # node --test 跑全部单测
pnpm build         # 生成 lib/（发布用）
pnpm cli --help    # 离线命令行
```

作为 DSH 插件安装时，`package.json` 的 `dsh.bundle.patch` 指向 `cordis.patch.yml`，宿主会自动加载。

## 设计信条

1. **每行代码都要能回答两个问题**：它对应起源的哪一条？它满足需求规格的哪个编号？两者都答不上来的代码不写。
2. **不写死参数**：所有阈值、权重、上限都在 `src/core/config.ts`，行为可调、可测。
3. **纯函数优先**：`core/` 下不允许有副作用，同样的输入必须得到同样的输出。
4. **宁缺毋滥**：召回不出来是安全的，召回错了才是有害的。
5. **不编造**：解析不出来就说解析不出来，不要猜。
6. **RSI 只是手段**（起源 L35·第 8 条）：提升的是「一把过任务的概率」，不是智能本身。记忆系统的目标同样不是「让模型显得更聪明」，而是**让有限的上下文真的够用**。

## 范围

- **本阶段做**：稳定记忆（写入 / 存储 / 召回 / 遗忘 / 时间感 / 可观测）

- 起源的第 2 条（绝不多线程）与第 3 条（强弱思考换挡）不在本插件范围内
