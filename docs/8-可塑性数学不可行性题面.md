## 一、系统与算子

记忆图谱的节点是记忆卡，边是带权关联。边权 `w ∈ [0,1]`，但**被强制吸附到 101 个格点上**：

```text
quantize(x) = round(100x) / 100
W = {0.00, 0.01, 0.02, …, 1.00}
```

两个算子交替作用：

**强化**（Hebbian，同一对记忆在一夜里被一起使用 `n` 次）：

```text
R(w) = quantize(min(1, w + δ))        δ > 0，加性
```

**衰减**（每夜一次）：

```text
D(w) = quantize(w · f)                  若 quantize(w·f) < w
     = quantize(max(0, w − 0.01))       否则
```

`D` 的第二个分支叫「线性地板」：比例衰减不足一格时强制降一格，保证衰减真的发生（这是修另一个缺陷「衰减被量化格永久卡死」留下的补丁）。

**每夜动力学**：

```text
w_{t+1} = D( R^n(w_t) )
```

真实实现：`src/core/spread.ts` 的 `nextDecayedWeight` / `reinforceEdges`；`src/core/graph.ts` 的 `quantizeWeight` / `EDGE_WEIGHT_STEP = 0.01`。

## 二、需求（全部约束的来源）

不同边的「使用频率」不同：某对记忆一夜被用 1 次，另一对 10 次。**最终权重必须能区分次数。**

> **目标**：对 `n = 1..N`（取 `N = 10`），`w*(n)` 必须是 10 个互不相同的值。

另外两条硬约束：

- **约束 A（遗忘速率不能太快）**：`f = 0.98` 对应半衰期 34 夜，符合「记忆」直觉。`f = 0.90` 半衰期仅 6.6 夜，两周忘光，产品上不可接受。**要求 `f ≥ 0.95`（半衰期 ≥ 13.5 夜）。**
- **约束 B（`δ` 必须是量化格的整数倍）**：`δ = k × 0.01`。
  **实测理由**：`δ = 0.002` 时，91 个格点中 **0 个**能真正升一格（全被 round 舍回）；`δ = 0.005` 时 **89/91** 有效（跨过半格）；`δ ≥ 0.008` 时 **91/91** 有效。

## 三、已实测的六个事实

### 事实 1：`w*(n)` 不是良定义函数——系统有多吸引子（实测）

`δ=0.01, f=0.98`，同一个 `n`，不同初值收敛到不同终值。

> **更正（P3-10 第五处，不在原清单里）**：本节原表把 `n=1` 的 27 个初值放进了
> 「终值 0.98」列，实际它们全部落在「终值 0.74」；「73 个初值各自不动」也不对。
> 原表还漏了一个会改变结论的前提——**初值集合是哪些**。下面把口径写死。

**口径**：初值取全部 **101 个格点 `0.00, 0.01, …, 1.00`**，每个初值迭代 600 夜。

| n | 收敛到 0.74 | 收敛到 0.98 | 自不动点个数 | 不同终值个数 |
|---|---|---|---|---|
| 1 | **27/101** | 0 | **75**（`0.00~0.74`） | **75** |
| 2 | **75/101** | 3/101（`0.98, 0.99, 1.00`） | **25**（`0.74~0.98`） | **25** |
| 3 | 0 | **101/101** | 1（`0.98`） | 1 |

两点必须说明，否则这张表会被读成自相矛盾：

1. **`0.74` 与 `0.98` 同时出现在「收敛到」列和「自不动点」列里**——它们是自不动点，
   也被算进自己那一档，所以两列不能相加。`n=2` 时 `75 + 3 + 23 = 101`，
   其中那 23 个是 `0.75~0.97` 各自不动。
2. **初值集合是这张表里唯一没被写出来的变量**，而它足以改变数字：换成
   `0.01~1.00` 这 100 个初值，`n=1` 就变成「**74 个自不动、26 个收敛到 0.74、
   74 个不同终值**」（表里那 75/27 变成 74/27），`n=2` 变成「自不动 25、
   收敛到 0.74 的 74 个、收敛到 0.98 的 3 个、**25 个不同终值**」。
   **`n=1` 的「75 个不动」和「74 个不动」都是实测正确值**，差别只在初值集合——
   报「多少初值不动」时必须同时报初值集合，否则数字无法复核。

`n=2` 时 101 个初值只产生 **25 个不同的终值**（`0.74~0.98` 各一个），
而 `n=1` 产生 75 个、`n=3` 只产生 1 个——**终值个数随 `n` 单调塌缩：75 → 25 → 1**。
所以「用得越多、分得越细」这个直觉是**反的**：`n` 越大，系统越倾向于把所有初值
压到同一个终值上。

**含义**：权重记录的是**历史路径**，不是频率。同样「每夜用 2 次」的边，因初始权重不同，最终可以是 0.74 或 0.98。

2. **`n=1` 那一列看起来「偏宽」不是误差，是 T4 在起作用**：`w=0` 是真不动点
   （`D(0)=0`），首带下端必然顶在 `0` 上，所以它的上沿由「撞到 `0` 之后 `n` 步强化

   实测 `0.74`；`f=0.95` 算 `0.29`、实测 `0.28`；`f=0.90` 算 `0.14`、实测 `0.14`。
   **这是首带的边界效应，不是公式失效。**
3. **倒数第二条带偏窄是 T5 截断**：末带塌缩成单点 `quantize(f)` 之后，前一条带

   被切到 `0.98` 的结果。`f=0.95/0.90/0.85/0.80/0.70` 逐个验过，**6/6 上沿都精确等于
   `quantize(f)`**。

**所以原文档「带宽」那个公式的问题被严重高估了**：它漏了 `f`（小错），
真正让表格看起来全错的是**首带边界（T4）**和**撞顶塌缩（T5）**这两个结构效应，

⇒ 「换公式没换掉那个真正的约束」这个结论成立，但**证据不是「恒为 5」**。

### 事实 6：默认 `δ` 与衰减地板步长**精确相等** ⇒ 「用一次」是零变化（实测，本文件新增）

这条是写这份题面之后才发现的，**它比「档数不够」更根本**，而且我怀疑它是 Q5 的真正答案。

**机制**：强化是 `w + δ`；衰减 `D(w)` 在「比例衰减不足一格」时走线性地板强制 `−0.01`。而 `δ` 的默认值是 `0.01`，**与地板步长恰好相等**。于是在地板区间内：

```text
w = 0.10
  → 强化：0.10 + 0.01 = 0.11
  → 衰减：quantize(0.11 × 0.98) = quantize(0.1078) = 0.11
          0.11 不小于 0.11 ⇒ 走地板 0.11 − 0.01 = 0.10   ← 精确回到原值
```

**实测（默认 `δ=0.01, f=0.98`，101 个格点，每夜共激活 1 次）**：

| 单步净变化 | 格点数 | 区间 |
|---|---|---|
| 不变 | **75** | `0.00 ~ 0.74` |
| 上升 | **0** | 无 |
| 下降 | 26 | `0.75 ~ 1.00` |

即：**「每夜用一次」与「完全不用」在前 75 个格点上无法区分**；没有任何格点会因「用了一次」而上升。要上升必须每夜 ≥ 2 次（`n=2` 时零变化格点降到 25 个）。

**后果**：`makeEdge` 的初始权重来自相似度（`same-topic` 实测常见 0.1~0.3），落在地板区间内。所以**一条新建的边，若每夜只被共激活一次，权重永不增长**——它只比「不用」好一点（不下降），但不携带任何「被用了」的增量。

**这是「分辨率 vs 响应性」的硬冲突，不是标定失误**：

| f | δ | 档数(n=1..12) | n=1 零变化格点 | n=1 终值（从 0.50） | 评价 |
|---|---|---|---|---|---|
| 0.98 | **0.01** | **3** | **75** | 0.50 | 档数最多，但用一次无效 |
| 0.98 | 0.02 | 2 | 25 | 0.74 | 抵消消失，档数减半 |
| 0.98 | 0.03 | 1 | 1 | 0.98 | 完全不响应 |
| 0.95 | 0.01 | 6 | 29 | 0.28 | |
| 0.95 | 0.02 | 3 | 21 | 0.48 | |
| 0.914 | 0.01 | 10 | 17 | 0.16 | 档数够，仍有一次无效区 |

**推论（我的判断）**：`δ = 0.01` 是「档数最大化」的唯一选择，而它恰好等于地板步长 ⇒ **最优分辨率参数与「一次强化要有效」互相排斥**。这条把 Q5 从「改精度值不值」变成了「改精度**是不是必须**」——只要 `EDGE_WEIGHT_STEP` 与地板步长仍都是 `0.01` 且 `δ` 取最小合法格点，抵消就必然存在。

**我不确定的地方——这两个我后来都验了，结论都是「不行」**（原来这里写「都没验」）：

| 候选改法 | `f=0.98` 下 `n=1` 上升格点 | 不变 | 档数 | 结论 |
|---|---|---|---|---|
| 现状（地板强制降一格，`δ=0.01`） | 0 | 75 | 3 | 基准 |
| **`δ` 取半格 0.005** | **0** | 73 | **2** | ✗ 抵消没消失，档数还掉了 |
| `δ` 取 1.5 格 0.015 | 72 | 27 | 2 | 抵消消失，档数 3→2 |
| **地板改 `max(0.01, 0.02w)`，`δ=0.01`** | **0** | **75** | **3** | ✗ **与现状逐位相同** |

两条都值得记，因为**它们的失败方式不同**：

1. **`δ` 取半格行不通，而且原因是量化的**：`0.005` 加到一个 0.01 格点上，
   `round(100x)/100` 直接把它舍回去——**半个格点根本不存在**。
   这与约束 B 里那组实测一致（`δ=0.002` 时 91 个格点 0 个能升）。
   想让 `δ` 小于一格，必须连量化格一起改，而那又回到 Q5 的死循环。
2. **`max(0.01, 0.02w)` 这个「修法」是个空操作**：`w ≤ 0.5` 时 `0.02w ≤ 0.01`，
   所以 `max(0.01, 0.02w)` 恒等于 `0.01`——**在出问题的整个区间里它和现行地板
   一模一样**。逐位相同的实测不是巧合，是代数恒等。
   这条值得单独记：**一个看起来更「合理」的公式，如果在乎的区间里恒等于原公式，
   它就不是修法，只是换了个写法**。

## 附：实测代码（可复现）

```js
import { nextDecayedWeight } from './lib/core/spread.js'
import { quantizeWeight as Q } from './lib/core/graph.js'

const night = (w, n, d, f) => {
  let x = w
  for (let k = 0; k < n; k++) x = Q(Math.min(1, x + d))
  return nextDecayedWeight(x, f)
}

// 数档数（定义 A：固定初值 w0，扫共激活次数 n —— 本文档全部档数都用这个定义）
const tiers = (d, f, w0 = 0.5, maxN = 10) => {
  const s = new Set()
  for (let n = 1; n <= maxN; n++) {
    let w = w0
    for (let i = 0; i < 600; i++) w = night(w, n, d, f)
    s.add(w)
  }
  return s.size
}

// 数档数（定义 B：固定 n=1，扫初值 w0 —— 同一个系统，数字完全不同）
// f=0.98 时定义 A 给 3、定义 B 给 74。报「多少档」必须说是哪一个。
const tiersByInit = (d, f, n = 1) => {
  const s = new Set()
  for (let i = 0; i <= 100; i++) {
    let w = Q(i / 100)
    for (let k = 0; k < 600; k++) w = night(w, n, d, f)
    s.add(w)
  }
  return s.size
}

// 找不动点带（注意：结果是「自不动点集合」，不是「吸引域」，两者不同）
const band = (d, f, n) => {
  const fps = []
  for (let i = 0; i <= 100; i++) {
    const w = Q(i / 100)
    if (night(w, n, d, f) === w) fps.push(w)
  }
  return fps
}
```

**四个口径陷阱，跑之前先看清楚**（这四个都让我算错过数）：

1. **`tiers` 与 `tiersByInit` 不是一个量。** 前者扫「用几次」、后者扫「从哪开始」。
   `f=0.98` 时一个给 3、一个给 74——**两个都实测正确，差 25 倍**。
2. **`maxN` 必须报。** `f=0.85` 在 `maxN=10` 下是 10 档（被扫描上限截平），
   `maxN=30` 下是 16 档。把 10 当成真实档数就会得出「`f=0.85` 刚好够用」的错结论。
3. **初值集合必须报。** `i` 从 `0` 开始（101 个初值）还是从 `1` 开始（100 个），
   会让 `n=1` 的自不动点数在 **75 和 74** 之间跳。`band()` 里那个 `i=0` 不是笔误——
   `w=0` 是真不动点，去掉它会把带宽从 0.74 改成 0.73，看起来像另一个结论。
4. **「带数」的定义必须写明——它天然带一个提前退出。** 本文数带数用的是
   `for (n = 1; ; n++) { 取 band(n); if (空) break; 记录; if (长度 === 1) break }`，
   **`if (长度 === 1) break` 这一句让「带数」在定义上就等于「最后一个多不动点带的
   `n` 加 1」**。也就是说 T2 那个夹逼有一半在描述**这个定义本身的形状**，
   而不是系统独立于定义的物理分辨率。
   把 `break` 去掉，`f=0.98` 的「带数」立刻从 3 变成 900（`n` 撞到扫描上限）。
   **这不影响 T1/T3/T4/T6（它们量的是单条带的几何，与计数方式无关），
   但报「多少档」时如果没写清是否用了提前退出，读者无法复核。**
   本文所有「带数」都指带提前退出的那个量；**「档数」另指定义 A/B 的可达终值个数**，
   三者不是同一个数，`f=0.98` 下分别是 **3 / 3 / 75**。
