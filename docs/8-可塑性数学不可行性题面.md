## 一、系统与算子

记忆图谱的节点是记忆卡，边是带权关联。边权 `w ∈ [0,1]`，但**被强制吸附到 101 个格点上**：

```text
quantize(x) = round(100x) / 100
W = {0.00, 0.01, 0.02, …, 1.00}
```

两个算子交替作用：

**强化**（Hebbian，同一对记忆在一夜里被一起使用 `n` 次）：

```text
R(w) = quantize(min(1, w + δ))        δ > 0，加性
```

**衰减**（每夜一次）：

```text
D(w) = quantize(w · f)                  若 quantize(w·f) < w
     = quantize(max(0, w − 0.01))       否则
```

`D` 的第二个分支叫「线性地板」：比例衰减不足一格时强制降一格，保证衰减真的发生（这是修另一个缺陷「衰减被量化格永久卡死」留下的补丁）。

**每夜动力学**：

```text
w_{t+1} = D( R^n(w_t) )
```

真实实现：`src/core/spread.ts` 的 `nextDecayedWeight` / `reinforceEdges`；`src/core/graph.ts` 的 `quantizeWeight` / `EDGE_WEIGHT_STEP = 0.01`。

## 二、需求（全部约束的来源）

不同边的「使用频率」不同：某对记忆一夜被用 1 次，另一对 10 次。**最终权重必须能区分次数。**

> **目标**：对 `n = 1..N`（取 `N = 10`），`w*(n)` 必须是 10 个互不相同的值。

另外两条硬约束：

- **约束 A（遗忘速率不能太快）**：`f = 0.98` 对应半衰期 34 夜，符合「记忆」直觉。`f = 0.90` 半衰期仅 6.6 夜，两周忘光，产品上不可接受。**要求 `f ≥ 0.95`（半衰期 ≥ 13.5 夜）。**
- **约束 B（`δ` 必须是量化格的整数倍）**：`δ = k × 0.01`。
  **实测理由**：`δ = 0.002` 时，91 个格点中 **0 个**能真正升一格（全被 round 舍回）；`δ = 0.005` 时 **89/91** 有效（跨过半格）；`δ ≥ 0.008` 时 **91/91** 有效。

## 三、已实测的六个事实

### 事实 1：`w*(n)` 不是良定义函数——系统有多吸引子（实测）

`δ=0.01, f=0.98`，同一个 `n`，不同初值收敛到不同终值：

| n | 终值 0.74 | 终值 0.98 | 其它 |
|---|---|---|---|
| 1 | — | 27/100 个初值 | **73 个初值各自不动**（每个都是自己的不动点） |
| 2 | **74/100** | 3/100 | 23 个初值各自不动 |
| 3 | — | **100/100** | — |

`n=2` 时对 100 个初值各迭代 600 夜，得到 **25 个不同的终值**（0.74×74、0.98×3、0.75×1、0.76×1 …）。

**含义**：权重记录的是**历史路径**，不是频率。同样「每夜用 2 次」的边，因初始权重不同，最终可以是 0.74 或 0.98。

### 事实 2：不动点是一个**带**，不是一点（推导 + 实测吻合）

```text
带的中心  = n · δ · f / (1 − f)
带的宽度  = 1 / (100 · (1 − f))        ← 恰好是「一个衰减步长」对应的区间
```

| f | δ | n | 预测中心 | 预测宽度 | 实测带 | 实测宽度 |
|---|---|---|---|---|---|---|
| 0.98 | 0.01 | 1 | 0.490 | 0.500 | [0.00, 0.74] | 0.74 |
| 0.98 | 0.01 | 2 | 0.980 | 0.500 | [0.74, 0.98] | 0.24 |
| 0.95 | 0.01 | 1 | 0.190 | 0.200 | [0.00, 0.28] | 0.28 |
| 0.95 | 0.01 | 2 | 0.380 | 0.200 | [0.28, 0.48] | 0.20 |
| 0.90 | 0.01 | 1 | 0.090 | 0.100 | [0.00, 0.14] | 0.14 |
| 0.90 | 0.01 | 2 | 0.180 | 0.100 | [0.14, 0.23] | 0.09 |

（`n=1, f=0.98` 实测带更宽，因下限被 `w=0` 的吸收边界截断后反向拉长。宽度公式在低权重区受线性地板影响而失真——这正是 Q3 要问的。）

**关键推论**：带内格点数 ≈ `1/(100(1−f))`。

| f | 带内格点占值域比例 |
|---|---|
| 0.99 | **99%**（几乎整个值域都是吸收态） |
| 0.98 | **50%** |
| 0.95 | 20% |
| 0.90 | 10% |

**这解释了为什么「权重不动」**：`f` 越接近 1，越多权重是吸收态——落在带内的权重无论怎么强化都出不来。

### 事实 3：可分辨档数的上界（推导）

相邻档中心差：

```text
Δw* = δ · f / (1 − f)
```

要在量化格上分辨，需 `Δw* > 0.01`：

```text
δ > 0.01 / f                              ……(1)
```

要不撞顶（撞顶后所有高档被压平），需 `N · δ · f / (1−f) < 1`：

```text
δ < (1 − f) / (N · f)                     ……(2)
```

联立 (1)(2)：`0.01/f < (1−f)/(N·f)` ⇒ **`N < (1 − f) / 0.01`**。

再代入约束 B（`δ ≥ 0.01`）：

| 目标档数 N | 要求 f < | 半衰期 | 每夜衰减 |
|---|---|---|---|
| 2 | 0.98 | 34.3 夜 | 2% |
| 3 | 0.97 | 22.8 夜 | 3% |
| 5 | 0.95 | 13.5 夜 | 5% |
| 10 | **0.90** | **6.6 夜** | **10%** |

**在 `f = 0.98`（产品直觉）下，`N < 2.04` ⇒ 最多只能分辨「用过」vs「没用过」。**

扫 `δ ∈ {0.01, 0.02, 0.03, 0.05, 0.08, 0.10}` × `f ∈ [0.900, 0.999]`，统计 `n=1..10` 收敛值去重数：

### 事实 5：饱和式强化也卡在 5 档（实测）

改用 `R(w) = quantize(min(1, w + δ(cap − w)))`：

| δ | f=0.95 | f=0.98 | f=0.99 |
|---|---|---|---|
| 0.02 | 5 档 | 2 | 2 |
| 0.05 | 5 | 3 | 2 |
| 0.10 | 5 | 3 | 2 |
| 0.20 | 5 | 3 | 2 |
| 0.30 | 4 | 3 | 2 |

`f=0.95` 时 `δ` 从 0.02 扫到 0.30，**档数恒为 5**——不随 `δ` 变化，说明它也被某个与 `δ` 无关的量卡住。

### 事实 6：默认 `δ` 与衰减地板步长**精确相等** ⇒ 「用一次」是零变化（实测，本文件新增）

这条是写这份题面之后才发现的，**它比「档数不够」更根本**，而且我怀疑它是 Q5 的真正答案。

**机制**：强化是 `w + δ`；衰减 `D(w)` 在「比例衰减不足一格」时走线性地板强制 `−0.01`。而 `δ` 的默认值是 `0.01`，**与地板步长恰好相等**。于是在地板区间内：

```text
w = 0.10
  → 强化：0.10 + 0.01 = 0.11
  → 衰减：quantize(0.11 × 0.98) = quantize(0.1078) = 0.11
          0.11 不小于 0.11 ⇒ 走地板 0.11 − 0.01 = 0.10   ← 精确回到原值
```

**实测（默认 `δ=0.01, f=0.98`，101 个格点，每夜共激活 1 次）**：

| 单步净变化 | 格点数 | 区间 |
|---|---|---|
| 不变 | **75** | `0.00 ~ 0.74` |
| 上升 | **0** | 无 |
| 下降 | 26 | `0.75 ~ 1.00` |

即：**「每夜用一次」与「完全不用」在前 75 个格点上无法区分**；没有任何格点会因「用了一次」而上升。要上升必须每夜 ≥ 2 次（`n=2` 时零变化格点降到 25 个）。

**后果**：`makeEdge` 的初始权重来自相似度（`same-topic` 实测常见 0.1~0.3），落在地板区间内。所以**一条新建的边，若每夜只被共激活一次，权重永不增长**——它只比「不用」好一点（不下降），但不携带任何「被用了」的增量。

**这是「分辨率 vs 响应性」的硬冲突，不是标定失误**：

| f | δ | 档数(n=1..12) | n=1 零变化格点 | n=1 终值（从 0.50） | 评价 |
|---|---|---|---|---|---|
| 0.98 | **0.01** | **3** | **75** | 0.50 | 档数最多，但用一次无效 |
| 0.98 | 0.02 | 2 | 25 | 0.74 | 抵消消失，档数减半 |
| 0.98 | 0.03 | 1 | 1 | 0.98 | 完全不响应 |
| 0.95 | 0.01 | 6 | 29 | 0.28 | |
| 0.95 | 0.02 | 3 | 21 | 0.48 | |
| 0.914 | 0.01 | 10 | 17 | 0.16 | 档数够，仍有一次无效区 |

**推论（我的判断）**：`δ = 0.01` 是「档数最大化」的唯一选择，而它恰好等于地板步长 ⇒ **最优分辨率参数与「一次强化要有效」互相排斥**。这条把 Q5 从「改精度值不值」变成了「改精度**是不是必须**」——只要 `EDGE_WEIGHT_STEP` 与地板步长仍都是 `0.01` 且 `δ` 取最小合法格点，抵消就必然存在。

**我不确定的地方**：若把地板改成 `max(0.01, 0.02·w)`（Q3）而非「强制降一格」，抵消是否消失？若把 `δ` 允许取半格（如 `0.005`），是否两个约束同时满足？这两个我都没验。

## 四、我的判断，以及我不确定的地方

**我的判断**：在 `δ ∈ 0.01ℤ`、`f ≥ 0.95`、`N = 10` 三约束下无解。这不是参数没调好，是**模型形态**承载不了「用得多少」。

**但事实 1 让我怀疑问题本身提错了**：如果权重记录的是历史路径而非频率，「稳态区分频率」这个需求在任何加性+乘性组合下都不成立，**与参数无关**。那么真正的问题不是「找可行参数」，而是「换一个能让权重成为频率函数的模型」。

### 请你检验的六个问题

**Q1. 「多吸引子」是否意味着需求提错了？**
如果 `w` 记录历史而非频率，是否应放弃「稳态区分频率」，改为「权重 = 频率的在线估计」？例如 IIR 滤波 `w ← (1−α)·w + α·used`，`used ∈ {0,1}` 表示这一夜是否被用。这样 `w*` = 该边的使用率，时间常数 `1/α`。请判断方向是否正确，以及它和「遗忘」语义如何统一（`α` 与 `f` 是否是同一参数？）。

**Q2. 事实 3 的推导有错吗？**
特别检查：`Δw* = δf/(1−f)` 在**有线性地板**时是否还成立？地板让 `D` 在低权重区变成平移而非缩放。我怀疑推导在低权重区失效，但没验证。若失效，档数上界是否不同？

**Q3. 线性地板破坏了什么？**
`D` 在 `w ≤ 0.25` 时每夜固定 `−0.01`（因 `0.02w < 0.005` 被 round 舍回）。这使低权重区**线性衰减**、高权重区**指数衰减**。这是否是「多吸引子」的主要来源？是否应改成对数尺度衰减（在 `log w` 上做乘性），或显式 `max(0.01, 0.02w)`？

**Q4. 饱和式强化是否真的救不了？**
实测最多 5 档，且对 `δ` 不敏感（见事实 5）。请推导饱和式的档数上界，判断是否存在能到 10 档的参数。

**Q5. 提高量化精度是最小改动吗？——事实 6 之后，我认为它从「可选项」变成了「必须项」**
若 `EDGE_WEIGHT_STEP` 从 0.01 改成 0.001，上界 `N < (1−f)/0.001`，`f=0.98` 时 `N < 20`——**看起来直接解决**。

但**事实 6 改变了我对这个问题的判断**：抵消的根源是 `δ` 与地板步长都是 `0.01`，两者相等。所以：

- 若只改 `EDGE_WEIGHT_STEP` 而不动地板步长，`δ` 可以取 `0.005`（半格），**抵消可能消失**——但地板步长仍是 `0.01`，于是「强化 +0.005、衰减 −0.01」会变成**净下降**，那是另一种坏。
- 若两者一起改小（都改成 `0.001`），抵消**原样重现**——只是发生在更细的格点上。

所以真正要问的是：**`δ` 与地板步长必须解耦**，而不是「精度取多少」。请评估：地板步长该不该独立于 `EDGE_WEIGHT_STEP`？若独立，它的取值依据是什么（总不能又是一个拍出来的 0.01）？

其余代价仍需评估：日志体积（每夜边权变化条数会变多）、比较逻辑（`quantizeWeight` 的浮点相等判断）、既有数据迁移（旧数据全是 0.01 格点）。

**Q6. 如果 Q5 成立，为什么它不显然？**
我怀疑答案在事实 2：**量化格距与衰减地板步长是同一个量**（都是 `0.01`）。提高格精度会同时改变地板行为。请检查这个耦合是否是真正的障碍。

## 附：实测代码（可复现）

```js
import { nextDecayedWeight } from './lib/core/spread.js'
import { quantizeWeight as Q } from './lib/core/graph.js'

const night = (w, n, d, f) => {
  let x = w
  for (let k = 0; k < n; k++) x = Q(Math.min(1, x + d))
  return nextDecayedWeight(x, f)
}

// 数档数
const tiers = (d, f, w0 = 0.5, maxN = 10) => {
  const s = new Set()
  for (let n = 1; n <= maxN; n++) {
    let w = w0
    for (let i = 0; i < 600; i++) w = night(w, n, d, f)
    s.add(w)
  }
  return s.size
}

// 找不动点带
const band = (d, f, n) => {
  const fps = []
  for (let i = 0; i <= 100; i++) {
    const w = Q(i / 100)
    if (night(w, n, d, f) === w) fps.push(w)
  }
  return fps
}
```
