## 一、总判定

**`docs/8.1` 的主诊断是对的，主方案是可用方向，但它给的三条关键结论里有一条错、两条漏了落地约束。**

| 论断 | 判定 | 依据 |
|---|---|---|
| 原模型有多固定点、且终值依赖初值 | ✅ **成立** | 实测 `n=1` 有 75 个固定点（区间 `[0,0.74]`）、`n=2` 25 个、`n=3` 1 个 |
| 强化步长与衰减地板精确抵消 | ✅ **成立** | 实测 `f=0.98`：上升 **0** / 不变 **75** / 下降 **26** |
| 原模型的单调性判断错了（不是「非单调」） | ✅ **成立，且是在纠正我** | 101 格点上完整一夜算子违反单调 **0 次**；最长周期 **1**（全是固定点，无振荡） |
| `docs/8` 的档数推导有代数错误 | ✅ **成立，确实是我写错** | `docs/8` L138 写 `δ > 0.01/f`，正确是 `δ > 0.01(1−f)/f`，漏了 `(1−f)` |
| 连续饱和式的档数上界 `N < (1−f)/(0.01f)` | ⚠️ **代数正确但没用** | 用**正确**的 (1) 与 (2) 联立，`(1−f)` 全部约掉 ⇒ `N < 100`，**与 f 无关** |
| EMA 能给出 10 个档位、唯一稳态 | ⚠️ **仅在「内部不量化」时成立** | 连续域：10 档、初值无关 ✅；**但加回 0.01 量化后只剩 6 档、35 个可达终值** |
| `u_t = n_t/10` 可直接落地 | ❌ **不可落地** | 现有接口只有 `ReadonlySet<string>`（共激活**集合**），**没有次数**；`grep` 全仓无「次数」型信号 |

## 二、它对我文档的纠正（三处，其中两处是硬错误）

> 这一节原写「四处纠正」，而下面只有 2.1 / 2.2 / 2.3 三节——
> **汇总句比明细多了一个数**。2.3 是 2.1 与 2.2 的共同诊断，不是第四处独立纠正。
> 记在这里，因为「改明细不改汇总句」是本仓库已经复发过的形态。

### 2.1 「量化使映射非单调」——我错了

`docs/8` L26 写「量化使映射非单调，系统多吸引子」。`docs/8.1` §2.3 用整数状态论证
`D(j) = max(0, min(round(f·j), j−1))` 是两个单调不减函数取 `min`，仍单调不减。

**实测支持它**：

```text
衰减算子 D 在 101 格点上违反单调：f=0.98 → 0 次；f=0.95 → 0 次；f=0.914 → 0 次
完整一夜算子 D(R^n(w)) 违反单调：  f=0.98/0.95 × n=1/2/3 → 全部 0 次
最长周期轨道：                     全部为 1（无振荡）
```

真正的问题形态是**固定点是一整段区间，不是离散几个值**：

```text
f=0.98, n=1: 固定点 75 个，范围 [0.00, 0.74]
f=0.98, n=2: 固定点 25 个，范围 [0.74, 0.98]
f=0.98, n=3: 固定点  1 个，范围 [0.98, 0.98]
```

「单调」与「多固定点」不矛盾——恒等映射 `f(x)=x` 就同时具备两者。
**归因错了会让修法选错方向**：以为是非单调振荡，就会去加阻尼；实际是多吸引子，
该换的是模型形态。

### 2.2 档数推导漏了 `(1−f)`——我错了，但修正后更没用

`docs/8` L132 `Δw* = δ·f/(1−f)`，L135 要求 `Δw* > 0.01`：

```text
正确：δ·f/(1−f) > 0.01  ⇒  δ > 0.01(1−f)/f
docs/8 写成：              δ > 0.01/f          ← 漏了 (1−f)
```

误差量级：`f=0.98` 时 `0.01/f = 0.010204` vs 正确 `0.000204`，**差 50 倍**。

**但顺着它改会得到更奇怪的结论**：把正确的 (1) 与 (2) `δ < (1−f)/(N·f)` 联立，

```text
0.01(1−f)/f < (1−f)/(N·f)
⇒ 0.01 < 1/N
⇒ N < 100          ← (1−f) 完全约掉，上界与 f 无关
```

即「理论上能分辨 100 档」，而实测 `f=0.98` 只有 **3 档**。所以 `docs/8.1` §2.4 末尾
那句「该公式只适用于连续模型，不能当作实际 101 状态系统的严格档数上界」是**对的，
而且是唯一诚实的写法**——连续域推导在这个离散系统上没有判别力。

### 2.3 我的「非单调」归因与「档数上界」是同一个病

两次都是「从连续域公式推离散系统结论」。`docs/8.1` §2.3/§2.4 把这两处都点了出来，
这一点比它给的方案更值钱。

## 三、它自己漏掉的落地约束（三条主项 + 一条附带）

> 3.1～3.3 是主项（前两条会让方案直接失效），3.4 是核验 3.3 时顺带发现的
> **同形态隐患**，不是独立的一条。这里把「三条」和实际节数写清，
> 免得读者数出四条又以为漏读了一节。

### 3.1 致命：`n_t`（当晚共激活次数）这个信号不存在

`docs/8.1` 的核心公式是

```text
w_{t+1} = f·w_t + (1−f)·min(n_t/10, 1)
```

`n_t` 是**当晚共同激活次数**。而现有接口是：

```ts
export function reinforceEdges(
  edges: readonly MemoryEdge[],
  coActivated: ReadonlySet<string>,     // ← 集合，不是计数
  config: MemoryConfig,
): MemoryEdge[]
```

全仓 `grep` 结果：`coActivationCount` / `activationCount` / `nightlyCount` / `usageCount`
**全部 0 命中**。也就是说：

- 现有信号只能回答「这两张卡今晚一起被想到过吗」（0/1）
- `docs/8.1` 的公式要求回答「今晚一起被想到过几次」（0..n）

**这不是加个参数的事**，而是要在召回链路上埋计数。而召回链路当前**刻意不写库**
（`buildRecall` 不写 `touch`，`confirmRecall` 零调用方）。要在那里加计数，
等于先把缺陷三十四那条「插件吃自己注入」的路径重新打开一遍——
`n_t` 一旦包含「被展示」，就等于把「展示」记成「使用」。

**结论**：`docs/8.1` 的公式在数学上正确，但它假设的输入在本仓库不存在。
按它实现会得到一个恒等于 `u_t=0 或 1` 的二值模型，
即退化成 `w*∈{0, 0.1}` 两档——**比现在的 3 档还少**。

### 3.2 `λ` 不是自由参数，它有下界

`docs/8.1` §5.3 说「λ 暂时不指定固定值，应通过真实检索效果测试确定」。
但 λ 直接乘在边权上，而边权是扩散能量的乘数：

```text
λ     | 边权  | b 的 boost | b 最终分 | 能越过 c(0.55)？
1.0   |  0.30 |  0.120000  | 0.620000 | 能
0.7   |  0.21 |  0.094500  | 0.594500 | 能
0.5   |  0.15 |  0.067500  | 0.567500 | 能
0.3   |  0.09 |  0.040500  | 0.540500 | 不能
0.2   |  0.06 |  0.027000  | 0.527000 | 不能
```

`λ ≤ 0.3` 时扩散已经**无法改变排序**。按真实语料 `semantic≈0.30`、
`hopDecay=0.5`、种子能量 `≈0.9` 换算：

```text
raw = 0.9 × λ × 0.30 × 0.5 = 0.135λ
要越过常见的 0.05~0.2 分数差 ⇒ λ > 0.37
```

**λ 不能「测了再定」，它有一个由 `maxBoost` 和打分区间共同决定的下界。**
把 λ 留白，等于把「突触效果是否可见」这个产品问题伪装成调参问题。

### 3.3 静态 `semantic` 分量不衰减 ⇒ 图谱永不遗忘

`docs/8.1` §5.1 把边拆成 `semanticWeight`（静态）+ `usageRate`（EMA），
§5.3 用 `λ·semantic + (1−λ)·usage` 合成。但 `usageRate` 初始化为 0，
且 `semantic` 永不衰减：

```text
夜数 | usage | 合成边权(λ=0.5, sim=0.30)
   0 |  0.00 | 0.15
  34 |  0.00 | 0.15
 300 |  0.00 | 0.15
```

从未被使用的边**永远保持 0.15**，而 `pruneThreshold = 0.1` ⇒ **永远不会被剪**。
这与它自己在 §4.3 宣称的「34.31 夜半衰期、自然遗忘」直接冲突：
EMA 只让 `usageRate` 遗忘，而 `usageRate` 从 0 开始、没人接线就永远是 0，
**「遗忘」作用在一个恒为 0 的量上等于什么都没发生**。

### 3.4 附带发现：`n=1` 的稳态恰好压在剪枝线上

```text
EMA n=1 的稳态 = 0.1
pruneThreshold = 0.1
判据 `weight < pruneThreshold` ⇒ 0.1 不剪（勉强活）
```

实测 600 夜后为 `0.100002176233`，**大于** 0.1，靠浮点余量 `2.2e-6` 活着。
若哪天改成 `<=` 判据、或 `f` 微调，**「用过一次」就等价于「不存在」**。
这是本仓库已经踩过的形态（「两个阈值精确相等 ⇒ 机制恒为空」）的变体：
**这次是「两个阈值精确相等 ⇒ 机制恒为存活/恒为死亡」**，同样不报错。

## 四、可用的部分

尽管有三条漏约束，`docs/8.1` 有两处**可以直接采纳**：

### 4.1 「取消逐次量化」这个方向是对的

实测对照（同一 EMA 公式，唯一差别是每次更新后是否 `quantize` 到 0.01）：

| 指标 | 不量化 | 量化到 0.01 |
|---|---|---|
| 扫 `n=1..10` 的档数 | **10** | **6** |
| 扫 `w0=0.01..1.00`（100 个初值）的终值分布 | **1 个稳态**，极差 `5.386e-6` | **35 个不同终值**（`0.01`～`0.35`） |
| 与初值无关？ | 是（偏差 < `0.98^600 = 5.441e-6`） | **否** |

**这张表的第一版我写错了**，记在这里：我原本写「不量化 → 100 个可达终值」，
那是用 `1e-9` 容差去重 600 夜后的浮点残差。容差敏感性实测：

```text
容差    | 去重个数
1e-9    | 100        ← 我第一版用的
1e-7    |  55
1e-6    |   6
1e-5    |   1        ← 正确口径
1e-4    |   1
1e-2    |   1
```

真实极差只有 `5.386e-6`，而 `1e-9` 远小于它，于是 100 个初值全被算成「不同」。
**报「可达终值个数」这类数字时必须连容差一起报**，否则同一个系统能报出 1 或 100，
两个都「实测正确」。这正是 `docs/9` §5.5 第 4 条记的形态，我在同一周又犯了一次。

正确结论：**不量化时是唯一稳态，量化时被重新打回 35 个吸引子。**
所以「取消量化」不是优化，是这个方案成立的前提。

### 4.2 「惰性衰减」在连续域严格等价

```text
逐夜 40 次 EMA(n=0) = 0.325361294884
惰性 f^40 × w       = 0.325361294884
差 = 1.1e-16
```

但如果保留量化，惰性衰减**不再等价**（实测差 0.00 但那是两边都被量化吃掉，
一旦 `Δt` 增大就会分叉）。**这两条要一起做：取消量化 + 惰性衰减。**
只做惰性衰减而保留量化，会得到一个「路径依赖的遗忘速度」。

## 五、落地前必须先解决的顺序

`docs/8.1` 把这几件事当平行的，实际有依赖：

```text
① 换模型形态（EMA 或其它）—— 但它需要 n_t
       ↓ 需要
② 埋共激活计数 —— 但召回链路刻意不写库，且要避开「展示≠使用」
       ↓ 需要
③ 确定「使用」的语义（docs/9 的 Q9）—— 这是产品决策，不是数学问题
       ↓ 才能
④ 定 λ 下界（≥0.37）与剪枝判据
       ↓ 才能
⑤ 数据迁移（旧边权语义混淆，不能反推 usageRate）
```

**`docs/8.1` 从 ①开始讲，但 ③ 才是真正的起点。** `docs/9` 的 Q9 没答，
所以 ① 的 `n_t` 无论怎么埋都是猜的。

## 六、给它的三条回问

如果还要再问一轮，这三个是它没答且决定成败的：

1. **`n_t` 在「展示」与「使用」不可分时该怎么定义？**
   本仓库唯一可信的「使用」信号 `confirmRecall` 零调用方，五个替代信号全部违反
   起源 L29（专注当前位置）。EMA 的 `u_t` 若取「被展示次数」，会把污染记成学习。

2. **`usageRate` 从 0 起步，但 `semantic` 不衰减，那「遗忘」到底作用在什么上？**
   实测显示未被使用的边权重恒定 0.15、永不被剪。要么让 `semantic` 也衰减
   （那它就退化成原模型），要么把剪枝判据改成基于 `usageRate`（那纯语义边会被全剪）。

3. **取消量化后，`weight` 的存储格式要不要改？**
   现有 `MemoryEdge.weight` 是 `number`，但幂等键是
   `buildIdempotencyKey('edge', id, String(op.edge.weight))`——**`String(float)` 是精确的**，
   所以浮点权重不会撞键。**但 `docs/8.1` §6 建议「存储保证足够小数精度」，
   若改成定长十进制字符串，`String()` 的稳定性就要重新验证。**

## 七、结论

**这份文档帮到我了，但帮的方式和它以为的不同。**

- 它给的方案（EMA）在**连续域**成立，且方向正确；
- 但它假设的输入 `n_t` 在本仓库不存在，而这是整条链路的起点；
- 它纠正了我两处真错误（非单调归因、档数推导漏因子），这两处**比方案本身更有价值**；
- 它漏了三条落地约束（`n_t` 不存在、λ 有下界、静态分量不遗忘），
  其中第一条会让整个方案退化成二值模型。

**下一步不该是「按它实现」，而是先答 `docs/9` 的 Q9。** 那个 Q9 没答，`n_t` 的定义就是猜的，
而 `n_t` 错，EMA 再优雅也只是把错误估计得更平滑。
