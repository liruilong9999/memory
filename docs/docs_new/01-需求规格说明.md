## 一、需求的源头

### 1.1 原始诉求：八条编号 + 七条无编号

这套系统不是从一份产品需求文档开始的，是从一段**哲学式的自述**开始的。
原始诉求必须原文保留，因为后面每一条工程需求的最终裁判都是它。

**七条无编号（带 U 前缀表示「未编号」）：**

| 编号 | 原话 |
|---|---|
| 源-U1 | 激素是关键！！！大脑皮层只是记忆，激素控制情绪！！！ |
| 源-U2 | 连续人生，自我驱动 |
| 源-U3 | 其实我们大多数细节都会忘记，只会留下感受。 |
| 源-U4 | 我猜想，可以把生活，学习，工作 3 个记忆模块，可插拔（同时存在或者只有一个） |
| 源-U5 | 我需要一种建立记忆图谱的方法，且跨层次关联。 |
| 源-U6 | 问题是原有的压缩记忆可能不可取了，然后模型搜索记忆等也可能有问题？污染上下文？ |
| 源-U7 | 那么如何出现感受和经验的写入和回忆呢？ |

**八条编号：**

| 编号 | 原话 |
|---|---|
| 源-1 | 解决 AI 没有时间观念问题，定闹钟 |
| 源-2 | 绝不多线程，除非工作 |
| 源-3 | 强弱思考，换挡，慢思考，低输出 |
| 源-4 | 今日记忆渐进累积，夜晚休眠整理，很长时间迭代 |
| 源-5 | 一个现象，人思考一个问题时，不会代入其它记忆，会专注当前位置。如学习线性代数时，大概率不会想昨天晚上吃了什么，所以百万上下文对于当前状态可能够的，需要优化记忆机制，和专注机制 |
| 源-6 | 上下文，等同于一个人在某个瞬间大脑信号（思考相关）的瞬时状态 |
| 源-7 | 利用有限的上下文，衍生出真正的智能，我认为当前模型足够用了 |
| 源-8 | rsi 只是为了让模型一把过任务的概率，而不是真正的智能 |

**一句后来补充的诉求：**

> 「我要类似神经的突触效果。」

### 1.2 一个必须先说清的事实

**原始诉求里没有出现「突触」「神经」「扩散」「激活」「强化」「衰减」中的任何一个词。**

「突触效果」是后来单独补的，不是原始诉求的字面内容。这条事实很重要，因为：

- 它意味着「突触」**不是一个硬性功能清单项**，而是一种**效果描述**。
- 用户要的效果是「记忆之间会互相带出来」——想起 A 就想到 B——而**不是**要求实现
  某个特定算法（比如赫布学习、脉冲神经网络、边权可塑性）。
- 因此「用什么机制实现这个效果」是**设计自由**，而「效果是否可感知」是**验收标准**。

这条区分在后续反复起作用：可塑性（边权随使用增强）被判定为**不可行**时，
受影响的是**一种实现手段**，不是**这条需求本身**。需求仍然可以用别的方式满足。

### 1.3 从原话到工程需求：八条翻译

原话是哲学层的，不能直接写进代码。下面是逐条翻译，**每一条都注明它来自哪条原话**。

| 需求 | 来源 | 翻译成可检验的断言 |
|---|---|---|
| **R1** 增量写、批量整 | 源-4 | 写入必须是**增量**的（每轮写，不重算历史）；巩固必须是**批量**的（每晚一次，不在主路径上） |
| **R2** 专注当前位置 | 源-5 | 注入内容必须**与当前查询相关**，无关的必须被挡住。**这是最硬的一条** |
| **R3** 细节会忘、只留感受 | 源-U3 | 必须存在**遗忘**机制，但感受类记忆**永不遗忘**，且必须能**被产出** |
| **R4** 激素控制情绪 | 源-U1 | 情绪强度必须**进入打分**，且情绪强的**记得更久**，且情绪表达**必须能被写进来** |
| **R5** 图谱与跨层次关联 | 源-U5 | 记忆之间有**边**，边有权重，边能影响打分，且能跨域、跨类型连边 |
| **R6** 不污染上下文 | 源-U6 | 注入必须有 **token 硬上限**，且**不能把自己的注入再吃回来** |
| **R7** 时间观念、定闹钟 | 源-1 | 时间必须参与：绝对时刻、相对时间、到期提醒 |
| **R8** 有限上下文衍生智能 | 源-6、源-7 | 注入必须**密度高**（3～7 张，不是 50 张），且总成本有上界 |

### 1.4 R2 与 R8 是整套系统的重心

其余六条是「要有」；R2 和 R8 是「必须准」。原因：

- 起源里唯一一处带**否定语气**的诉求是源-U6「污染上下文？」和源-5「不会代入其它记忆」。
  用户在担心一件事：**记忆会把当前思考带跑**。
- 记忆系统的失败有两种：**想不起来**（可惜）和**想错了、想偏了**（有害）。
  后者会把模型的注意力从当前任务上拖走，而且**用户很难察觉**——他只会觉得模型今天有点糊。

所以整套设计的验收重心不在「召回率」，而在「**不该进来的没进来**」。
这解释了为什么后面有**三道闸**而不是一道，为什么绝对闸要换尺子（见 06 第 3 章），
也解释了为什么「全低分时硬塞」被当成一个真缺陷而不是一个体验问题。

## 二、定位、范围与非目标

### 2.1 一句话定位

**一个跑在智能体宿主里的、确定性的、事件溯源的长期记忆层。**

拆开四个词：

| 词 | 含义 | 排除掉的东西 |
|---|---|---|
| **跑在宿主里** | 在宿主进程内，能读会话事件、能注册注入通道 | 独立服务、外挂 MCP 工具、旁路进程 |
| **确定性** | 同状态 + 同查询 + 同参数 ⇒ 结果逐位相同 | 任何依赖随机、哈希顺序、浮点累加顺序的实现 |
| **事件溯源** | 只追加日志是唯一真相源，视图可重建 | 「一张会变的表」、就地修改、无审计的写入 |
| **长期记忆层** | 跨会话存在，与单次会话历史正交 | 上下文压缩、会话摘要、RAG 检索外挂 |

### 2.2 目标的四个维度：什么叫「稳定」

「稳定记忆」不是一个形容词，它有四个可分别检验的维度。**四者缺一，系统就不能长期用。**

```text
              ┌─────────────────────────────────────────┐
              │  稳定记忆 = 四个维度同时成立              │
              └─────────────────────────────────────────┘
                                  │
    ┌──────────────┬──────────────┴──────────────┬──────────────┐
    ▼              ▼                             ▼              ▼
┌────────┐   ┌────────────┐              ┌────────────┐   ┌────────────┐
│数据稳定 │   │  内容稳定   │              │  行为稳定   │   │  成本稳定   │
├────────┤   ├────────────┤              ├────────────┤   ├────────────┤
│写得进   │   │记得对       │              │每次结果一致 │   │token 有上限│
│存得住   │   │不忘形       │              │可解释       │   │库大小有界  │
│崩不坏   │   │不污染       │              │可回滚       │   │整理耗时可控│
└────────┘   └────────────┘              └────────────┘   └────────────┘
     │              │                          │              │
  事件溯源       两道尺子                     纯函数         硬预算
  幂等键         三道闸                       事件日志       归档比例
  崩溃修复       图谱                         版本快照       索引重建
```

| 维度 | 一句话 | 如果不成立会怎样 | 主要落在哪几篇 |
|---|---|---|---|
| **数据稳定** | 写进去的东西不会丢、不会重、不会坏 | 用户信任一次就没了，且事后无法审计 | 04 |
| **内容稳定** | 召回的确实相关，无关的进不来，长期用不退化 | 用得越久越糊，最后成为负担 | 06、08 |
| **行为稳定** | 同样的输入永远给同样的输出，且能解释 | 无法定位问题，也无法回滚 | 03、06、12 |
| **成本稳定** | 每轮注入与每夜整理都有硬上界 | 长会话被记忆拖慢、库无限膨胀 | 06、07 |

### 2.3 长期方向

系统分阶段推进，当前阶段只做地基。后续方向的**排序理由**是「前一个不做对，后一个做了也没用」：

| 阶段 | 内容 | 触发条件 |
|---|---|---|
| 本阶段 | 稳定记忆（写入、存储、召回、注入、巩固、遗忘、时间） | — |
| 后续 | 图谱扩散与联想（本阶段已实现基础算法，但列为后续扩展） | 稳定记忆跑通并积累真实数据 |
| 后续 | 状态调制与认知换挡 | 稳定记忆 + 联想可解释之后 |
| 后续 | 经验抽象（从事件提炼经验卡） | 基础去重合并稳定之后 |
| 后续 | 主动性（空闲联想、长期驱动） | 召回质量达标之后 |
| 后续 | 多模态（语音转写） | 文本记忆稳定之后 |
| 暂缓 | 双人格 / 分身 / 交流卡 | 不在当前路线图 |

### 2.4 非目标（明确不做）

**这一节和需求同等重要。** 一个没有非目标的设计会无限膨胀。

| # | 不做 | 理由 |
|---|---|---|
| N1 | 不做参数化记忆（把记忆写进权重或隐状态） | 模型是服务商 API，无权重访问权限（见 C2） |
| N2 | 不做多模态（语音、视频、语气） | 独立感知层，与记忆层正交，先做文本 |
| N3 | 不做「让模型自己管理记忆」的工具入口 | 写入由系统驱动。开放「模型写记忆」会让模型自说自话污染库，且**写入路径一旦由模型决定，幂等、来源、置信度全部失控** |
| N4 | 不做复杂状态机与情绪系统 | 本阶段只需要「情绪影响打分与半衰期」，不需要情绪状态机 |
| N5 | 不靠长上下文硬扛 | 百万上下文不是方案。源-5 与源-7 明确说「利用有限的上下文」 |
| N6 | 不做知识图谱式的本体建模 | 边只有四种语义关系，不引入实体类型体系与推理 |
| N7 | 不做跨用户的共享记忆 | 单机本地、单用户（见 C9） |
| N8 | 不做在线学习式的模型微调 | 同上，无权重访问 |

> **N3 值得单独强调**：它是「记忆系统」与「记忆工具」的分界线。
> 让模型自己决定写什么，等于把幂等键、来源指针、置信度三件事全部交给一个
> 不可审计的黑盒，而这三件事恰好是数据稳定的全部地基。

### 2.5 使用场景

| 编号 | 场景 | 通过标准 |
|---|---|---|
| S1 | 跨会话回忆 | 次日新会话问「我们昨天聊了什么」，要点正确、不编造 |
| S2 | 工作任务记忆 | 某工程项目的任务、决策、踩坑能按需召回 |
| S3 | 长期使用稳定 | 连续用两周，召回质量不下降、上下文不膨胀 |
| S4 | 夜间整理 | 日终自动去重、合并、降权、归档，产出一份可读的变更日志 |
| S5 | 到期提醒 | 重要事项到点主动提醒，无需用户输入 |

**S3 是最容易被忽略、但最能定义成败的一条。** 绝大多数记忆系统的演示都在第一天
很好看，第三十天开始变糊。S3 把「长期」写进了验收，等于强制要求遗忘机制。

## 三、设计原则 P1～P8

八条原则，每条都是**一个曾经被违反过、违反后出了事**的判断。
原则的价值不在于它说了什么，而在于**它排除了哪些看起来合理但会出事的做法**。

### P1 · 记忆系统是操作系统，不是提示词技巧

**含义**：写入、去重、衰减、打分、归档全部由确定性代码完成。模型只负责
「摘要抽取」与「自然语言表达」这两件确实需要语言能力的事。

**它排除了什么**：

- 用一段系统提示词告诉模型「请记住这些内容」——那不是记忆，那是把负担转给模型。
- 用模型自己判断「这条重要不重要」——不可复现、不可审计、不可回滚。
- 把记忆存在对话历史里靠上下文长度维持——那与会话历史没有区别。

**违反它会怎样**：系统的行为变成模型行为的函数。同一个输入两次结果不同，
无法解释某条记忆为什么被召回，也无法定位「为什么昨天记得今天忘了」。

**它约束了**：整个系统的分层（行为面全是纯函数）、ST-1 的可检验性、
以及 N3（不开放模型写记忆）。

### P2 · 事件日志是唯一真相源

**含义**：记忆库的真实状态是一串只追加的事件记录。当前的卡片集合、图谱边集合、
检索索引**全部是从日志重放出来的派生视图**。视图可丢弃、可重建，日志不可改。

**它排除了什么**：

- 「就地更新一张表」——没有历史，无法回答「这条记忆是怎么变成现在这样的」。
- 「索引当真相源」——索引一旦损坏，数据就丢了。
- 「内存状态是权威」——重启即丢。

**违反它会怎样**：一次崩溃或一次索引损坏就永久损失数据；修正记录（FR-A5）
根本无法实现；导出重建（ST-8）失去意义。

**它约束了**：04 的全部设计（操作集、幂等键、重放、崩溃修复）、
以及「投影层不得改写事实」这条硬边界（见 04 第 7 章）。

### P3 · 写入幂等、读取可解释

**含义**：两件事合成一条原则，因为它们是同一个承诺的两面——
**系统对自己做过的事负责**。

- **写入幂等**：同一件事重复提交不产生重复记录。
- **读取可解释**：每一条召回都能说出「它为什么进来了，各分项得了多少分」。

**它排除了什么**：

- 「差不多去重」——相似度阈值去重是巩固层的事，写入层必须靠**确定的键**。
- 「黑盒排序」——任何不能输出分数构成的打分都不合格。

**违反它会怎样**：重复导入一次会话，卡数翻倍；用户问「你为什么想起这个」，
系统答不出来，于是无法判断是召回错了还是内容错了。

**它约束了**：幂等键设计（04 第 5 章，这是全系列最容易被写错的一节）、
可解释渲染（06 第 6 章）。

### P4 · 记忆是带置信的线索，不是事实

**含义**：每条记忆都带**来源、置信度、时效、冲突标记**。系统从不宣称
「这是真的」，只说「有这么一条记录，它来自这里，可信度这么多，多久以前，与谁冲突」。

**它排除了什么**：

- 「记忆即真相」的简化模型——它会诱导模型把过时的、有争议的内容当定论复述。
- 静默覆盖——新记忆覆盖旧记忆而不留痕，等于让系统替用户裁决事实。

**违反它会怎样**：模型会自信地复述一条三个月前已经变更的结论；
冲突的两条记忆只留一条，用户再也看不到「这里有过分歧」。

**它约束了**：卡的字段（来源指针、置信度、冲突列表、修正历史）、
FR-B5（冲突必须显式）、FR-A5（修正留痕）。

### P5 · 遗忘是功能

**含义**：不追求记住一切，追求「**记得对、忘得合理、找得回**」。
遗忘是主动设计的能力，不是容量不足的妥协。

**它排除了什么**：

- 「全部保留」——库无限膨胀，检索退化，成本失控。
- 「遗忘即删除」——不可逆的删除会让用户不敢用。

**违反它会怎样**：违反 S3（长期使用稳定）最直接。两周之后每次召回都在噪声里捞针。

**它约束了**：强度衰减、有效半衰期、归档比例、永不归档类别、
以及「归档 ≠ 删除」这条语义（见 07 第 5 章）。

> **P5 与源-U3 的关系**：「细节会忘记，只会留下感受」不是一句感慨，
> 它是一条**不对称的遗忘策略**——普通记忆按强度衰减，感受类记忆永不归档。
> 这条不对称是整个遗忘层的形状来源。

### P6 · 门控先于检索

**含义**：系统在模型开口前**主动预取**记忆并注入，模型不发起检索。
检索是系统的责任，不是模型的工具调用。

**它排除了什么**：

- 「给模型一个搜索记忆的工具，让它自己查」——这会把两件事推给模型：
  什么时候该查、查什么。而模型恰好最不擅长判断「我不知道什么」。
- 「按需检索」——模型不查的时候，它就永远想不起来，记忆形同不存在。

**违反它会怎样**：记忆变成「用户得提醒模型去查」的东西，与「连续人生」（源-U2）相反。

**它约束了**：注入通道的选择（必须能在每轮自动求值，见 02 第 2 章）、
召回必须够快（在主路径上，见 NFR-1）。

### P7 · 参数可版本化、可回滚

**含义**：阈值、权重、策略**带版本**，改动可追溯、可回滚。
配置本身是被记录的对象，不是散落的字面量。

**它排除了什么**：

- 「参数写死在代码里」——改一个阈值要发版，且无法知道昨天用的是哪组参数。
- 「改坏了只能改回来」——没有版本就无法回滚，也无法回答「上周的召回为什么不一样」。

**违反它会怎样**：调参变成不可复现的实验。更糟的是**两个入口读到不同配置副本**
而都自认为正常——这种分歧不报错、不崩溃，只是结果悄悄不同。

**它约束了**：配置的结构化与校验、配置快照台账、健康检查必须报「配置来源」
而不只报结果（见 12 第 3 章）。

### P8 · 成本有上界

**含义**：记忆注入的 token、库的大小、整理耗时**都有硬上限**，不是「平均而言可以接受」。

**它排除了什么**：

- 「按相关度取前 k 个，k 不设上限」——稠密图上 k 会随库增长。
- 「每夜全量重算」——库大时整理跑不完。
- 「平均延迟达标即可」——**平均值掩盖长尾，而长尾恰好在最忙的时候出现**。

**违反它会怎样**：违反 S3 与 NFR-2。长会话被记忆拖慢，而用户只会感觉「今天有点卡」。

**它约束了**：三道闸的硬上限、token 预算、k 近邻建图（按构造封顶度数）、
归档比例上限、单次剪枝上限。

### 3.1 八条原则之间的关系

```text
        P2 事件日志唯一真相源
              │  （地基：没有它，P3 无法验证）
              ▼
        P3 幂等 + 可解释 ──────► P7 版本可回滚
              │                        │
              ▼                        ▼
        P1 系统驱动而非提示词      P8 成本有上界
              │                        │
              └────────┬───────────────┘
                       ▼
              P6 门控先于检索
                       │
                       ▼
        P4 线索非事实 ──► P5 遗忘是功能
```

**P2 在最下面，因为它是其余七条的共同前提**：没有唯一真相源，
幂等无法验证、可解释无法回溯、回滚无基准、成本无法核算。

## 五、平台硬约束 C1～C9

这些不是「需求」，是**宿主给出的事实**。设计不能违反它们，只能围绕它们变形。

| 编号 | 约束 | 影响 |
|---|---|---|
| **C1** | 宿主是一个 TypeScript 插件运行时，插件以模块形态加载 | 主干语言与运行形态固定 |
| **C2** | 模型是服务商 API，**无权重访问** | 只能做上下文级可塑性；一切「学习」必须落在数据层 |
| **C3** | 存储走宿主的存储域抽象，后端为进程内 SQLite 或纯文本记录文件 | 不引入原生数据库扩展；同名存储域全进程只能开一次 |
| **C4** | 注入主通道是**每轮求值、尾部追加、压缩后自愈**的快照通道 | 记忆卡不重写提示词头部（KV 缓存安全） |
| **C5** | **不得写自定义会话事件类型** | 记忆状态只能存自己的数据域，不能污染会话日志 |
| **C6** | 压缩**没有「压缩前」可阻断钩子** | 只能「平时增量写 + 听压缩摘要事件回填」 |
| **C7** | KV 前缀缓存要求**稳定内容在前、动态内容在后** | 记忆卡只能进动态层，绝不能进系统提示词 |
| **C8** | 宿主为预览版，会有破坏性变更 | 必须有适配层，且适配层是唯一允许依赖宿主的部分 |
| **C9** | 单机、本地、单用户 | 规模目标 10 万级记忆卡；不做分布式与多租户 |

### 5.1 三条约束直接决定了架构形状

其余六条是「注意一下」，这三条是**决定性**的：

| 约束 | 逼出了什么 |
|---|---|
| **C4 + C7** | 只有一条注入通道可用。另一条（写系统提示词）会重写头部、让 KV 缓存从第一个变化 token 起全部失效。⇒ 注入必须是「追加式快照」 |
| **C5** | 记忆不能寄生在会话日志里。⇒ 必须有独立的事件日志（这恰好与 P2 合流） |
| **C6** | 压缩不可拦截。⇒ 记忆写入必须**不依赖压缩时机**，只能靠平时增量写；且压缩后必须能自动重建（C4 的「每轮求值」正好提供了这个能力，不需要任何钩子） |

> **C6 与 C4 的配合值得单独看一眼**：看起来「压缩没有钩子」是个大问题，
> 实际上因为 C4 的注入通道是**每轮重新求值的函数**，压缩之后下一轮自然就重新
> 生成了快照——**不需要钩子**。这不是绕过限制，是设计正好落在限制之外。
> 详见 02 第 5 章。

## 六、非功能需求 NFR-1～NFR-8

| 编号 | 需求 | 可检验的形式 |
|---|---|---|
| **NFR-1** | 延迟：预取在本地完成，不阻塞首个 token；万级记忆单次预取 < 50 ms | 召回耗时随库增长呈次线性；主路径上无 IO 等待 |
| **NFR-2** | 成本：每轮记忆注入 token 有硬上限；稳定前缀不因记忆变化而失效 | 连续 50 轮波动 ≤ ±10%；系统提示词头部逐字节不变 |
| **NFR-3** | 规模：10 万级记忆卡、百万级来源指针可用 | 重放耗时、索引内存、召回耗时三者的增长曲线都有实测 |
| **NFR-4** | 可靠性：崩溃不丢已确认写入；写入幂等；索引可重建 | 强杀进程后磁盘自洽；重复导入卡数不变；删索引可重建 |
| **NFR-5** | 可移植：数据可导出，不锁定宿主内部结构 | 导出为通用文本格式，脱离宿主可读 |
| **NFR-6** | 隐私：数据全部本地；不写密钥；支持整体删除 | 数据目录之外无副本 |
| **NFR-7** | 可维护：数据面 / 行为面 / 适配面分离；宿主升级只改适配层 | 反向依赖为零 |
| **NFR-8** | 可测试：打分、去重、衰减为纯函数可单测；关键路径有端到端用例 | 纯函数层零 IO；链路层有真实输入用例 |

### 6.1 NFR-1 与 NFR-2 是一对张力

- NFR-1 要求**快**：召回在主路径上，每轮都跑。
- NFR-2 要求**稳**：注入的内容变化不能让 KV 缓存失效。

这两条一起排除了「把记忆写进系统提示词」这条路——那是所有方案里最省事、
效果最直接的一种，但它每轮都会改动前缀，把缓存全部打掉，成本爆炸。

**代价必须说清**：走追加式快照，意味着记忆永远在对话历史的**尾部**，
模型对它的注意力弱于系统提示词里的内容。这是**用效果换成本**，
而且是刻意的（源-7「利用有限的上下文」本来就要求省着用）。

## 七、功能需求 FR-A～FR-G

### 7.1 写入与数据稳定（FR-A 组）

**这一组的共同目标**：数据进去之后不会丢、不会重、不会坏、可追溯。

| 编号 | 需求 | 验收要点 |
|---|---|---|
| FR-A1 | 轮次边界**异步**写卡，不阻塞回复 | 回复延迟与写入耗时无关 |
| FR-A2 | **幂等**：同一事件重复处理不产生重复卡 | 重复导入同一会话，卡数不变 |
| FR-A3 | **原子性**：单次写入要么全生效要么不生效；崩溃后重启不受影响 | 强杀进程后重启，无半条记录 |
| FR-A4 | **来源指针**：每张卡记录会话、轮次、步骤、原文序号 | 任意卡能定位回原文 |
| FR-A5 | **修正留痕**：同一事实更新时保留旧版本，可查历史 | 修正后可回答「改过什么、为什么」 |
| FR-A6 | **导出与重建**：全量导出，可从导出重建库 | 导出 → 重建 → 抽查 100 条一致 |
| FR-A7 | **索引可重建**：检索索引随时可丢弃重建，不影响真相源 | 删索引后自动重建 |

**FR-A2 的失败模式必须特别记住**：幂等做错时**不报错**。数据面判定「这是重复」，
直接丢弃，读回来还是旧值。唯一的症状是「改了但没生效」，而它可能几周都不出现。

### 7.2 召回与内容稳定（FR-B 组）

**这一组的共同目标**：召回的确实相关，且每一次都能解释。

| 编号 | 需求 | 验收要点 |
|---|---|---|
| FR-B1 | **打分公式**：语义相关 + 重要性 + 时间衰减 + 目标匹配 + 置信度 − 冲突惩罚，权重可配 | 公式可单测，参数落在配置 |
| FR-B2 | **三道闸**：绝对阈值 + 相对阈值 + 条数硬上限；全低分时**不硬塞** | 全低分时返回空包 |
| FR-B3 | **确定性**：固定参数下同状态同查询返回相同结果 | 连续 10 次逐位相同 |
| FR-B4 | **可解释**：每条附分数构成（各分项与总分） | 能回答「为什么想起这条」 |
| FR-B5 | **冲突显式**：冲突记忆标出来，并同时暴露双方 | 冲突不隐藏 |
| FR-B6 | **不编造**：空召回必须给出明确信号，注入侧空包不写任何内容 | 空库与无关话题都不臆造 |
| FR-B7 | **看到与使用分离**：召回本身**不改变记忆状态** | 召回前后强度、访问计数、日志字节数均不变 |

**FR-B7 的理由来自源-5**：如果「被召回」就等于「被强化」，那么偶然召回 →
强度上升 → 更容易被召回，形成**马太效应**，历史噪声会被越推越前。
这与「专注当前位置」正好相反。所以「看到」和「真正用上」必须分开，
只有显式确认「这条被用上了」才加深记忆。

**FR-B2 与 FR-B6 是一对**：B2 管「不该进的别进」，B6 管「没有的时候要说没有」。
两者都失败时的症状一样——模型开始编——但修法完全不同。

### 7.3 遗忘与巩固（FR-C 组）

**这一组的共同目标**：库长期可用，且重要的东西不会因为遗忘机制被误伤。

| 编号 | 需求 | 验收要点 |
|---|---|---|
| FR-C1 | **夜整理最小集**：去重、合并、降权、归档、重建索引，产出可读变更日志；整理进度落盘，重启不重复执行 | 每次整理有一份可读报告；重启后再跑不会重复衰减 |
| FR-C2 | **遗忘可逆**：归档不删除，可恢复 | 恢复后能正常召回 |
| FR-C3 | **阈值可配 + 永不归档类别**：承诺、核心事实、长期偏好、**感受** | 这些类别在任何策略下都不被归档 |
| FR-C4 | **库增长有界**：无上限增长时自动触发合并与归档 | 连续两周使用，库大小趋于平稳 |
| FR-C5 | **感受必须被产出**，不只是被保留：从事件卡蒸馏出感受卡，并用「蒸馏」边指向源事件 | 从一批事件卡能产出感受卡，且该卡带溯源边 |

**FR-C5 的措辞是刻意加重的**（「必须被产出」）。原因：只做到「不删感受」，
等于**假设感受是外部送进来的**，而源-U7 问的正是「**如何出现**感受和经验的写入和回忆」。
一条只保护、不生产的路径，恰好跳过了需求里唯一的问句。

**FR-C1 的顺序是约束不是风格**：夜整理的八步顺序有实测依据，
换顺序会让某些机制**产出恒为零**且不报错。见 07 第 2 章。

### 7.4 时间感（FR-D 组）

| 编号 | 需求 | 验收要点 |
|---|---|---|
| FR-D1 | **绝对时间读数**：复用宿主的时间上下文（时刻、时区、距上条消息时长） | 新会话问「现在几点」回答正确 |
| FR-D2 | **相对时间数值**：距上次会话、事件年龄、搁置时长由代码算好并进入打分 | 打分中的时间项来自真实时间差，不是模型推断 |
| FR-D3 | **到期提醒**：一次性 / 每日 / 每周 / 定时表达式，到期投递并唤醒 | 到点无需用户输入自行接力 |
| FR-D4 | **时间边界**：按自然日聚合日摘要，作为整理输入 | 日摘要与日期一一对应 |

**FR-D2 的关键词是「由代码算好」**：时间感不能靠模型读时间戳自己算。
模型算时间差会错，而错了没有任何人会察觉。所有时间量必须在打分前算成数值。

### 7.5 上下文装配与注入（FR-E 组）

| 编号 | 需求 | 验收要点 |
|---|---|---|
| FR-E1 | 记忆卡**只进动态层**；候选池、搜索过程、原文不进上下文 | 上下文里只有卡片摘要 |
| FR-E2 | 主注入通道是**追加式快照**，KV 安全 | 不重写提示词头部 |
| FR-E3 | **token 预算**：每轮注入有硬上限，超限先截断低分卡 | 连续 50 轮占用波动 ≤ ±10% |
| FR-E4 | **压缩后自动重建焦点包**，不丢焦点、不报错 | 触发压缩后继续对话正常 |

**FR-E4 为什么「不需要钩子」**：注入通道的文本是**每轮重新求值的函数**。
压缩改变了历史，下一轮求值自然产生新的快照。所以「压缩后自愈」不是额外实现的能力，
而是**通道选择带来的性质**。这条推论在 02 第 5 章展开。

### 7.6 可观测与运维（FR-F 组）

| 编号 | 需求 | 验收要点 |
|---|---|---|
| FR-F1 | **结构化日志**：每次写入 / 召回 / 整理都留可读记录 | 一条命令能看最近 N 次召回 |
| FR-F2 | **查询命令**：按域 / 类型 / 时间 / 关键词查记忆 | 不需要打开数据库就能查 |
| FR-F3 | **指标**：召回次数、命中率、冲突数、库大小、注入 token | 有最小周报 |
| FR-F4 | **参数版本化与回滚**：阈值 / 权重带版本 | 改坏能一键回滚 |
| FR-F5 | **健康检查**：库完整性校验 | 一条命令报「健康 / 异常」 |

**FR-F 组有一条贯穿性教训**：**「算出来没人看得见，等于没算」。**
一个机制照常运行、结果正确、测试全绿，但没有任何出口让人看到它算了什么，
那么它对使用者等于不存在。这条判断在 06 第 7 章（影子模式的出口）
与 12 第 3 章（可观测性）各出现一次。

### 7.7 后续扩展（本阶段不验收）

| 编号 | 内容 | 触发条件 |
|---|---|---|
| FR-G1 | 图谱扩散与联想（突触效果） | 稳定记忆跑通、积累真实数据 |
| FR-G2 | 状态调制（情绪影响思考方式）与认知换挡 | 稳定记忆 + 联想可解释之后 |
| FR-G3 | 经验抽象（从事件提炼经验卡） | 基础去重合并稳定之后 |
| FR-G4 | 主动性（空闲联想、长期驱动） | 召回质量达标之后 |
| FR-G5 | 多模态 | 文本记忆稳定之后 |
| FR-G6 | 双人格 / 分身 / 交流卡 | 暂缓 |

> **FR-G1 的实际状态**：算法与常量已就位，默认影子模式运行，出厂配置开启。
> 但它**不在本阶段验收范围**，且其第二层（边权可塑性）经数学论证判定为
> **当前不可行**——见 10 的 OP-07。这是一条「需求成立、手段受限」的诚实记录。

## 八、验收

### 8.1 稳定性验收 ST-1～ST-8（本阶段硬指标）

| 编号 | 测试 | 通过标准 | 最容易写错的地方 |
|---|---|---|---|
| **ST-1** | 重启一致 | 相同状态 + 参数 + 查询，连续 10 次召回结果完全一致 | 只测「同进程内 10 次」不够，必须测**跨进程重放后**的 10 次 |
| **ST-2** | 幂等 | 重复导入同一会话两次，卡数不变 | 只测「该丢弃的丢弃」是半个测试，必须测「该更新的更新」 |
| **ST-3** | 崩溃恢复 | 写入中强杀进程，重启后已确认写入完整、无半条记录 | 「无半条」这半边在某些平台**不可能被观测到**，必须写明边界 |
| **ST-4** | 来源可追溯 | 随机抽 100 张卡，100% 能定位回原始事件 | 要说明「能定位」是格式正确还是内容真能对上 |
| **ST-5** | 不编造 | 空库 / 无关话题时明确回答「没有相关记忆」，不臆造 | 「无关」的测试语料必须验零词项交集 |
| **ST-6** | 上下文稳定 | 连续 50 轮，动态层 token 波动 ≤ ±10%，不单调增长 | 波动与增长是两个断言，都要 |
| **ST-7** | 遗忘可逆 | 归档的记忆可恢复并正常召回 | 必须配「归档确实发生过」的前提断言 |
| **ST-8** | 导出重建 | 全量导出后重建，抽查 100 条一致，召回结果一致 | 「100 条一致」必须逐字段，不能只比数量 |

> **ST-1 是全系列最贵的一条验收**。它排除了几乎所有图算法（图遍历顺序会影响
> 浮点累加），也排除了任何用集合迭代顺序的地方。09 里的很多取舍都是被它逼出来的。

### 8.2 场景验收 SC-1～SC-5

| 编号 | 场景 | 通过标准 |
|---|---|---|
| SC-1 | 跨会话回忆 | 次日问「我们昨天聊了什么」，要点正确且不编造 |
| SC-2 | 任务召回 | 提到「上次部署」，能召回当时的原因与结论 |
| SC-3 | 时间感 | 问「距上次聊这个多久了」，回答与代码计算一致 |
| SC-4 | 冲突处理 | 同一事实两种说法，标记冲突并能查历史 |
| SC-5 | 到期提醒 | 到点无需用户输入触发一轮，并说明提醒原因 |

**场景验收与稳定性验收的分工**：ST 组验「机制对不对」，SC 组验「用起来对不对」。
两者不可互相替代——一个机制全对但场景不通的系统，用户拿不到价值；
一个场景看起来通但机制不稳的系统，第三十天会崩。

### 8.3 验收分母

**45 条 = 32 条功能需求 + 8 条稳定性 + 5 条场景。**

这个分母必须写死并统一使用。历史上曾把分母写成 30，导致后面每一个百分比都错了，
**而它不会让任何断言变红**。凡报覆盖率，必须同时报分母是怎么数出来的。

## 九、已定决策 D-01～D-12

这些是**已经拍过板、不再重新讨论**的选择。列在这里是为了防止后来者反复推翻。

| 编号 | 决策 | 理由 |
|---|---|---|
| **D-01** | 插件形态，跑在宿主进程内 | 注入点必须在进程内，外挂进程做不到每轮求值 |
| **D-02** | 先在可热重载的验证环境跑通，再进桌面环境 | 可灰度、可回退 |
| **D-03** | 主注入通道是追加式快照 | 每轮求值、KV 安全、压缩后自愈（C4 + C7） |
| **D-04** | 存储用宿主存储域 + 进程内 SQLite 后端 | 避免原生模块 ABI 风险 |
| **D-05** | 不写自定义会话事件类型 | 读路径会拒绝未知事件（C5） |
| **D-06** | 压缩不做前置阻塞：增量写 + 摘要事件回填 | 宿主没有压缩前钩子（C6） |
| **D-07** | 时间读数复用宿主的时间上下文 | 不重复造时钟，且时区处理已经正确 |
| **D-08** | 数据面单例，行为面按智能体挂载 | 为将来多智能体留接口，当前只有一个 |
| **D-09** | **范围收敛为稳定记忆**：双人格 / 分身暂缓 | 地基优先 |
| **D-10** | 本阶段不引入人格与身份机制 | 稳定记忆不需要人格层 |
| **D-11** | 写入由系统驱动，**不开放「模型写记忆」工具** | 防止自说自话污染库（见 N3） |
| **D-12** | 第一版不做多模态 | 独立感知层，后续接入 |

### 9.1 D-09 是最重要的一个决策

它的意思是：**先把地基做对，再谈智能。**

这条决策否决了一整类看起来很吸引人的方向（双人格、分身、自我叙事、认知档位），
理由不是「做不到」，而是「**地基不稳的时候，上层做得越花，坏得越快**」。

它同时解释了两件事：

- 为什么本阶段的功能需求里没有一条关于「人格」或「自我」。
- 为什么 FR-G1（突触效果）被列为后续扩展，而用户明确想要它——
  **想要的东西和现在该做的东西不是同一件事**。

### 9.2 已定决策的失效条件

决策不是永久的。每条决策都有它的前提，前提变了就该重审。三个明确的失效条件：

| 决策 | 失效条件 |
|---|---|
| D-06（压缩靠事件回填） | 宿主提供压缩前钩子 |
| D-11（不开放模型写记忆） | 出现可审计的写入提议机制（模型提议、系统校验并落库） |
| D-12（不做多模态） | 文本记忆的召回质量稳定达标 |

## 十、需求层的开放问题

> **算法层的开放问题在 10。这里只列「需要人拍板」的问题，不是「需要研究」的问题。**

| 编号 | 问题 | 影响面 | 当前倾向 |
|---|---|---|---|
| RQ-01 | 第一版启用哪些记忆域：只工作域，还是三域全开？ | 决定写入噪声。三域全开会让生活闲聊也进库 | 只工作域（可配置扩展） |

| RQ-03 | 摘要由模型生成还是规则生成？ | 模型生成质量高但在写入路径上不可控；规则生成确定但表达生硬 | 规则生成（可复现优先） |
| RQ-04 | 是否提供硬删除入口（隐私）？ | 与「归档可逆」的平衡 | 提供，但显式确认 |
| RQ-05 | 记忆语言：中文摘要为主，英文与代码原文是否保留？ | 影响摘要与检索 | 保留原文，摘要中文 |

| RQ-07 | 记忆库跨项目复用还是每工作区一套？ | 决定存储分区方式 | 每工作区一套 |

> **RQ-06 值得单独看**：引入向量检索会让「语义相关」这一项显著变好，
> 但向量的来源（本地小模型还是远程 API）会直接冲击 ST-1（确定性）——
> 模型版本一升级，同一段文本的向量就变了，历史结果无法复现。
> 这是一个**用效果换可复现性**的交换，不是纯技术选择。

## 十二、需求之间的冲突与取舍

> **这一章是给架构师的核心内容。** 需求之间不是和谐的，它们互相拉扯。
> 下面列出六对真实冲突，以及本设计的取舍和代价。

### 冲突一：R2（专注）vs R5（联想）

- **R2 说**：不相关的记忆不要进来。
- **R5 说**：记忆之间要能互相带出来（想起 A 就想到 B）。

**联想天然会带进不相关的东西**——这就是「污染」的定义。两者在同一个机制上方向相反。

**取舍**：联想**只加分，不放行**。

具体做法：

1. 联想加分只作用于**总分**，不作用于**相关分量**。
2. 相关分量的闸门（绝对闸）在联想之前就已经决定「这张卡自己够不够格」。
3. 所以联想只能把「本来就已经相关、但排序靠后」的卡拉上来，
   **不可能把一张不相关的卡拉进包**。

**代价**：联想的表达力被限制在「重排序」而非「扩召回」。
真正意义上的「因为想起 A，所以第一次想起了完全不相干的 B」**做不到**。

**为什么接受这个代价**：因为 R2 是「最硬的一条」，而 R5 的验收词是「效果」不是「算法」。
重排序已经能产生可感知的联想效果（这也是影子模式要测的东西），
而扩召回会直接违反源-U6。

### 冲突二：R3（遗忘）vs 可追溯（FR-A5、ST-4）

- **R3 说**：细节该忘。
- **可追溯说**：任意一张卡都能定位回原文，修正要有历史。

**如果遗忘真的删掉数据，溯源就断了。**

**取舍**：**遗忘只做「降级」，不做「删除」。**

- 遗忘的终点是**归档**：卡移出活跃集，不再参与召回，但数据完整保留。
- 真正的物理删除只有一个入口（隐私用途），且需显式确认。
- 归档可恢复（FR-C2）。

**代价**：磁盘不会真正变小。库的**逻辑大小**有界，物理大小单调增长。

**为什么接受**：数据稳定（P2、P5 的「找得回」）比磁盘空间重要得多。
一个不敢用的记忆系统等于没有。

### 冲突三：R8（密度）vs 召回率

- **R8 说**：3～7 张，不是 50 张。
- **召回率说**：该想起的都要想起来。

**张数上限直接限制了召回率上限。**

**取舍**：**牺牲召回率，保密度。**

理由回到源-5：「人思考一个问题时不会代入其它记忆」。人的记忆也是低召回率的——
想不起来的占绝大多数，而这正是「专注」的实现方式。

**代价**：确实会有「明明记得但没召回」的情况。本设计选择让它发生，
而不是用「多塞几张」来掩盖——因为多塞几张会同时破坏 R2。

**一个附带的技术发现**：实测表明「条数上限」与「token 预算」哪个是真闸门
**取决于卡片文本长度**。短卡（≤100 字）时条数上限先生效，长卡（≥120 字）时
token 预算先生效。所以「密度」在不同输入下的实际含义不同，两者必须同时存在。

### 冲突四：确定性（ST-1）vs 效果

- **ST-1 说**：同输入连续 10 次逐位相同。
- **效果说**：想要更聪明、更有联想力的召回。

**几乎所有「更聪明」的图算法都会引入顺序依赖**：图遍历顺序、集合迭代顺序、
浮点累加顺序。一旦引入，同样的输入会给出微小不同的分数，排序就可能翻转。

**取舍**：**确定性优先，牺牲一部分算法自由度。**

具体被牺牲掉的：

| 想做但没做 | 为什么不能做 |
|---|---|
| 逐跳迭代传播（第 2 跳用第 1 跳结果） | 结果依赖遍历顺序 |
| 全局访问集合去重（先到先得） | 引入「哪个种子先处理谁就赢」的顺序依赖 |
| 按相似度动态扩召回 | 候选池变化会让分数不可比 |
| 向量检索 | 模型版本漂移会改变历史结果 |

**代价**：算法的表达力被压在一个很窄的范围内。

**为什么接受**：一个不可复现的记忆系统**无法调试**。当用户说「它昨天记得今天忘了」，
如果结果本身带随机性，就永远分不清是数据问题还是算法问题。

### 冲突五：FR-B7（看到≠使用）vs 学习能力

- **FR-B7 说**：召回本身不改变记忆状态。
- **可塑性说**：用得多的应该变强。

**如果召回就强化，就形成了「被看到 → 更容易被看到」的正反馈。**

**取舍**：**把「看到」和「用上」分开，且「用上」的入口当前不接线。**

具体：

- 召回路径**只读**，不写任何状态。
- 有一个「确认使用」的入口，但它当前**没有任何生产调用方**。
- 边权可塑性（第二层联想机制）因此也**未启用**。

**代价**：系统当前**只衰减、不强化**。这是一个明确的不对称，也是一个已知缺口。

**为什么接受**：因为在没有可靠「被用上」信号的情况下，接上强化会比不接更糟——
它会把「被展示过」当成「被用过」，从而放大噪声。**宁可缺一个能力，
不要接一个会自我放大的错误信号。** 详见 10 的 OP-09。

### 冲突六：可解释（FR-B4）vs 分数真实

- **可解释说**：每条要能说出分数构成。
- **分数真实说**：输出的分数必须就是实际用来排序的分数。

**联想加分和分数构成天然冲突**：分数构成是在打分阶段算的，
而联想加分发生在打分之后。于是「解释里写的分数」和「实际排序用的分数」会不一致。

**取舍**：**分两层呈现，且必须显式标注哪层是假设值。**

- 实际分数：就是用来排序的那个，永远显示真实值。
- 假设分数：联想的加分，放在独立的、明确标注「当前未生效」的行里。

**代价**：解释文本变长，且有被误读的风险（读者可能把假设值当成实际值）。

**为什么接受**：另一种做法（把联想折进分数构成）会让解释**说谎**——
它声称的分数构成里有一部分并不来自卡片自身。这比文本变长严重得多。

### 12.1 六对冲突的总览

```text
                需求 A                      需求 B                  取舍方向
        ┌──────────────────┐      ┌──────────────────┐      ┌────────────────────┐
   ①    │ R2  专注          │  vs  │ R5  联想          │  →   │ 联想只加分不放行     │
        └──────────────────┘      └──────────────────┘      └────────────────────┘
   ②    │ R3  遗忘          │  vs  │ 可追溯 / 可恢复    │  →   │ 只降级不删除         │
   ③    │ R8  密度          │  vs  │ 召回率            │  →   │ 牺牲召回率           │
   ④    │ ST-1 确定性       │  vs  │ 算法效果          │  →   │ 确定性优先           │
   ⑤    │ B7 看到≠使用      │  vs  │ 可塑性 / 学习      │  →   │ 不接不可靠信号       │
   ⑥    │ B4  可解释        │  vs  │ 分数真实          │  →   │ 分层呈现 + 显式标注   │
```

**六条取舍有一条共同形状**：**每一处都选择了「可验证」而不是「更强」**。
这不是保守，是因为这套系统的失败模式大多是**静默的**——不报错、不崩溃、
日志正常，只是慢慢变糊。在静默失败的领域里，可验证性比强度重要得多。
