# 00 · 阅读指引与术语总表

> 本文件是整套设计文档的**入口与契约**。先读完这一篇，再读任何其他篇。
> 本系列共 12 篇，面向**架构师与外部评审者**，自包含：不依赖任何代码库、
> 不依赖任何其他文档、不假设读者能看到实现。

## 一、这套文档是什么

### 1.1 它描述的系统

一套**给对话式 AI 智能体（Agent）用的长期记忆系统**。它要解决的不是「怎么存」，而是
「怎么让一个每次会话都从零开始的模型，拥有连续的记忆，并且这套记忆不会越用越烂」。

系统以一个**宿主平台插件**的形态运行在一个名为 DSH（DeepSeek Harness，深度求索智能体
宿主框架）的智能体运行时里，宿主提供模型调用、会话日志、上下文装配、定时唤醒、持久化
存储等基础设施，本系统在其上构建记忆能力。

### 1.2 它回答的三个问题

| # | 问题 | 落在哪几篇 |
|---|---|---|
| Q-A | **要做什么，做到什么程度算做完** | 01 需求规格 |
| Q-B | **分几层、数据怎么流、每个部件负责什么** | 03 总体架构、04 数据模型、05/06/07 三条链路 |
| Q-C | **每一条数学与算法，哪些已经成立、哪些还没有解** | 08 图谱与扩散、09 数学全集、10 未解算法 |

### 1.3 它不是

- **不是代码说明**。全系列不含任何源代码，只含结构、契约、公式与流程。
- **不是用户手册**。它不教怎么装、怎么配、怎么用。
- **不是进度报告**。它不写「已完成 42 项、剩余 3 项」这类状态，只写「这个设计是什么、
  为什么是这个形状、哪里有洞」。
- **不是完美方案**。第 10 篇整篇在写「哪些算法当前无解」，那是本系列最有价值的部分之一。

## 二、读者与读法

### 2.1 三类读者，三条路径

```text
路径一：只想判断「这东西该不该做、做对没有」
  00 → 01 → 03 → 12

路径二：要接手设计或评审架构
  00 → 01 → 02 → 03 → 04 → 05 → 06 → 07 → 08 → 12

路径三：只关心算法可行性与数学风险
  00 → 01（第 3、4 章）→ 08 → 09 → 10
```

### 2.2 每条路径省不掉的东西

- **01 第 3 章（设计原则）与第 4 章（可量化需求）**：后面所有设计取舍都在回答这两章。
  跳过它们，第 05～08 篇的很多「为什么不能那样做」会显得没道理。
- **02 第 2 章（注入通道）与第 5 章（压缩）**：这两条是宿主给的硬边界，
  整套架构的形状有一半是被它们逼出来的。
- **09 第 2 章（两个分量的分工）**：这是全系列最容易读错、代价最大的一节。

### 2.3 三条阅读提醒

1. **凡标「实测」的数字，都是在本系统上跑探针得到的观测值，不是推导值。**
   凡标「推导」的，都是公式算出来的，可以自己复核。两者混写就是骗人，所以逐条标注。
2. **凡标「已知缺陷」的地方，都是当前实现确实没做对的事。** 本系列不用内部事故编号，
   只写「错在哪、为什么、正确的形状是什么」。**未修的地方就写未修**。
3. **第 10 篇的问题是真的没有答案。** 不要期待那里有「建议方案」，那里只有
   「试过什么、为什么失败、剩下的路在哪」。

## 三、书写约定（本系列的禁则）

这套文档的**唯一目的**是让一个拿不到代码库的人能独立评审设计。因此：

| 禁则 | 原因 |
|---|---|
| **不写源代码**，包括片段、伪代码实现、类型定义、接口声明 | 读者要评审的是设计，不是打字。公式与流程用数学记号和框图表达 |
| **不写文件路径、模块路径、符号名** | 路径是断路：读者点不开，写了等于那句话不存在 |
| **不写内部事故编号、提交号、日期快照** | 这些是内部账本。设计约束要用「为什么」表达，不用「第几号」表达 |
| **不写「详见某文档第几节」以外的外部引用** | 全系列自包含，交叉引用只指向本系列内部 |
| **不写「实测于某时某环境」** | 环境会漂。只写「在什么输入规模下观测到什么」，规模是输入的一部分，可复现 |

**允许且鼓励**：数学公式、ASCII 结构框图、Mermaid 时序图与状态图、参数表、对照实验表。

> 关于图：**结构图、分层图、状态机用 ASCII 框图画**（任何渲染器都能看）；
> **时序图与复杂状态流转用 Mermaid**（不是代码，是图的描述语言）。
> 两类图里所有标签一律中文。

## 五、术语总表

> 英文术语在本系列**首次出现时**带括号。此表是唯一权威，各篇必须与此处一致。

### 5.1 数据与存储

| 中文 | 英文 | 定义 |
|---|---|---|
| 记忆卡 | Memory Card | 记忆的最小存储单元。一张卡是一条可独立召回的语义片段，带类型、来源、显著性、强度等字段 |
| 记忆原子 | Memory Atom | 记忆卡的构成字段，如时间、摘要、来源、显著性、置信度 |
| 来源指针 | Source Pointer | 记忆卡指回原始会话事件的位置，由会话标识、轮次、步骤、事件序号四元组构成 |
| 修正记录 | Revision | 同一事实被更新或纠正时保留的历史版本，旧版本不覆盖、可回溯 |
| 事件日志 | Event Journal | 只追加的记录序列，是记忆库的**唯一真相源** |
| 读模型 | Read Model | 从事件日志重放出来的当前状态视图（卡片集合、图谱边集合、检索索引）。可丢弃、可重建 |
| 重放 | Replay | 从头按序读取事件日志并重建读模型的过程 |
| 幂等键 | Idempotency Key | 每条写入附带的一个键。键相同则视为同一件事重复提交，直接丢弃 |
| 记忆域 | Domain | 记忆的横向分区：生活、学习、工作 |
| 记忆类型 | Kind | 记忆的纵向分类：事件、概念、感受、承诺、经验、摘要 |
| 存活卡 | Live Card | 状态为活跃、且未被合并进其他卡的卡。图谱与召回只处理存活卡 |
| 已合并 | Merged | 卡被去重合并后，标记为指向合并目标，不再独立存在 |
| 硬删除 | Purge | 不可逆的物理移除。与归档（可逆）是两个不同概念 |

### 5.2 召回与打分

| 中文 | 英文 | 定义 |
|---|---|---|
| 召回 | Recall | 给定当前查询，从库中选出若干张卡准备注入上下文的过程 |
| 候选池 | Candidate Pool | 召回第一步从倒排索引取出的候选卡集合，有数量上限 |
| 焦点包 | Focus Pack | 一次召回最终真正注入上下文的记忆卡集合，目标 3～7 张 |
| 词项 | Term | 文本归一化与切分后的最小可比较单位。中文取连续汉字二元组，英文取整个小写单词 |
| 二元组 | Bigram | 中文里相邻两个汉字构成的词项。无词典分词的标准做法 |
| 停用词 | Stop Word | 区分度为零、不参与匹配的高频词（虚词、程度副词、感知动词） |
| 覆盖率 | Coverage | 集合 A 中被集合 B 覆盖的比例，分母是 A |
| Jaccard 相似度 | Jaccard Similarity | 两集合交集除以并集，衡量「两张卡有多像」 |
| 语义分 | Semantic Score | 文本、标签、实体三路覆盖率的加权和 |
| 重要性分 | Importance Score | 显著性、情绪强度、访问频次三者的加权和 |
| 新鲜度分 | Recency Score | 由卡龄与有效半衰期算出的指数衰减值 |
| 目标分 | Goal Score | 卡文本对当前目标的覆盖率。目标缺席时贡献 0，但权重仍留在分母 |
| 冲突惩罚 | Conflict Penalty | 卡被标记的冲突数量带来的扣分 |
| 归一化分数 | Normalized Score | 五个正向分量按固定权重加权后的值，分母恒为全部正向权重之和 |
| 总分 | Total Score | 归一化分数减去冲突惩罚后的值。排序用这个 |
| 相关分量 | Relevance | 只由「语义分」与「目标分」构成的归一化分量。**判断「够不够相关」用它** |
| 绝对闸 | Absolute Gate | 第一道筛选：相关分量低于阈值直接丢弃 |
| 相对闸 | Relative Gate | 第二道筛选：总分低于本轮最高分一定比例直接丢弃 |
| 硬上限 | Hard Cap | 第三道筛选：条数上限，精确截断 |
| token 预算 | Token Budget | 焦点包的注入长度硬上限，含固定开销 |
| 装包 | Packing | 在条数上限与 token 预算内逐条装入卡片的过程 |
| 影子模式 | Shadow Mode | 照常计算某个机制的结果并记录下来，但不让它改变实际输出 |

### 5.3 图谱与扩散

| 中文 | 英文 | 定义 |
|---|---|---|
| 记忆图谱 | Memory Graph | 以记忆卡为节点、以语义关系为边的图结构 |
| 邻接表 | Adjacency | 「节点 → 它的边列表」的映射。扩散算法唯一的图输入 |
| 种子卡 | Seed Card | 扩散的起点。由本轮打分够强的卡担任 |
| 跳数 | Hop | 沿边传播的步数。一跳 = 直接邻居 |
| 跳衰减 | Hop Decay | 每多传一跳，能量乘上的折扣系数 |
| 扩散激活 | Spreading Activation | 从种子出发沿图传播能量，给部分卡加分的算法 |
| 边权重 | Edge Weight | 边的强度，取值 0～1，量化到 0.01 格点 |
| 突触可塑性 | Synaptic Plasticity | 边权随使用而增强、随闲置而衰减的机制。**当前未启用** |
| 共激活 | Co-activation | 两张卡在同一次思考中被一起真正使用。可塑性的唯一合法驱动信号 |
| 度数 | Degree | 一个节点连出的边数 |
| k 近邻 | k-Nearest Neighbors | 每个节点只与最相似的 k 个节点连边，按构造封顶度数 |

### 5.4 巩固与遗忘

| 中文 | 英文 | 定义 |
|---|---|---|
| 巩固 | Consolidation | 批量整理记忆的过程：压缩、去重、合并、降权、归档 |
| 夜整理 | Nightly Consolidation | 每晚执行一次的完整巩固流程，共八步，顺序有约束 |
| 去重 | Deduplication | 找出高度相似的卡并分组 |
| 合并 | Merge | 把一组重复卡合成一张，被合并的卡保留指向新卡的溯源 |
| 归档 | Archive | 把不再重要的卡移出活跃集。**可逆**，不是删除 |
| 强度 | Strength | 卡的当前「生命力」，每夜衰减 |
| 半衰期 | Half-life | 强度衰减到一半所需的时间 |
| 有效半衰期 | Effective Half-life | 由情绪强度与访问频次延长后的实际半衰期 |
| 显著性 | Salience | 写入时算出的「这条信息量有多大」 |
| 情绪强度 | Emotional Intensity | 写入时算出的「这条有多强的情绪色彩」 |
| 置信度 | Confidence | 写入时算出的「这条有多可信」 |
| 摘要卡 | Summary Card | 由下级卡压缩而成的层级摘要，分日、周、月三级 |
| 感受蒸馏 | Feeling Distillation | 从多张反复出现同一情绪的卡中提炼出一张「感受」卡 |

### 5.5 数学与算法

| 中文 | 英文 | 定义 |
|---|---|---|
| 量化 | Quantization | 把连续值映射到有限格点 |
| 格点 | Grid Point | 量化后可取的值。边权共 101 个格点 |
| 不动点 | Fixed Point | 迭代中不再变化的值 |
| 吸引子 | Attractor | 迭代最终收敛到的值。**存在多个吸引子时，「稳态」不是函数而是初值的函数** |
| 档数 | Tier Count | 一个参数系统能分辨出的不同稳态值个数。**必须注明扫的是哪个维度** |
| 指数移动平均 | EMA (Exponential Moving Average) | 用固定比例融合新旧值的递推平均。其稳态等于输入的时间平均 |
| 滞回 | Hysteresis | 上升与下降路径不对称，形成一段不敏感区间 |
| 分辨率上限 | Resolution Limit | 机制在数学上能分辨的最小差异。低于它的参数调节无效 |

## 六、系统一句话与三个时间尺度

### 6.1 一句话

**一条日志、两个视图、三个面。**

- **一条日志**：记忆库的真相源是一串只追加的事件记录。卡片、图谱、索引全部是它的派生视图。
- **两个视图**：当前状态（卡片 + 图谱边）与检索索引（倒排表）。两者都可丢弃、可重建。
- **三个面**：数据面（写得进、存得住）、行为面（取得回、忘得掉）、适配面（接到宿主上）。

### 6.2 三个时间尺度

```text
┌──────────────────────────────────────────────────────────────┐
│ 尺度一：每一轮对话（毫秒～秒级）                                │
│   写路径：门控 → 抽取 0～4 张卡 → 追加日志（异步，不阻塞回复）    │
│   读路径：取候选 → 打分 → 扩散 → 三道闸 → 装包 → 注入            │
├──────────────────────────────────────────────────────────────┤
│ 尺度二：每一夜（一次）                                          │
│   夜整理八步：衰减 → 蒸馏 → 去重合并 → 归档 → 摘要 → 连边         │
│               → 重建索引 → 出报告                               │
├──────────────────────────────────────────────────────────────┤
│ 尺度三：永远（跨会话）                                          │
│   日志只追加。重启即重放。任何视图都可丢弃后重建。                │
└──────────────────────────────────────────────────────────────┘
```

**三个尺度的分工是整套架构的骨架**：
尺度一必须快（在主路径上），尺度二必须准（可以慢），尺度三必须稳（不可丢）。

### 7.1 打分权重

| 参数 | 默认 | 含义 |
|---|---|---|
| 语义权重 | 0.42 | 正文/标签/实体三路覆盖率的合计权重 |
| 重要性权重 | 0.18 | 显著性、情绪、访问频次 |
| 新鲜度权重 | 0.20 | 时间衰减 |

## 十一、本篇的诚实边界

**一、本篇的常量表会腐烂。**

第七章那张「全局常量速查」是**时点快照**。参数一旦调整，它会与各篇正文脱节，
而**它看起来是核过的**——这比不写更坏。

**读法**：把它当索引，不当权威。任何一个数字要用于决策时，去对应的篇目核对，
两处不一致时以**篇目正文**为准（正文有推导过程，常量表没有）。

**二、编号冲突提醒只解决了一半。**

第四章列出了 `P1`～`P8` 与 `OP-01`～`OP-11` 这类编号。本系列内部它们是一致的。
但**本系列之外可能还有一套同字母编号**（例如某个旧文档用 `P0`～`P3` 表示优先级）。
**引用时必须带出处限定**（「本系列的 P3」而不是「P3」），否则读者会在两套体系间跳。

**三、术语表不解释「为什么」。**

第五章每一条只给「是什么」。**术语表的作用是让人读懂别的篇目，不是让人理解设计。**
如果你读完一条术语仍然不知道「为什么这样定义」，那说明该去看对应的篇目正文——
术语表刻意不承担这个职责，因为它一旦开始解释原因，就会与正文产生第二个真相源。

**四、本篇没有说的东西。**

| 没说 | 为什么 |
|---|---|
| 这套系统好不好用 | 没有真实用户、没有基准、没有对照 |
| 实现到了哪一步 | 本系列刻意不描述实现状态，只描述**设计与算法** |
| 参数为什么取这些值 | 每条的依据在各篇正文的「标定依据」里，本篇只给值 |
| 与外部系统的比较 | 没有做过横向调研，任何比较都会是猜的 |

**最后一条最需要强调**：这套文档描述的是**一个设计**，
不是一个已经验证过的产品。**设计与实现的差距、实现与效果的差距，
本篇一个字都没有回答。**
