# 05 · 写入链路

> 本篇讲**一轮对话里的东西怎么变成记忆卡**。

> 本篇不含任何源代码，只含结构、判据、公式与流程。术语与编号以 00 篇为准。

## 一、写路径的位置：它和读路径在时间上完全解耦

### 1.1 一句话

**写路径不在回复的主路径上。**

用户说一句话，模型开始生成回复。回复生成完、这一轮结束之后，写入才发生。
写入的结果（若干张新卡）最早在**下一轮**的召回里才可能被看到。

这带来一个必须说清的性质：**写慢不影响回复**。
一轮抽取要切句、算情绪、抽实体、算显著性、排序、派生标识、追加日志，
这些全部发生在「回复已经发出去」之后。哪怕它慢了 200 毫秒，
用户也感知不到，因为他在等的是下一句话。

这条性质是需求 FR-A1「轮次边界异步写卡，不阻塞回复」的全部内容。
它也是整套系统敢在写路径上做这么多事的原因——**写路径被允许慢，读路径不被允许**。

### 1.2 三个时间尺度里它在哪

| 尺度 | 频率 | 允许的耗时 | 本系统的态度 |
|---|---|---|---|
| 每一轮对话 | 每次交互 | 毫秒～秒级，**且在回复之后** | 可以复杂，不可以阻塞回复 |
| 每一夜 | 每晚一次 | 分钟级，可以很慢 | 必须准，慢不是问题 |
| 永远 | 跨会话 | 不参与交互 | 必须稳，不可丢 |

写路径属于第一个尺度。**它慢是安全的，它漏是不安全的**——这个不对称贯穿全篇。

### 1.3 写路径六阶段

```text
               一轮对话结束（用户输入 + 助手输出 都已就位）
                              │
                              ▼
        ┌─────────────────────────────────────────────┐
        │ ① 门控（整轮级，布尔）                      │
        │    五条通道任一成立即继续，否则本轮 0 张    │
        └─────────────────────┬───────────────────────┘
                              │ 放行
                              ▼
        ┌─────────────────────────────────────────────┐
        │ ② 切句                                      │
        │    用户侧、助手侧各自切成句子序列           │
        │    连续标点归入前一句，不产生纯标点句       │
        └─────────────────────┬───────────────────────┘
                              │
                              ▼
        ┌─────────────────────────────────────────────┐
        │ ③ 逐句过滤（逐句级，四道判据）              │
        │    长度闸 / 入选判据 / 显著性闸             │
        │    情绪达标可豁免其中两道                   │
        └─────────────────────┬───────────────────────┘
                              │ 存活的句子
                              ▼
        ┌─────────────────────────────────────────────┐
        │ ④ 三个量（写入时算，之后不再重算）          │
        │    显著性 = 取较大者(信息项, 情绪项)        │
        │    情绪强度 = 标点项 + 强词项 + 中词项      │
        │    置信度 = 来源权重 + 措辞修正             │
        └─────────────────────┬───────────────────────┘
                              │
                              ▼
        ┌─────────────────────────────────────────────┐
        │ ⑤ 排序取上限                                │
        │    显著性降序 → 文本长度降序 → 文本字典序   │
        │    取前 4 张                                │
        └─────────────────────┬───────────────────────┘
                              │ 0～4 张草稿
                              ▼
        ┌─────────────────────────────────────────────┐
        │ ⑥ 派生标识并追加日志                        │
        │    标识由「域+来源+类型+归一化文本」派生    │
        │    ⇒ 同一事件重复处理得到同一个标识         │
        └─────────────────────┬───────────────────────┘
                              │
                              ▼
                        事件日志（唯一真相源）
```

**六阶段里只有 ⑥ 会碰持久化**，前五个阶段全是纯计算。
这条设计不是洁癖：它让「同一轮对话输入两次，得到逐位相同的草稿」
成为可测试的性质，而不用去模拟任何外部状态。

## 二、门控：五条放行通道

### 2.1 门控在做什么

门控是一个**整轮级**的布尔判断：这一轮对话到底值不值得进入抽取。

它必须是整轮级的，不能是逐句级的。理由是成本：一轮对话可能有二十句，
逐句做实体抽取和显著性计算是六阶段的 ③④ 要做的事；门控如果也要做这些，
它就不是门控了。门控要回答的是一个更便宜的问题——**这一轮有没有可能含有值得记的东西**。

判据便宜到什么程度？五条通道全部只看三样东西：**词表命中、字符数、情绪强度**。
其中词表命中和字符数是常数时间，情绪强度只做一次词表扫描。

### 2.2 五条通道逐一说明

| # | 通道 | 判据 | 它想抓住的东西 |
|---|---|---|---|
| ① | 用户信号词 | 用户侧文本命中信号词表 | 决策、约定、偏好、结论这类「以后还会用到」的话 |
| ② | 用户到期词 | 用户侧文本命中到期词表 | 「明天三点提醒我」这类必须落到时间上的话 |
| ③ | 助手信号词 | 助手侧文本命中信号词表 | 助手给出的结论、方案、判断 |
| ④ | 双方都够长 | 用户侧 ≥ 6 字 **且** 助手侧 ≥ 40 字 | 一段实质性的、双向的讨论 |
| ⑤ | 情绪通道 | 整轮情绪强度 ≥ 0.28 | 情绪表达，见第五章 |

#### ① 用户信号词

**判据**：用户说的话里出现了信号词表里的词。

**为什么需要它**：这是最便宜、最准的一条。人在说「我们决定」「以后都这样」
「记住」这类话时，语言上是有标记的。抓住这些标记，就抓住了大部分有留存价值的内容。

**单独用它时会漏掉什么**：**所有没有语言标记但有信息量的话**。
用户完整地描述了一段经历、解释了一个原因，一个信号词都不含——
而这段描述恰恰是三天后要回忆的东西。信号词是「显式声明」，而人的表达大部分不是显式声明。

#### ② 用户到期词

**判据**：用户说的话里出现了到期词表里的词。

**为什么需要它**：到期词和信号词在功能上是两件事。
信号词说「这条值得记」，到期词说「这条必须落到一个时刻上」。
把它们并成一张表，抽取阶段就没法区分「要记住」和「要提醒」，
而后者需要额外的到期解析（FR-D3）。

**单独用它时会漏掉什么**：几乎所有内容。到期词是极稀疏的一类词，
一轮正常的技术讨论里一个都不会出现。它是**补充通道**，不是主通道。

#### ③ 助手信号词

**判据**：助手说的话里出现了信号词表里的词。

**为什么需要它**：用户的问题常常很短（「那怎么办？」），
真正的结论在助手的回答里。只盯用户侧，会丢掉整段对话里信息密度最高的那一半。

**单独用它时会漏掉什么**：助手的话有大量「正确但无用」的内容——
解释、铺垫、礼貌性收尾。信号词在助手侧的信噪比明显低于用户侧，
所以它必须和 ① 并列而不是替代 ①。

#### ④ 双方都够长

**判据**：用户侧 ≥ 6 字 **且** 助手侧 ≥ 40 字。

**为什么需要它**：这是唯一一条不依赖词表的通道。它捕捉的是「形态」：
两边都说了不少，说明这是一次实质性的交流，而不是一句「好的」加一段模板回复。

两个门槛不对称（6 对 40）是刻意的：用户侧一句话就可能是完整的需求，
助手侧不到 40 字通常是「好的，我明白了」这类无信息量的应答。

**单独用它时会漏掉什么**：**所有短而重的话**。
「我快崩溃了」6 字，够 6 但助手侧不达标；「有点烦」3 字，连用户侧都不够。
更要命的是它和 ①③ 有同一个盲区：判据是长度，而**情绪表达的强度与长度负相关**——
越强烈的情绪，人说得越短。

#### ⑤ 情绪通道

**判据**：整轮情绪强度 ≥ 0.28。

**为什么需要它**：前四条通道的判据全部是「长度 / 信号词 / 实体」，
而情绪表达在这三项上恰恰是弱项。这不是「阈值调高了」，
是**这个维度不在判据里**——调任何数值都救不了它。详见第五章。

**单独用它时会漏掉什么**：所有平静而重要的内容。
一个冷静的技术决策、一段客观的事实陈述，情绪强度接近 0。

### 2.3 为什么五条通道是「或」，不是「与」

```text
放行 = ① ∨ ② ∨ ③ ∨ ④ ∨ ⑤
```

五条通道各自覆盖一类内容，它们的交集很小。做成「与」的话，
能同时满足「用户有信号词」和「助手有信号词」的轮次会少得可怜，
整条写路径会退化成「只记那些双方都在用标记词说话的对话」——
而那恰好是最不像真实对话的一类。

**「或」的代价是误放行**：门控只是第一道粗筛，它放行不等于一定出卡。
后面还有三道更细的判据（第三章）。**用便宜的判据做粗筛、用贵的判据做精选**，
这是整条写路径的成本结构。

### 2.4 四道闸串联：任意一道恒假，整条路径恒假

门控只是四道闸里的第一道。一轮对话要产出一张卡，必须四道全过：

```text
┌──────────────────────────────────────────────────────────────┐
│ 闸①  门控（整轮级）                                          │
│      放行 = 信号词∨到期词∨助手信号∨双方都长∨情绪 ≥ 0.28      │
└───────────────────────────┬──────────────────────────────────┘
                            │ 假 ⇒ 本轮产出 0 张
                            │      后面三道一次都不会执行
                            ▼
┌──────────────────────────────────────────────────────────────┐
│ 闸③  长度闸（逐句级，求值顺序上先于闸②）                     │
│      句长 ≥ 6 字，或情绪达标（豁免）                         │
└───────────────────────────┬──────────────────────────────────┘
                            │ 假 ⇒ 这一句被丢弃
                            ▼
┌──────────────────────────────────────────────────────────────┐
│ 闸②  逐句入选（逐句级）                                      │
│      有信号 ∨ 有到期词 ∨ 有实体 ∨ 情绪达标 ∨ 句长 ≥ 40       │
└───────────────────────────┬──────────────────────────────────┘
                            │ 假 ⇒ 这一句被丢弃
                            ▼
┌──────────────────────────────────────────────────────────────┐
│ 闸④  显著性闸（逐句级）                                      │
│      取较大者(信息项, 情绪项) ≥ 0.25                         │
└───────────────────────────┬──────────────────────────────────┘
                            │ 假 ⇒ 这一句被丢弃
                            ▼
                     进入草稿池
```

> 编号沿用 03 篇的分类编号；实现里的求值顺序是 ① → ③ → ② → ④。
> 顺序不影响下面的结论——结论只依赖「串联」这一件事。

**核心事实**：

```text
产出 = 闸① ∧ 闸② ∧ 闸③ ∧ 闸④
```

这是串联判据的标准形态：**任意一道恒假，整条路径恒假**。
而更隐蔽的是它的诊断性质——**只修任何一道，最终产出仍然是零**。

| 只修这一道 | 会发生什么 |
|---|---|
| 只加门控的情绪通道 | 门控放行了，闸③ 因为「有点烦」3 字把它丢掉 |
| 只豁免长度闸 | 长度过了，闸② 因为「无信号 + 无实体 + 不足 40 字」把它丢掉 |
| 只改逐句入选判据 | 入选了，闸④ 因为显著性 0.063 < 0.25 把它丢掉 |
| 只改显著性 | 显著性够高，但它根本没走到闸④——前三道已经拦掉了 |

**四道闸各自都「合理」**：门控不该为每轮都做重活，长度闸该挡住「嗯」「好的」，
入选判据该挡住复述和寒暄，显著性闸该挡住噪声。每一条单独看都能写出正当理由。
**它们的错误不在任何一道，而在它们的交集为空。**

这个形态有一个非常危险的观测特征：**不报错、不崩溃、日志正常、测试全绿**。
四道闸各自都有测试，各自的测试都通过，而整条链路的产出是零。
只有**端到端**探针能看见它。

> **判据之间是否互相抵消，比单个判据对不对更重要。**
> 写多阈值逻辑时必须问：这几个阈值的可达区间有没有交集。

## 三、切句与逐句过滤

### 3.1 切句规则

切句的输入是一段文本，输出是句子序列。规则只有三条：

| 规则 | 内容 | 为什么 |
|---|---|---|
| 断句符 | 句号、问号、叹号、分号、换行 | 这些是语言上的句子边界 |
| 连续标点归入前一句 | 「真的吗？！」整段算一句，不切成三句 | 见下 |
| 纯标点片段附加到前一句 | 不产生只有标点的「句子」 | 见下 |

后两条是踩出来的，不是设计出来的。

**连续标点为什么必须归入前一句**：早期实现按「零宽后视」切分，
「感觉超级爽！！！」被切成 `…超级爽！` + `！` + `！` 三句。
那两个孤立的感叹号各自拿到 0.12 的情绪分，然后参与**按句平均**——
于是**情绪越激烈，平均情绪强度反而越低**。这是一处方向相反的失效：
它专门惩罚最该被留下的那种句子。

**纯标点为什么不能独立成句**：它既是噪声（每句 0.12 情绪分），
又会稀释平均分。但也不能直接丢掉——「真的吗？！」里的 `！` 属于前一句的语气，
丢掉会让这一句的情绪强度偏低。**两种都错，所以只能附加。**

### 3.2 逐句入选判据

一句通过切句的文本，要成为草稿，必须依次通过：

```text
第一步  长度闸：句长 ≥ 6 字，或情绪强度 ≥ 0.28（豁免）
第二步  入选判据：有信号 ∨ 有到期词 ∨ 有实体 ∨ 情绪达标 ∨ 句长 ≥ 40
第三步  显著性闸：取较大者(信息项, 情绪项) ≥ 0.25
```

三项判据的语义分工：

| 判据 | 回答的问题 | 情绪豁免 |
|---|---|---|
| 长度闸 | 「这句话有没有内容」 | 是 |
| 入选判据 | 「这句话有没有值得记的锚点」 | 是（情绪本身就是锚点） |
| 显著性闸 | 「这句话值多少分」 | 是（取较大者，见 4.1） |

**为什么长度闸要豁免情绪，而不是把长度阈值调低**：

长度阈值 6 字是挡「嗯」「好的」「收到」「行」这类寒暄的。
把它调到 3 字，「有点烦」进来了，「好的吧」「知道了」也全进来了——
**降低闸门高度和给某类内容开一条旁路，是两件完全不同的事**。
前者让所有人都进来，后者只让指定的人进来。

这条区别在测试上有一个直接后果，见 5.5。

### 3.3 单轮出卡上限与排序键

**单轮最多 4 张。** 这不是效果上限，是成本上限：写入发生在每一轮，
一张卡的成本包括一次日志追加、一次索引更新、一次图谱边的潜在重建。
无上限的话，一轮长对话可以产出几十张卡，而其中大部分是同一件事的不同说法。

超过上限时按三键排序取前 4：

| 优先级 | 排序键 | 方向 | 理由 |
|---|---|---|---|
| 1 | 显著性 | 降序 | 主要判据 |
| 2 | 文本长度 | 降序 | 同显著性下，长句信息量更大 |
| 3 | 文本字典序 | 升序 | 兜底，保证结果与输入顺序无关 |

第三键不是装饰。前两键相等的情况在批量导入时会大量出现
（同一模板生成的句子），没有第三键时结果会依赖集合遍历顺序，
而遍历顺序在不同运行之间可能不同——那会直接违反「同一输入十次结果逐位相同」。

### 3.4 助手侧最短长度

助手侧有两条长度门槛，都指向同一件事：**助手的话要先证明自己不是模板**。

| 门槛 | 值 | 作用点 | 挡的是什么 |
|---|---|---|---|
| 助手侧最短长度 | 40 字 | 门控通道 ④ 与助手侧信号词通道 | 「好的，我明白了」这类应答 |
| 逐句入选的 40 字 | 40 字 | 逐句入选判据 | 同上，但作用在单句上 |

两个 40 不是巧合，也不是必须相等的两个常量——它们是**同一个判断在两层的表达**：
「助手说了不到 40 字，大概率没有实质内容」。

**为什么助手侧需要更严的门槛**：用户说 10 个字可能是完整的需求（「把日志目录改成 logs」），
助手说 10 个字几乎一定是应答。**同一个长度，在两侧的信息量期望不同。**

## 四、写入时算出的三个量

三个量全部在写入时算一次，之后**永不重算**。
这是事件溯源的要求：卡是从日志重放出来的确定性函数，
如果某个字段依赖「重放时的当前时间」，重放就不再确定。

| 量 | 取值范围 | 写入后谁在用 | 会不会随时间变 |
|---|---|---|---|
| 显著性 | 0～1 | 打分的重要性分、逐句闸门、排序 | 否 |
| 情绪强度 | 0～1 | 打分的重要性分、有效半衰期、蒸馏候选 | 否 |
| 置信度 | 0～1 | 打分的置信度分量、强度初值 | 否 |

### 4.1 显著性 = 取较大者(信息项, 情绪项)

```text
长度项 = 句长 < 8      → 0.15
         句长 < 20     → 0.50
         句长 ≤ 80     → 1.00
         句长 > 80     → 0.70        ← 太长通常是复述，回退

信号项 = 取较小者(1, 命中信号词数 / 3)
实体项 = 取较小者(1, 抽到实体数 / 3)

信息项 = 长度项 × 0.42 + 信号项 × 0.36 + 实体项 × 0.22
情绪项 = 夹取到[0,1]（情绪强度）

显著性 = 夹取到[0,1]（ 取较大者(信息项, 情绪项) ）
```

三个系数之和 = 1.00，所以信息项天然落在 0～1，不需要额外夹取。

**为什么是取较大者，不是加权和**——这是本篇第二个最重要的判断，理由有三条：

**理由一：加权就得从原有三项里各砍一刀。**
如果做成「信息项 × 0.7 + 情绪项 × 0.3」，那么三项系数之和必须变成 0.7，
原有系数只能按比例缩到 0.294 / 0.252 / 0.154。结果是**所有句子的信息项都下降 30%**。
【实测】那样会让真正的决策句显著性下降 **18%**——为了修一个通道而弄坏另一个。

**理由二：它们是两个独立的、择一的记忆理由，不是互补分量。**
「这句话信息量大」和「这句话情绪强」不是同一件事的两个侧面，
而是**两个各自成立、互不替代的「值得记」理由**：

```text
「明天下午三点提醒我交周报」  信息项高（有信号词 + 有实体 + 够长），情绪项 0
「我快崩溃了」              信息项 0.063，情绪项 0.80
```

加权和表达的是「两者都要有一点」；取较大者表达的是「有其一即可」。
后者才是真实的记忆机制：一条信息量极低的崩溃，恰恰是最该留下的那种记忆。

**理由三：取较大者让原有分数一分不动。**
这是可验证的性质，而不是修辞：对任意句子，若 信息项 ≥ 情绪项，
则显著性 = 信息项，与加入情绪项之前**逐位相同**。
于是「情绪通道的修复」不可能改变任何一句原本就够格的句子的分数。

这条性质有配对的测试守着，见 5.5。

### 4.2 情绪强度

```text
强情绪词项 = 命中强情绪词表的次数
中情绪词项 = 命中中情绪词表的次数
标点项     = 感叹号与问号的个数

情绪强度 = 夹取到[0,1]（ 强情绪词项 × 0.40 + 中情绪词项 × 0.18 + 标点项 × 0.12 ）
```

**合成方式的关键点：命中是「计次」不是「去重」。**
「特别特别开心」必须比「特别开心」更浓，所以同一个词出现两次算两次。
这与「命中信号词」的语义不同——后者是「命中了哪些词」，用于展示给人看；
前者是「情绪有多浓」，用于度量强度。**同一个词表，两种统计口径，服务于两个目的。**

【推导】由公式可以直接算出几个可达值，这是判断阈值是否合理的基础：

| 命中情况 | 情绪强度 | 与门控阈值 0.28 的关系 |
|---|---|---|
| 单个中情绪词 | 0.18 | 低于 |
| 两个中情绪词 | 0.36 | 高于 |
| 单个强情绪词 | 0.40 | 高于 |
| 一个感叹号 | 0.12 | 低于 |
| 两个感叹号 | 0.24 | 低于 |

**0.28 落在 0.18 与 0.36 之间**，这是一条可复核的性质：
它意味着「只带一个中情绪词的句子不足以单独放行」，
而「两个中情绪词」或「一个强情绪词」可以。

这条性质解释了修复后的一处观测：低情绪组出卡率从 43% 降到 20%。
原因不是它们被挡了，而是**排序**——单轮上限 4 张，情绪句的显著性普遍更高，
把原本靠长度进来的低情绪长句挤出了前 4。

### 4.3 置信度

```text
基础分 = 用户侧 0.85 / 助手侧 0.62
不确定措辞（可能 / 也许 / 大概 / 或许 / 不确定 / 好像 / 似乎 / 据说）→ 基础分 − 0.25
确定措辞（确定 / 一定 / 实测 / 验证过 / 确认 / 确实 / 必然）  → 基础分 + 0.12

置信度 = 把基础分夹取到 [0.05, 1.00]
```

**为什么用户侧 0.85 高于助手侧 0.62**：用户说的是他的事实
（「我住在杭州」），助手说的是它的推断（「可能是因为缓存没清」）。
两者都可能错，但错的代价不同——把助手的推断当成用户的事实记下来，
下次召回时它会以「用户说过」的姿态出现。

**为什么下限是 0.05 而不是 0**：置信度要进强度初值。
置信度为 0 的卡强度初值为 0，它会立刻落在归档阈值以下，
等于「写进去然后当夜被归档」。下限 0.05 保证它至少存在过一晚，
可被审计、可被人工恢复。

**这里的措辞词表是硬编码的，而情绪词表必须进配置**——这个不对称是刻意的，见 5.4。

### 4.4 三个量的分工

| 量 | 回答的问题 | 用在哪 | 用错会怎样 |
|---|---|---|---|
| 显著性 | 这条值不值得记 | 逐句闸门、重要性分、排序 | 太低 → 什么都记不进来；太高 → 噪声入库 |
| 情绪强度 | 这条有多浓 | 重要性分、有效半衰期、蒸馏候选 | 太低 → 情绪句进不来、蒸馏没原料 |
| 置信度 | 这条有多可信 | 置信度分量、强度初值 | 太高 → 推断被当事实；太低 → 刚写就归档 |

三者**不能合并成一个「质量分」**。合并之后，一个「情绪极强但来源可疑」的句子
和一个「平淡但来源可靠」的句子会得到同一个分数，而它们的正确处理方式完全不同：
前者该留但该标低置信，后者该留但该排后面。

## 五、情绪通道为什么必须单列

> 这一节是 05 篇的核心。前面四章都在讲「怎么写」，这一章讲
> **「为什么原来那条路对某一类内容整个是关着的」**。

### 5.1 需求源头

需求侧有两句话，是同一个机制的两半：

- **「激素是关键！！！大脑皮层只是记忆，激素控制情绪！！！」** ——情绪决定什么被留下。
- **「其实我们大多数细节都会忘记，只会留下感受。」** ——感受是留下的那部分。

第一句说的是**写入时的筛选权重**，第二句说的是**遗忘之后的残留形态**。
合起来是一个完整的要求：**情绪必须影响「什么能进记忆」，而不只是影响「什么留得久」。**

在修复之前，这个入口**不存在**。而且是以最隐蔽的方式不存在的：
不是没实现，是**四道各自合理的过滤，交集为空**。

### 5.2 四道闸的判据与情绪表达的结构性错配

四道闸的判据全部落在三样东西上：**长度、信号词、实体**。
而情绪表达在这三样上恰恰全是弱项：

| 闸 | 判据 | 情绪句为什么过不去 |
|---|---|---|
| ① 门控 | 信号词 ∨ 到期词 ∨ 助手信号 ∨ 双方都长 | 四条通道无一是情绪；情绪句短，且不含决策词 |
| ② 逐句入选 | 有信号 ∨ 有实体 ∨ 长度 ≥ 40 | 「我快崩溃了」6 字、无实体、无信号词 |
| ③ 长度闸 | 句长 ≥ 6 字 | 「有点烦」3 字 |
| ④ 显著性 | 长度×0.42 + 信号×0.36 + 实体×0.22 | 短情绪句三项全低：0.15×0.42 = 0.063 < 0.25 |

具体到句子：

```text
「我快崩溃了」   6 字   实体 0   信号词 0   信息项 = 0.15 × 0.42 = 0.063
「有点烦」       3 字   实体 0   信号词 0   信息项 = 0.15 × 0.42 = 0.063
「心里有点慌」   6 字   实体 0   信号词 0   信息项 = 0.15 × 0.42 = 0.063
```

三句全部是「情绪极强、信息项极低」的形态。**这不是巧合，是语言事实**：
人在情绪强烈时说得短、说得碎、不点明对象（「烦」「难受」「崩溃了」）。
**判据越依赖长度和实体，情绪表达就越容易被系统性低估。**

而「系统性低估」比「随机漏掉」危险得多：随机漏掉是噪声，可以靠多跑几次补偿；
系统性低估是**方向性偏差**，跑多少次都是同一个方向。

### 5.3 实测对照：情绪越强，越留不下来

【实测】10 句真实感情绪表达，输入同一套门控与逐句判据：

| 观测项 | 修复前 | 修复后 |
|---|---|---|
| 门控通过 | 1/10 | 8/10 |
| 最终出卡 | 0/10 | 8/10 |
| 高情绪组出卡率（情绪 ≥ 0.28） | 17% | 100% |
| 低情绪组出卡率（情绪 < 0.28） | 43% | 20% |
| 反相关（情绪越强越留不下来） | 存在 | 消除 |
| 决策句出卡（对照组） | 1/3 | 1/3（未受影响） |

修复前唯一通过的那一句是「我很担心明天的面试」——
它通过的原因是命中了**「明天」这个到期词**，与情绪毫无关系。

**最关键的观测是这一行**：

```text
高情绪组 17%  <  低情绪组 43%
```

**方向是反的。** 一个声称「情绪是记忆的关键」的系统，
在真实情绪表达上给出了比普通句子更低的通过率。

这个数字的价值不在于它难看，而在于它**排除了「参数没调好」这个解释**。
如果是阈值问题，高情绪组应该和低情绪组同向变化；反相关说明
**情绪这个维度根本不在判据里**——它只通过「拉低长度」这个副作用间接影响结果，
而长度是负向的。

> **判据的通道集合决定了什么能进入记忆。**
> 少一条通道，最该留的那类东西就会恰好被最先丢掉，而且它不报错。

### 5.4 修法的三条纪律

#### 纪律一：取较大者，不取加权

理由已在 4.1 展开。这里只补一条**可验证的后果**：
取较大者之后，「信息量足够的决策句，显著性不会被情绪项改动」是一条
可以逐位断言的等式性质；取加权则做不到——它必然改动每一句的分数。

**一条修复不应该以「弄坏另一个通道」为代价。** 如果它必须，
那说明两个通道被塞进了同一个量里，而它们本该分开。

#### 纪律二：情绪豁免长度闸，但不得降低长度闸

```text
正确：句长 < 6 且 情绪未达标 → 丢弃
      句长 < 6 但 情绪达标     → 放行

错误：把长度阈值从 6 改成 3
```

第二种做法让「有点烦」进来了，也让「好的吧」「知道了」「行吧行吧」全进来了。
**降低闸门高度和给某类内容开旁路，是两件不同的事。**
前者对所有人生效，后者只对指定条件生效。

这条纪律在代码上体现为一个 `且` 条件的位置，在测试上体现为一条配对断言（见 5.5）。

#### 纪律三：情绪词表必须进配置，不能硬编码

原实现的词表只有 18 个硬编码词，而「失望 / 慌 / 焦虑 / 委屈 / 疲惫 / 孤独 / 感激」
**一个都不在表内**——它们全部是中文里最常见的情绪词。

为什么这不是「补几个词」的问题：**「哪些词算情绪」取决于用户的语言习惯，
属于配置项而非常量。** 一个用户说「闹心」，另一个说「emo」，
第三个说「破防」——这些词无法在出厂时穷举，只能由使用者补充。

配置化必须带一条校验：**词表不得为空**。
空表会让情绪强度恒等于标点项，也就是恒 ≤ 0.24 < 0.28，
整条情绪通道静默失效，而它不报错。**一个能让机制静默归零的配置，必须被拒绝加载。**

**对照：为什么置信度的措辞词表反而硬编码？**
「可能 / 也许 / 大概」这类词是**语言的结构性成分**，不是个人习惯；
它们在任何中文语料里都表达同一种不确定性。**配置化的是因人而异的，硬编码的是语言本身的。**

### 5.5 配对的反向对照：只测「该放行的放行」是半个测试

这是本篇最重要的一条**测试纪律**，它比任何一条公式都更值得带到别的项目里。

```text
测试 A：短情绪句豁免长度闸，能进来
        ↓
        通过。但它证明了什么？
        ↓
        证明「长度闸没挡住情绪句」。
        它同样能通过于一个「长度闸被整个删掉」的实现。
```

**一个只断言「该进来的进来了」的测试，无法区分「开了旁路」和「拆了闸门」。**

所以必须配一条反向对照：

```text
测试 B：真正的寒暄仍然被挡
        （「嗯」「好的」「收到」「行」）
        ↓
        它与测试 A 一起，才把「旁路」与「拆闸」区分开
```

同样形态的配对还有两组：

| 配对 | 正向 | 反向对照 | 只做正向会漏掉什么 |
|---|---|---|---|
| 情绪通道 | 情绪句能出卡 | 真正的寒暄仍被挡 | 把闸门整个删掉也能通过 |
| 显著性取较大者 | 情绪句显著性被抬起来 | 决策句显著性**逐位不变** | 直接把显著性改成常量 1 也能通过 |
| 主题词分桶 | 程度副词不聚桶 | 真实主题词仍能聚出桶 | 把分桶整个关掉也能通过 |

**这三组的共同结构是：正向断言证明「机制在工作」，反向对照证明「机制没有把别的东西一起放开」。**
缺了后者，一条通过的测试可能守的是「这个功能被删掉了」。

## 六、抽取产物的形态

### 6.1 一轮产出 0～4 张草稿

六阶段的输出是**草稿**，不是完整卡。两者的区别：

- 草稿只含「这一句自己知道的事」：类型、文本、归一化文本、三个量、标签、实体、来源指针、域。
- 完整卡还要含「写进去才知道的事」：标识、强度初值、创建与更新时刻、状态、访问计数、
  冲突集合、合并溯源、到期时刻。

**为什么分两步**：草稿是纯函数的输出，可以被测试直接比对；
完整卡依赖写入时刻 `at` 这个外部输入，把它也塞进纯函数会让
「同一轮输入两次得到逐位相同结果」变成「同一轮输入两次在同一毫秒得到逐位相同结果」——
后者在测试里不可靠。

### 6.2 草稿 → 完整卡的字段映射

| 草稿字段 | 完整卡字段 | 怎么来的 |
|---|---|---|
| 类型 | 类型 | 逐句分类器的输出：事件 / 概念 / 感受 / 承诺 / 经验 |
| 文本 | 文本 | 原句去掉首尾空白，并按单卡字符上限 160 截断 |
| 归一化文本 | 归一化文本 | 全角转半角、转小写、标点转空格、多空格合并 |
| 显著性 | 显著性 | 4.1 的公式，写入时算一次 |
| 情绪强度 | 情绪强度 | 4.2 的公式，写入时算一次 |
| 置信度 | 置信度 | 4.3 的公式，写入时算一次 |
| 标签 | 标签 | 命中的全部信号词与到期词（去重，保留首次出现顺序） |
| 实体 | 实体 | 实体抽取器的输出（项目名、路径、需求编号、专名） |
| 来源指针 | 来源指针 | 由调用方传入，见 6.4 |
| 域 | 域 | 由调用方传入：生活 / 学习 / 工作 |
| — | **标识** | 由内容派生，见 6.3 |
| — | **强度初值** | 取较小者(1, 显著性 × 置信度 + 0.15) |
| — | 创建时刻 / 更新时刻 | 写入时刻，两者初值相同 |
| — | 状态 | 初值「活跃」 |
| — | 访问计数 | 初值 0 |
| — | 冲突集合 | 初值空 |
| — | 合并溯源 | 初值空 |
| — | 到期时刻 | 初值空，由到期解析单独填（FR-D3） |

**强度初值为什么是 显著性 × 置信度 + 0.15**：
前两项让「重要且可信」的卡一开始就更强；常数 0.15 是地板，
保证一张显著性很低的卡也不会一出生就贴着归档阈值 0.08。
**乘与加的混合不是数学上的优雅选择，是标定的结果**：纯乘会让低显著性卡强度趋近 0，
纯加会让显著性失去作用。

### 6.3 标识由内容派生

```text
标识 = 哈希( 域 ‖ 来源四元组 ‖ 类型 ‖ 归一化文本 )
```

**为什么必须由内容派生，而不是用随机数或递增序号**：

| 方案 | 重复处理同一事件 | 崩溃后重放 | 结果 |
|---|---|---|---|
| 随机标识 | 产出两张卡 | 产出重复卡 | 库膨胀 |
| 递增序号 | 产出两张卡 | 序号漂移 | 违反确定性 |
| **内容派生** | **同一个标识** | **同一个标识** | **幂等** |

幂等是这么实现的：同一轮对话被处理两次，两个草稿的全部输入相同，
于是派生出的标识相同；写入层看到标识相同就视为同一件事的重复提交，直接丢弃。

**注意这条链的脆弱点**：标识依赖「归一化文本」而不是「原文」。
这意味着两句话如果归一化之后相同（大小写不同、全角半角不同、标点不同），
会被判为同一张卡。**这是刻意的**——「Hello」和「hello」不该是两条记忆。
但它也意味着归一化函数是一个**契约**：改它等于改所有历史卡的身份。
所以它属于契约层，不属于实现细节。

**摘要卡为什么能反复生成而不重复**：同一层级同一天的摘要，
其来源四元组里含日期键，归一化文本由统计量渲染而来，两者都相同，
于是派生同一个标识，重复整理直接覆盖。这是夜整理可以反复跑的前提（见 07 篇）。

### 6.4 来源指针四元组

| 分量 | 含义 | 为什么必须有它 |
|---|---|---|
| 会话标识 | 这段对话属于哪个会话 | 没有它就无法「回到那一次对话」 |
| 轮次 | 这一轮是会话里的第几轮 | 会话很长时，只给会话标识等于给了一本书不给页码 |
| 步骤 | 这一轮内部的第几个步骤 | 一轮可能含多次模型调用 |
| 事件序号 | 这个事件在日志里的序号 | 精确到「哪一条记录」，是最后一位精度 |

四元组之外还有两个**附加标注**（不参与定位，只帮助排查）：

- **事件类型**：这条来源是用户消息还是助手消息。
- **来源种类**：这条事件是真实用户输入，还是宿主合成的上下文快照。

第二个标注是必须的，理由在 07 篇会展开：**宿主会把本系统自己注入的焦点包
当作一条用户消息回送**，如果不看来源种类，系统会把自己的注入吃回去，
逐轮自我复制。**「来源是用户」这个判断不能靠事件类型，要靠来源种类。**

## 七、写不进去 vs 写进去但沉淀不下来

### 7.1 两件事，一个观测值

这是本篇第二个核心辨析。系统有两个完全不同的失败：

| 失败 | 含义 | 观测值 |
|---|---|---|
| 写不进去 | 这一轮根本没产出卡 | 产出 = 0 |
| 写进去但沉淀不下来 | 卡产出了，但下游（感受、摘要、图谱）没有从它得到任何东西 | 沉淀量 = 0 |

**两者的观测值可以完全相同。** 而且不止两层——修好一层之后，
下一层的零和上一层的零长得一模一样：

```text
第一层零：门控挡掉了 90% 的情绪句          → 产出 = 0
第二层零：卡进来了，但显著性不够          → 产出 = 0
第三层零：卡进来了，蒸馏按主题分桶，桶数 = 0 → 沉淀 = 0
第四层零：桶有，但候选集被一条判据清空     → 沉淀 = 0
```

**这四层的共同点是：不报错、不崩溃、日志正常。**
所以「重跑一次看看」永远区分不出它们——重跑得到同一个零。

### 7.2 四层探针

区分它们的唯一办法是**逐层设观测点**，而不是看最终产出。

| 层 | 观测点 | 判别方法 | 这一层为零意味着 |
|---|---|---|---|
| 门控层 | 本轮是否放行；放行率 | 对同一批输入统计放行率，并按「高情绪 / 低情绪」分组对比 | 判据的通道集合缺一个维度 |
| 逐句层 | 每句落在哪一道闸；各闸的拦截数 | 逐句打印「句长、信号词、实体、情绪、显著性」五项 | 某一道闸的阈值与该类内容的分布不重叠 |
| 显著性层 | 显著性的两个分量各是多少 | 分别打印信息项与情绪项，看是哪一项把它抬起来或压下去 | 分量合成方式错了（加权 vs 取大） |
| 蒸馏层 | 候选数、桶数、达标桶数、产出数 | 四个数分别打印，看断在哪一步 | 粒度、判据或顺序出了问题 |

**关键纪律：探针必须打印「被测路径确实执行了」的证据。**
一个跑通、有输出、数字看着合理的探针，可能被测的那段代码一行都没执行。
判据不能是「脚本没报错」，必须是一个正向证据——
比如「候选数 = 5」证明了候选筛选真的跑到了，
如果它是 0，后面所有关于桶数和产出的结论都无效。

### 7.3 「能进来」和「能沉淀」是两件事

```text
能进来  =  门控 ∧ 逐句 ∧ 显著性        （本篇第五、六阶段）
能沉淀  =  候选 ∧ 粒度 ∧ 判据 ∧ 顺序    （07 篇第二、六章）
```

**修好前者不等于后者会有产出。** 中间隔着四道独立的关卡，
而它们中任何一道出错，观测值都是同一个零。

这条辨析的实际价值是**排序**：当产出为零时，
先问「原料有没有进来」（看门控层与逐句层），再问「沉淀链路有没有跑」（看蒸馏层）。
反过来查会浪费大量时间——因为沉淀层的探针在原料为零时，
每一个数字都合理地为零，看不出任何异常。

## 八、更隐蔽的失败：产出非零，格式正确，内容在说假话

修好前四层之后，系统终于有产出了。这时会出现第四种失败形态：

```text
产出数量：非零  ✅
格式校验：全部通过  ✅
日志：正常  ✅
测试：全绿  ✅
内容：「『有点』这件事反复牵动我的情绪，前后经历了 2 次」
```

**只有读文本才能发现它在说假话。**

这个失败的成因链条值得完整走一遍，因为它是「每一步都执行成功」的典型：

```text
① 主题词从「二元组切分」得到 —— 执行成功
② 「有点烦」和「有点慌」都含二元组「有点」 —— 统计正确
③ 两张卡聚成同一个桶 —— 分桶逻辑正确
④ 桶内张数 2 ≥ 重复门槛 2 —— 判据正确
⑤ 渲染成「『有点』这件事反复牵动我的情绪」 —— 模板正确
```

五步全部正确，结论是错的。**错在第 ①步选出来的那个词根本不是主题。**

根因：二元组切分没有词典，靠停用词表过滤噪声。原表收了「的 / 了 / 是 / 很」，
但**没有收「有点 / 有些 / 非常 / 感觉 / 觉得」**这类程度副词与感知动词。
它们有两个致命特点：

1. **区分度为零**——几乎每句情绪表达都能带一个；
2. **恰好高频出现在情绪句里**——「有点烦」「有点慌」「感觉很累」「特别开心」。

于是它们成了**最容易被聚成桶的词项**，而桶的内容是假的。

**为什么这不能用「计数指标」发现**：任何计数指标都是绿的。
产出数从 2 变成 1（修好之后）看起来像退化——**「产出变多」和「产出变对」是两件事**，
只看数量会把这条修复误判成回归。

**为什么这不能用「格式校验」发现**：格式完全正确。
模板是固定的，参数是合法的，文本是通顺的。**它在语法上无懈可击，在语义上是假的。**

**为什么这不能用「抽样检查几条」发现**：2 条里 1 条真 1 条假，
抽查命中假的那条的概率只有 50%，而且假的那条**看起来和真的那条一模一样**——
都是「『X』这件事反复牵动我的情绪」的句式。**没有对照就读不出差别。**

唯一可靠的发现方式：**把产出的文本逐条读一遍，并追问「这个 X 真的是一件具体的事吗」。**

> **产出的文本本身是一个需要被断言的输出，不能只断言它非空。**
> 「非零」只证明链路通了，不证明链路对了。

## 九、写路径的诚实边界

写到这里必须说清：上面所有内容里，哪些是已经做到的，哪些是还没做到的。

### 9.1 已经成立的

| 性质 | 状态 | 靠什么保证 |
|---|---|---|
| 五条放行通道都在 | 成立 | 五条各有测试，且有一条端到端用例覆盖「只修一道不够」 |
| 情绪句能进来 | 成立 | 情绪句出卡 8/10，高情绪组 100% |
| 取较大者不取加权 | 成立 | 有配对断言：「决策句显著性逐位不变」 |
| 情绪豁免长度闸但不降闸 | 成立 | 有反向对照：「真正的寒暄仍被挡」 |
| 情绪词表在配置里 | 成立 | 有非空校验，空表加载期失败 |
| 标识由内容派生、幂等 | 成立 | 同一事件重复处理，卡数不变 |
| 单轮上限 4 张 | 成立 | 有边界测试 |
| 写路径不阻塞回复 | 成立 | 写入发生在轮次边界，不在回复生成过程中 |

### 9.2 明确的边界

**边界一：情绪强度只度量强度，不度量极性。**

「开心」和「难过」在同一个量上得到同一个分数。
这不是没做，是**当前不做**——极性需要语义理解，而规则版做不到。
它的直接后果是：蒸馏出来的感受文本只能说「这件事反复牵动我的情绪」，
**绝不能说「这件事让我开心」**。写一个它判断不出的情绪名，就是让文本撒谎。

**边界二：情绪词表的质量取决于使用者。**

出厂表覆盖常见词，但「哪些词算情绪」是语言习惯问题。
表漏一个词不会报错，只会安静地少记一类东西。**这是配置项，不是实现错误。**

**边界三：显著性只判断「值不值得记」，不判断「记得对不对」。**

它不知道这句话是真的还是编的。置信度只管来源（用户 vs 助手），
不管内容。**一个用户说错的结论，会被完整地、高置信地记下来。**
这是设计选择：记忆系统记的是「他说过什么」，不是「事实是什么」。

**边界四：切句对中文标点之外的边界不敏感。**

分号、冒号、破折号的处理是近似。一段没有标点的长文本会被当成一句，
它的显著性由长度项决定（超过 80 字回退到 0.70），可能被误判为复述。

**边界五：「能进来」的验证是端到端的，但「进来之后对不对」只能靠读。**

第八节那类失败没有自动判据。这不是工具不够，是**语义正确性没有可计算的代理指标**——
任何能自动算出来的量（产出数、桶数、覆盖率）都在这类失败上保持绿色。

### 9.3 一条留给评审者的判断

如果只允许评审者问一个问题，应该是这个：

> **五条通道里，哪一条的判据与前四条是「不同维度」的？**
> 如果答案里没有一条是不同维度的，那这套门控就只能记住
> 「说话带标记词的人说的话」——而那不是记忆，是关键词收集。

情绪通道之所以必须单列，不是因为它重要，是因为**它是唯一一条
判据维度与前四条正交的通道**。这也是为什么它缺失时，
症状不是「记得少」，而是「**记得的方向是反的**」。
