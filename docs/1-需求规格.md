# 人格记忆系统 · 需求规格（v0.1）

> 状态：讨论稿（需求收集阶段，尚未冻结）
> 日期：2026-10-31
> 来源：`docs/0-起源.md`、2026-10-31 与 DeepSeek 的 15 轮对话、DSH 宿主源码与文档调研
> 说明：本文档只记录"已知需求"，不含实现代码。待定项集中在第 10 节。

---

## 1. 背景

当前通用 agent 的三个问题：

1. **每次会话从零开始**：跨会话只认得文件，不记得"我们经历过什么、我当时什么感受"。
2. **现有记忆方案是查表，不是记忆**：RAG（检索增强生成，Retrieval-Augmented Generation）、记忆插件、MCP（模型上下文协议，Model Context Protocol）记忆服务，本质都是"模型主动检索 → 候选塞进上下文"，没有时间感、没有情绪调制、没有遗忘与巩固。
3. **堆上下文不解决问题**：百万上下文只是把更多东西塞进窗口，不产生"同一个人"的连续感。

结论：要做的不是更大的记忆库，而是一套**有动力学的记忆系统**。目标是人格连续性（同一个主体在成长），不是任务成功率。

## 2. 目标、非目标与边界

### 2.1 目标（按优先级）

| 编号 | 目标 | 说明 |
|---|---|---|
| G1 | 人格连续性 | 跨会话记得"我是谁、我们聊过什么、感受是什么、学到什么" |
| G2 | 时间感 | 感知当前时刻、距上次交互多久、事情搁置多久、未来什么到期 |
| G3 | 状态调制 | 全局状态向量（俗称"激素"）影响检索、思考档位、输出倾向 |
| G4 | 分层记忆图谱 | 事件→感受→经验→自我叙事，跨层次关联，带突触权重 |
| G5 | 触发阈值 | 检索由"激活超过阈值"决定，不是固定 topK，防止上下文污染 |
| G6 | 巩固与遗忘 | 日积月累、夜间整理、合理遗忘，细节可丢、感受要留 |
| G7 | 主动性 | 会定闹钟、到期提醒、自己醒来整理 |
| G8 | 双人格（后续） | 两个对等完整人格，共享人核基线、隔离经历、可交流协作 |

### 2.2 非目标（明确不做）

- N1 不改模型权重、不做微调（LoRA 等）；模型由服务商提供。
- N2 不做通用记忆 SaaS、不做多用户平台；这是单用户本地系统。
- N3 第一版不做多模态（语音、视频、语气）。
- N4 不追求 AGI 或"强涌现"；只求人格连续性与经验迁移。
- N5 不做三个物理隔离的记忆库；生活/学习/工作用域标签 + 偏置，不复制内容。
- N6 不靠长上下文硬扛记忆；记忆库在后台，上下文只放焦点。
- N7 第一版不做独立常驻服务（不另起进程/数据库服务），以宿主编织插件形态运行。

### 2.3 定位与边界（来自对话的硬约束）

- **是"放大我"，不是"替代我"**：分身替你执行、探索、试错、并行，不替你生活与承担。
- **分身是延伸，不是陪伴**：它是"不甘心"的延续，不是孤独的解药；这条边界要写进人核，防止拟人化过载。
- **机械飞升是长期叙事方向，不是当前任务优先级**：不得让它污染执行层决策。
- **主我保留真实世界锚点**：真实工作、身体、真实接触的人，必须有至少一个分身不可读写的记忆域。

## 3. 设计原则（实现方式的硬规则）

| 编号 | 原则 | 含义 |
|---|---|---|
| P1 | 记忆系统是操作系统，不是提示词技巧 | 写入、衰减、打分由确定性代码完成；LLM 只在两处出现：写入时摘要抽取、召回后归纳表达 |
| P2 | 状态先于语言 | 情绪用数值参数调制检索与档位，不写"你现在很焦虑" |
| P3 | 门控先于检索 | 模型不发起检索；系统在模型开口前预取（90% 本能通道 + 10% 认知通道例外） |
| P4 | 记忆是带置信的线索，不是事实 | 每条记忆带来源、置信度、时效、冲突标记 |
| P5 | 遗忘是功能而不是缺陷 | 细节可以丢，感受与经验要留；不追求记住一切 |
| P6 | 人格连续性是第一目标 | 评估不能只看任务成功率，要看回忆合理性、遗忘合理性、情绪一致性 |
| P7 | 参数可版本化、可回滚 | 在线流程只读参数；只有夜整理能改人格参数，且带版本 |
| P8 | 真实世界锚点不可虚拟化 | 主我保留一个分身不可读写的真实世界记忆域 |

## 4. 用户与使用场景

### 4.1 用户

- **主用户**：老大（C++ 工程师），系统创建者，代号"主我"。
- **后续用户**：No.1 / No.2 两个分身人格（对等、独立记忆、共享人核基线）。

### 4.2 场景

| 编号 | 场景 | 触发 |
|---|---|---|
| S1 | 跨会话连续对话 | 次日打开新会话，agent 知道昨天聊到哪 |
| S2 | 工作任务记忆 | C++ 项目的任务、决策、踩坑、承诺 |
| S3 | 学习域 | 概念、错题、理解演进 |
| S4 | 生活域 | 偏好、关系、日常、情绪 |
| S5 | 夜间整理 | 凌晨自动压缩、提经验、更新人核 |
| S6 | 主动唤醒 | 闹钟到点、未完成事项回捞 |
| S7 | 双人格协作 | 交流卡、经验晋升、定期对账（后续） |

## 5. 术语表

| 术语 | 英文 | 定义 |
|---|---|---|
| 记忆原子 | Memory Atom | 记忆的最小存储单元，7 类之一（事件/感受/经验/事实/概念/未完成/叙事） |
| 突触 | Synapse | 记忆原子之间的带类型、带权重的有向连接 |
| 激活 | Activation | 记忆被当前上下文唤醒的强度，随时间衰减 |
| 触发阈值 | Trigger Threshold | 激活强度超过它才允许进入焦点包的门槛，分进入/退出两档 |
| 焦点包 | Focus Pack | 一次预取后真正注入上下文的记忆卡集合，3~7 条 |
| 工作记忆 | Working Memory | 当前任务栈、临时假设，分钟级 |
| 情节记忆 | Episodic Memory | 发生过的事件卡，天级衰减 |
| 语义记忆 | Semantic Memory | 从情节中抽象出的事实与模式，月级衰减 |
| 自我叙事 | Self-Narrative | 我是谁、我重视什么、我在变成谁，几乎不衰减 |
| 状态向量 | Neuromodulator Vector | 6 个 0~1 的全局调制变量（压力/好奇/疲惫/愉悦/紧迫/信任） |
| 巩固 | Consolidation | 把短期记忆压缩、抽象、重连的过程，夜间执行 |
| 专注锁 | Focus Lock | 与当前焦点无关的记忆被抑制而非降分的机制 |
| 人核 | Persona Core | 价值观、行为边界、关系设定、长期目标，短而稳，慢更新 |
| 交流卡 | Exchange Card | 双人格之间对等的结构化消息，记忆不共享 |
| 汇报卡 | Report Card | 分身向主我上报的结构化摘要卡 |
| 时间状态 | Time State | 代码计算出的相对时间特征集合（距上次会话、事件年龄、到期项） |

## 6. 宿主编织与平台约束

| 编号 | 约束 | 影响 |
|---|---|---|
| C1 | 宿主为 DSH（DeepSeek Harness）预览版，插件为 TypeScript/ESM/Cordis 形态 | 主干语言定为 TS；不引入 Python 核心 |
| C2 | 模型是服务商 API，无权重访问 | 只能做上下文级可塑性，不能改参数 |
| C3 | 存储走宿主 storage domain，后端 node:sqlite / JSON | 不引入原生数据库扩展模块 |
| C4 | 注入主通道是 `systemPrompt.context()`（每轮求值、尾部追加、压缩后自愈） | 记忆卡不重写系统提示词头部 |
| C5 | 不得写自定义 session 事件类型 | 记忆状态只存 storage domain |
| C6 | 压缩没有"压缩前"阻塞钩子 | 改为平时增量写 + 压缩摘要事件回填 |
| C7 | KV 前缀缓存要求"稳定内容在前、动态内容在后" | 记忆卡只进动态层；状态 hint 离散化 + 滞回 |
| C8 | 人格层工具预算 4~6 个 | 其余能力折叠/按需，不挤占动态层 |
| C9 | 单机本地、单用户 | 规模目标 10 万级记忆原子 |
| C10 | 宿主预览版会有破坏性变更 | 必须有适配层，宿主升级只改适配 |

## 7. 功能需求

优先级：P0 = 第一版必须；P1 = 第二版；P2 = 后续。

### 7.1 时间基座

| 编号 | 优先级 | 需求 | 验收要点 |
|---|---|---|---|
| FR-A1 | P0 | 绝对时间感知：每个模型步骤可见当前时刻（带时区）、时段、星期 | 新会话问"现在几点"，回答与注入读数一致 |
| FR-A2 | P0 | 相对时间计算：距上次会话、距上次同类事件、记忆年龄、任务搁置时长，全部由代码算好 | 检索打分的 recency 项来自 Δt，非模型推断 |
| FR-A3 | P0 | 会话节律状态机：休眠/清醒/专注/放松/整理，由真实时钟 + 活动量驱动 | 连续工作 40 分钟后进入疲劳倾向；夜间进入整理态 |
| FR-A4 | P0 | 定时器/闹钟：一次性、间隔（≥1 分钟）、每日、每周、cron；到期唤醒 agent | 设 1 分钟后提醒，到时无需用户输入自行接力 |
| FR-A5 | P1 | 生物钟基线：时段映射到唤醒度基线，可配置 | 同一查询在早晨与深夜的阈值有可观察差异 |

### 7.2 记忆原子与分层

| 编号 | 优先级 | 需求 | 验收要点 |
|---|---|---|---|
| FR-B1 | P0 | 7 类记忆原子：事件卡、感受卡、经验卡、事实、概念、未完成事项、自我叙事摘录 | 每类都有明确的生成条件与字段 |
| FR-B2 | P0 | 原子字段：id、类型、域、创建时间、事件时间、摘要、原文指针、显著性、置信度、情绪向量、访问次数、最近激活、状态 | 字段可导出、可重建 |
| FR-B3 | P0 | 四层时间金字塔：工作记忆（分钟）/情节（天）/语义（月）/自我叙事（年），各层独立衰减常数 | 不同层检索时权重可区分 |
| FR-B4 | P0 | 可插拔域：life/study/work 为标签，可单独激活，跨域靠突触关联不复制内容 | 只开工作域时生活记忆不出现 |
| FR-B5 | P0 | 写入策略：每轮异步写事件卡，不阻塞回复；显著性阈值控制；冷启动偏严 | 回复延迟不受写入影响 |
| FR-B6 | P1 | 原文指针：摘要可回溯会话日志原文；上下文只放摘要级卡片 | 能从记忆卡定位到原始事件 |
| FR-B7 | P0 | 记忆生命周期：工作→情节→巩固→语义→归档，由时间与整理驱动 | 状态转移可在查看器观察 |

### 7.3 突触

| 编号 | 优先级 | 需求 | 验收要点 |
|---|---|---|---|
| FR-C1 | P1 | 边类型：时序相邻、因果、关于、涉及人物、感受、支撑经验、冲突、同域、共激活 | 至少 6 类可检索 |
| FR-C2 | P1 | 权重更新：共激活强化（赫布式）+ 按类型时间衰减 + 用户确认强化 | 多次一起出现的记忆关联变强 |
| FR-C3 | P1 | 冷启动规则建边：同会话相邻、同实体、同域、同主题先建规则边 | 前两周无共激活数据也能扩散 |
| FR-C4 | P1 | 冲突显式暴露：冲突边在焦点包标 CONFLICT 并暴露冲突对象 | 冲突不隐藏，交给模型判断 |
| FR-C5 | P1 | 跨层链接：事件→主题→叙事，各层衰减常数不同 | 能从一次事件走到相关叙事 |

### 7.4 激活与触发阈值

| 编号 | 优先级 | 需求 | 验收要点 |
|---|---|---|---|
| FR-D1 | P1 | 激活衰减：a(t)=a0·exp(-Δt/τ)，按层与类型取不同 τ | 同一条记忆久不访问后更难被召回 |
| FR-D2 | P1 | 阈值集合：习惯命中、检索入选、情绪触发、慢思考切换、写入显著性、冲突判定、遗忘下限、门控开启（至少 8 类） | 每类阈值可配、可观测 |
| FR-D3 | P1 | 滞回与冷却：进入严、退出松、冷却防抖 | 边界附近不抖动 |
| FR-D4 | P1 | 双阈值截断：绝对阈值 + 相对 top 值阈值；topK 硬上限 7 | 全低分时不硬塞 |
| FR-D5 | P2 | 阈值自适应：只在夜整理用 EMA 小步调整，带 clamp 边界与版本回滚 | 阈值不会越调越偏 |
| FR-D6 | P2 | 检索反馈闭环：记录哪些记忆被实际使用，用于权重与阈值信用分配 | 召回质量月度可评估 |
| FR-D7 | P1 | 图谱扩散：有界 BFS 1~2 跳，hops/beam/decay/min_weight 四旋钮；状态调制边权；图谱分打折后与向量分合并 | 扩散不爆炸（候选数可控） |

### 7.5 状态向量（"激素"）

| 编号 | 优先级 | 需求 | 验收要点 |
|---|---|---|---|
| FR-E1 | P1 | 6 个调制变量：压力/好奇/疲惫/愉悦/紧迫/信任，0~1，带衰减与事件触发 | 变量变化可在查看器观察 |
| FR-E2 | P1 | 调制作用：检索权重、思考档位、输出长度、写入显著性、行为倾向 | 高压力时未完成事项权重上升 |
| FR-E3 | P1 | 粗粒度注入：只注入离散化 hint（如"倾向：谨慎"），滞回后才变 | 多数轮次 L2 层文本不变 |
| FR-E4 | P1 | 事件触发规则：被肯定→愉悦↑、临近截止→紧迫↑、连续失败→压力↑，规则可配置 | 规则可单测 |
| FR-E5 | P0 | 情绪来源：第一版从对话文本与事件推断 | 不依赖外部信号即可运行 |

### 7.6 认知状态机与换挡

| 编号 | 优先级 | 需求 | 验收要点 |
|---|---|---|---|
| FR-F1 | P1 | 认知档位：反射/专注/慢思考/发散 | 档位切换有日志 |
| FR-F2 | P1 | 档位作用：检索宽度、阈值、输出长度、是否允许联想 | 不同档位行为可区分 |
| FR-F3 | P1 | 换挡条件：不确定度、风险、情绪强度、置信度、任务类型 | 换挡可解释 |
| FR-F4 | P0 | 单线程纪律：默认单线程；仅工作域允许子任务，结果必须汇总回主线程 | 无并发污染主叙事 |
| FR-F5 | P1 | 习惯缓存："如果…就…"规则，命中优先于检索，可被慢思考覆盖 | 高频场景不再重复检索 |
| FR-F6 | P1 | 双通道：本能通道（自动预取，90%）+ 认知通道（模型显式请求深检索，10%，每轮最多一次） | 认知通道有超时与长度上限 |

### 7.7 上下文装配

| 编号 | 优先级 | 需求 | 验收要点 |
|---|---|---|---|
| FR-G1 | P0 | 三层上下文：L1 人核（短稳可缓存）/ L2 半稳定（状态 hint + 叙事摘要）/ L3 动态（焦点包 + 最近 3~5 轮 + 当前输入） | 三层职责不混 |
| FR-G2 | P0 | 记忆卡只进 L3；候选池、搜索过程、原始长文不进上下文 | L1/L2 每轮字节稳定 |
| FR-G3 | P0 | 焦点包 3~7 条，每条带来源、置信度、时效、冲突标记 | 焦点包可打印、可解释 |
| FR-G4 | P1 | 专注锁：与焦点无关的域/记忆被抑制而非低分 | 无关话题时焦点包为空或 ≤2 条 |
| FR-G5 | P0 | token 预算：L1 ≤1.5k、L2 ≤600、L3 ≤3k（可配），用宿主 token 计量测量 | 超预算时先截断低分卡 |
| FR-G6 | P0 | 注入方式：主注入点 `systemPrompt.context()`（追加式、KV 安全、压缩后自愈）；需要按 step 决策时用 `agent/pre-step` | 不重写系统提示词头部 |
| FR-G7 | P0 | 压缩配合：压缩遮蔽后自动重新物化；压缩后召回内容自动变短、变结构化 | 压缩后不丢焦点、不报错 |

### 7.8 巩固与遗忘

| 编号 | 优先级 | 需求 | 验收要点 |
|---|---|---|---|
| FR-H1 | P0 | 日整理：压缩当日事件 → 提经验 → 合并重复 → 标记冲突 → 更新人核（小步）→ 低显著降权 | 次日能看到经验卡 |
| FR-H2 | P1 | 遗忘策略：低于遗忘阈值的先降权、再归档，默认不硬删；提供导出与恢复 | 遗忘可逆、可审计 |
| FR-H3 | P1 | 永不遗忘类别：身份、承诺、核心事实、真实世界锚点 | 这些记录不会进入归档 |
| FR-H4 | P1 | 人核更新：仅整理时小步更新（max_delta 限制），带版本与回滚 | 人核可 diff、可回滚 |
| FR-H5 | P2 | 周期节律：日整理 / 周对账 / 月叙事更新 | 周期任务可配置 |
| FR-H6 | P0 | 压缩配合：平时增量写；监听压缩摘要事件，用被遮蔽序列回填 | 不做压缩前阻塞写 |

### 7.9 主动性

| 编号 | 优先级 | 需求 | 验收要点 |
|---|---|---|---|
| FR-I1 | P0 | 闹钟唤醒：到期投递提示并唤醒 agent，不等待用户输入 | 到点能自行开一轮 |
| FR-I2 | P1 | 未完成事项回捞：紧迫度高时对未完成事项加权 | 拖延事项会被主动提起 |
| FR-I3 | P2 | 空闲发散：空闲时随机游走联想，产生新突触与灵感候选，需预算控制 | 发散不产生垃圾写入 |

## 8. 非功能需求

| 编号 | 需求 |
|---|---|
| NFR-1 | 延迟：预取在本地完成，不阻塞首 token；单次预取目标 <50ms（万级记忆） |
| NFR-2 | 成本：记忆注入每轮新增 token 有硬上限；稳定前缀不因记忆变化而失效 |
| NFR-3 | 规模：10 万级记忆原子、百万级突触在 SQLite 上可用 |
| NFR-4 | 可靠性：崩溃不丢已提交写入；写入幂等；索引可重建且不影响真相源 |
| NFR-5 | 可移植：数据可导出（JSON/JSONL），不锁定宿主内部结构 |
| NFR-6 | 隐私：数据全部本地；不写密钥；支持整体删除 |
| NFR-7 | 可维护：数据面/行为面/适配面分离；宿主升级只改适配层 |
| NFR-8 | 可测试：动力学为纯函数可单测；关键路径有端到端用例 |

## 9. 已定决策（Decision Log）

| 编号 | 决策 | 理由 |
|---|---|---|
| D-01 | TypeScript / ESM / Cordis 插件主干，不用 Python 核心 | "本能"注入点必须在宿主进程内 |
| D-02 | 先在 CLI `dsh web` profile 验证，再进桌面 profile | 可热重载、可 --patch 灰度 |
| D-03 | 主注入点 `systemPrompt.context()`，`agent/pre-step` 为例外 | 追加式、KV 安全、压缩后自愈 |
| D-04 | 存储用 storage domain + node:sqlite 后端，不引原生模块 | 避免打包运行时 ABI 风险 |
| D-05 | 不写自定义 session 事件类型 | 读取端对未知非 ignorable 事件会拒绝整份日志 |
| D-06 | 人格身份复用 `dsh-persona`，记忆系统只供内容不改身份 | 身份与记忆分离，避免互相污染 |
| D-07 | 时间读数复用 `dsh-time-context`，记忆层只加时间特征与节律 | 不重复造时钟 |
| D-08 | 压缩不做前置阻塞：增量写 + 压缩摘要事件回填 | 宿主没有压缩前钩子 |
| D-09 | 双人格存储在表内按 agentId/sessionId 分区 | 同一 domain 全进程只能打开一次 |
| D-10 | 第一版不做多模态 | 语音/视频是独立感知层，后续接入 |
| D-11 | 数据面（memory-core）在 host 平面单例，行为面在 preset 平面按 agent 挂载 | 双人格共享基线、隔离经历 |
