## 一、本篇的地位与约定

### 1.1 公式、参数与依据各自的权威范围

本篇负责公式与算法推导，第12章集中补列参数及依据；00第7章是全局默认值与推荐基线的入口。
两处共有参数以00的数值为准，00未列出的内部参数以本篇明确表项为准；算法契约以正文推导为准。
变更时必须同步所有出现处，不能用优先级规则掩盖两处冲突。

参数默认值不证明最优，既有观测也不证明本轮推荐方案已经实现或优于基线。
数学上成立、约定环境可复现、真实任务有效是三个需要分别验证的结论。

### 1.2 证据标注必须区分

| 标注 | 含义 | 读者能做什么 |
|---|---|---|
| **【实测】** | 原材料记录的历史观测，本轮未重新运行 | 核对输入与周围公式；缺少原始材料时不能独立复现，不能外推保证 |
| **【推导】** | 明确前提下从公式计算的结论 | 复算公式与边界；前提不成立时不得引用结论 |
| **【判断】** | 经验取舍，尚无充分标定 | 比较替代方案并要求质量与成本证据 |
| **【未标定】** | 尚无足够的参数选择依据 | 在独立语料上标定后再决定是否采用 |
| **【设计决策·待验证】** | 本轮推荐的有边界方案 | 先验数学不变量，再验实现、故障与任务效果 |

历史上曾把连续模型推导出的档数上界，误当成离散参数全空间的已验证结论，
详见第10章。连续公式、有限格点枚举和实际探针必须分别标注；有限扫描只支持被扫描的参数范围。

> 凡声称「必然」或「不可能」，都须列前提、可达区间和反例边界。

### 1.4 全篇骨架：一条数据从文本走到焦点包

```text
  输入       已归一化文本 / 目标文本 / 候选池 / 图谱 / 当前时刻
                              │
                              ▼
  第一层   文本 → 词项集合 → 覆盖率 / 杰卡德 / token 估算
                              │
                              ▼
  第二层   五个分量：语义 · 重要性 · 新鲜度 · 目标 · 冲突惩罚
                              │
                              ▼
  第三层   两个合成量：总分 T（排序用） · 相关分量 R（判相关性用）
                              │
                              ▼
  第四层   三道闸 → 装包 → 焦点包（3～7 张，token 有硬上限）
                              ▲
  第六层   扩散激活 ──────────┘  只加 T，绝不改 R
                              ▲
  第五层   图谱：话题边 / 实体边 / 取代边 / 蒸馏边
                              ▲
  第八层   巩固：去重 · 摘要 · 蒸馏      第九层   可塑性      第七层   遗忘
                              │
                              ▼
  第十层   时间：到期推进 / 五种重复 / 自然日聚合
```

**这张图有两处方向值得记住**：

1. **第五、六层在第四层之前**，但第六层只能改总分。顺序与「谁能改哪个量」
   是两件事，混起来就会让联想绕过绝对闸。
2. **第七、八、九层不在召回路径上**，它们改的是**下一轮召回时读到的状态**。
   召回是只读的（看到不等于用上），这条边界决定了第九层当前为什么没接线。

## 二、第一层：文本 → 可比较的量

### 2.1 归一化：四步，顺序不能换

```text
① 全角转半角：码点减去 0xFEE0（全角空格 U+3000 单独映射为半角空格）
② 转小写
③ 所有标点与符号替换为半角空格
④ 多个连续空格合并为一个，去掉首尾空格
```

**顺序是规范选择，不能用错误的字符范围证明它唯一。** U+FF01～U+FF5E 的兼容全角字符可减去 0xFEE0，但“。”位于 U+3002，并不属于该区间。若按 Unicode（统一字符编码）标点类别正确识别，全角兼容转换与标点替换对许多字符可交换；若只识别半角标点，才需要先转半角。推荐固定上述顺序，并单独验证 U+3002、全角逗号、破折号、表情与空白，保证不跨标点造词项。

| 步骤 | 输入例 | 输出例 | 漏做会怎样 |
|---|---|---|---|
| ① 全角转半角 | ＡＢＣ１２３ | ABC123 | 全角字母不算英文单词，整段丢失 |
| ② 转小写 | Deploy | deploy | 大小写不同被当成两个词项 |
| ③ 标点转空格 | 部署，完成 | 部署 完成 | 二元组跨标点生成「，完」 |
| ④ 合并空格 | 部署␣␣␣完成 | 部署␣完成 | 空词项进入集合，抬高并集大小 |

### 2.2 词项切分：中文取二元组，英文取整词

```text
中文：取连续汉字的**二元组**（Bigram，双字组）
      「线性代数」→ {线性, 性代, 代数}
      单字段落保留为单元组
英文：取**整个小写单词**，不切词干、不去复数
过滤：停用词在切分**内部**过滤，不留在集合里
```

**为什么中文用二元组而不是分词**：系统里**没有词典**。二元组是无词典分词的标准做法，
代价是会产生一些无意义的组合。这个代价被两件事限制住：入参必须是已归一化文本
（标点已变空格，二元组不跨标点），以及停用词表覆盖虚词、程度副词、感知动词。

**英文为什么不切词干**：切词干需要词典与规则，且「deploy / deployed / deploying」
归并后会让两个不同时态的事实看起来是同一件事。**宁可漏匹配，不要错匹配**——
这条取舍与去重阈值 0.86 取严是同一条纪律。

### 2.3 入参约定：必须是已归一化文本

**这是本篇唯一一条「接口约定」性质的规则，而它是一次真实故障的产物。**

切分函数的约定是：**输入是已归一化的文本**。它按空格切段，并假定段内没有标点。
传原文进去会怎样：

```text
原文      ：我今天特别开心，这个项目终于跑通了
归一化    ：我今天特别开心 这个项目终于跑通了
按空格切段：["我今天特别开心", "这个项目终于跑通了"]     ← 段内无标点，正确
传原文切段：["我今天特别开心，这个项目终于跑通了"]        ← 整句一段
二元组    ：… 心， / ，这 / 这 个 …                      ← 跨标点的假词项
```

**【实测】** 传原文时产出的主题词里出现了「，这」「了，」这种片段，
于是感受卡被渲染成「『，这』这件事反复牵动我的情绪」。

**这不是「难看」，是判据错了。** 主题词是**判据**不是标签：两张本来无关的卡
会因为共享一个假词项而被聚进同一个桶。所以这条约定的正确写法不是注释，
而是一条**断言**：切分函数拒绝或至少暴露「输入里还残留标点」这件事。

### 2.4 三个集合运算：分母不同，用途不同

| 运算 | 公式 | 分母 | 回答的问题 | 用在哪 |
|---|---|---|---|---|
| 覆盖率 | $\lvert A\cap B\rvert / \lvert A\rvert$ | **A**（被覆盖的一方） | 「A 有多少被 B 覆盖了」 | 语义分、目标分 |
| 杰卡德相似度 | $\lvert A\cap B\rvert / \lvert A\cup B\rvert$ | 并集 | 「两个集合有多像」 | 话题边、去重、实体边 |
| 词频 | 词项在文本中的出现次数 | — | 「这个词在这段里有多重」 | 只用于展示，不进公式 |

**覆盖率与杰卡德不可互换**，这是最容易犯的错：

```text
A = 5 个词项的短卡，B = 50 个词项的长卡，A ⊂ B
覆盖率(A,B) = 5/5  = 1.00     ← 「A 被完全包含」
杰卡德(A,B) = 5/50 = 0.10     ← 「两者很不像」
```

用错量的后果是方向性的：**用覆盖率做去重，长卡会吞掉所有短卡；
**用杰卡德替换方向性覆盖率，会改变短查询和长卡的取舍，不能沿用原阈值。**

### 2.5 实体抽取：四类可抽，一类明确抽不出

实体是跨层次关联的连接点，也是实体边的唯一输入。

| # | 形态 | 抽取方式 | 状态 |
|---|---|---|---|
| 1 | 文件路径形态的字符串 | 按分隔符切段，取段内非空片段 | 可抽 |
| 2 | 带连字符的项目名 | 按连字符识别整体，保留为一个实体 | 可抽 |
| 3 | 需求编号形态（字母 + 数字） | 按「字母段 + 数字段」的模式匹配 | 可抽 |
| 4 | 引号内的专名 | 取引号内文本 | 可抽 |
| 5 | **无引号的中文专名** | **无法抽取** | **已知边界** |

**第 5 条必须写成断言，不能写成注释。** 理由：注释会被读成「以后再说」，
而它其实是「当前模式识别器对任意无引号中文专名不作可靠抽取保证」。有限上下文可以支持启发式识别，但不能据此宣称普遍的数学不可能。
写成断言的意思是：**有一条测试专门验证「抽不出」**，这样将来谁想「顺手修一下」，
会立刻撞上一条红测试，从而必须先读完这条边界再动手。

**这条边界的代价要写清**：中文里「项目叫青鸟」「找张工确认」这类表达
不会被抽成实体，于是实体边在这类内容上恒为空，跨层次关联退化成只靠话题边。
**这是能力的缺口，不是缺陷，且不能用「多加几个正则」补上**——无引号专名的边界
是语义的，不是字符模式的。

### 2.6 token 估算：不用真分词器

```text
token(t) = CJK 字符数 + ⌈其余字符数 / 4⌉
```

| CJK 码位区间 | 用途 |
|---|---|
| U+4E00 – U+9FFF | 基本汉字 |
| U+3400 – U+4DBF | 扩展 A 区汉字 |
| U+3000 – U+303F | 中文标点与全角符号 |
| U+FF00 – U+FFEF | 全角字母数字与符号 |

这个公式可以确定地复现，但它只是经验估算，不是 token 数的普适上界。“平均每个词元约几个字符”不能推出“每一段文本都不会低估”；对拉丁文本取除以 4 比除以 3 更小，也不是保守方向。汉字、罕见符号和不同模型分词规则同样不能保证一字恰为一个词元。

**【推导】** 按此估算式，“线性代数”为 4，“deploy”为 2，“线性代数 deploy”为 6。这些是估算值，不是指定模型上的真实计数。

**【设计决策·待验证】** 保留估算作快速装包；最终对完整渲染文本使用目标模型版本固定的分词器复计，含模板、元数据与归属于记忆的消息封装开销。超限时减卡或安全截短后重新计数，直到满足预算或为空。无法取得此分词器时，只承诺估算上限，由宿主在最终请求处执行真实硬限制；不能称“估算预算 900”已证明“真实 token≤900”。

## 三、第二层：五分量打分

五个分量各自独立算，都落在 $[0,1]$。**它们互不引用**——这是可解释性的前提：
任何一个分量错了，都能单独定位，不会连锁。

### 3.1 语义分：三路覆盖率的加权和

$$s=\mathrm{clip}\Bigl(0.72\cdot\mathrm{cov}(A_{\text{正文}},Q)+0.14\cdot\mathrm{cov}(A_{\text{标签}},Q)+0.14\cdot\mathrm{cov}(A_{\text{实体}},Q)\Bigr)$$

其中 $\mathrm{clip}(x)=\min(1,\max(0,x))$，$\mathrm{cov}$ 的分母是**卡的那一路**，
$Q$ 是查询词项集合。

| 路 | 权重 | 理由 |
|---|---|---|
| 正文 | 0.72 | 正文是主要语义载体 |
| 标签 | 0.14 | 标签是人工/规则给的摘要，可靠但稀疏 |
| 实体 | 0.14 | 实体是跨层次关联的锚点 |

三项系数和 = 1.00，所以**不需要再夹取**（夹取只是防御）。

**覆盖方向与空集必须明确。** 本篇沿用“卡片某一路有多少被查询覆盖”的方向，分母为该路词项数，空集覆盖率定义为 0；它会惩罚冗长卡、偏好简短匹配，不能同时宣称它保证长卡匹配短查询时高分。若改用查询覆盖率，必须另行标定，也要防一张很长的卡因含很多词而普遍命中。

**标签能单独过绝对闸，也可能成为最终入选卡。** 若只有标签完全命中，则 s=0.14，无目标时 R=0.42×0.14/0.52≈0.1131>0.06；只要没有更强竞争者且长度可容纳，它也能通过相对闸和装包。因此“标签权重小，所以不能当主角”不是保证。标签与实体各 0.14 是工程判断，须用标签污染和同实体难负例检验。

### 3.2 重要性分：三个来源，其中一个是使用频次

$$i=\mathrm{clip}\Bigl(0.55\sigma+0.25e+0.20\cdot\min\bigl(1,\ \tfrac{\ln(1+k)}{\ln 13}\bigr)\Bigr)$$

| 项 | 权重 | 来源 | 写入后是否变 |
|---|---|---|---|
| 显著性 $\sigma$ | 0.55 | 写入时算一次 | 否 |
| 情绪强度 $e$ | 0.25 | 写入时算一次 | 否 |
| 访问加成 | 0.20 | 访问计数 $k$ | **是**（只增） |

**饱和点：$k=12$。** $\ln(1+12)/\ln 13=1$，此后恒为 1。
**【实测】** $k=12$ 与 $k=50$ 的总分**逐位相同**（都是 0.667900）。
也就是说「被访问 12 次」和「被访问 50 次」在这套系统里是**同一件事**。

**饱和点 12 是工程判断，未由这里的数据证明最优。** 对数增益让第 1 次访问的边际增量最大
（$\ln 2/\ln 13=0.270$），第 12 次之后边际价值应该让位于内容本身。
12 次对应「两周内每天看一次」。

**【实测】两个分量的相对力度**——这是本篇最该被复核的一组数：

| 变化 | 总分变化 | 比值 |
|---|---|---|
| 访问计数 $0\to 12$ | $0.036$ | 基准 |
| 显著性 $0\to 1$ | $0.099$ | **2.75 倍** |

**【推导】** 这两个数可以直接从权重算出来，所以它们同时是「实测」和「可复核」：
$0.18\times 0.20=0.036$，$0.18\times 0.55=0.099$，$0.099/0.036=2.75$。

**这个 2.75 倍是本篇最重要的一个比值**：它说明**静态重要性是使用频次的 2.75 倍**。
换句话说，这套系统在打分上**更相信「这条内容本身重要」而不是「这条被用得多」**。
这不是随手定的——它解释了第十章为什么「先修入口，别加机制」：
使用频次通道本来就只有 1/2.75 的力度，再叠一个边级的频次机制，
得到的仍然是一个弱通道。

### 3.3 两个对数值分母（12 与 20）是刻意的

| 用途 | 分母 | 饱和点 | 回答的问题 |
|---|---|---|---|
| 重要性分里的访问加成 | $\ln 13$ | $k=12$ | 「这张卡有多重要」 |
| 有效半衰期里的访问加成 | $\ln 21$ | $k=20$ | 「这张卡能活多久」 |

**为什么允许不同**：排序与寿命是两个不同用途，适合独立标定；本篇没有证据证明它们必须取不同数字。

- **影响排序**：12 次就够。排序是相对的，饱和点再高只会让长尾卡之间继续微调，
  而那部分差异本来就在噪声里。
- **影响记忆寿命**：20 次才饱和。寿命是绝对的——一张被访问 20 次的卡
  和一张被访问 12 次的卡，在「还该不该存在」这件事上确实不同，
  而这个判断的容差比排序大得多。

**如果两处都用 12**，会诱使读者以为它们是同一个量，进而把两处合并成一个参数——
那一刻「排序尺度」与「寿命尺度」就被绑死了，以后想单独调其中一个都不可能。
**参数应按用途命名并独立校准；两个默认值即使相同，也不代表必须合并为同一个参数。**

### 3.4 新鲜度分与有效半衰期

$$r=\begin{cases}0 & h_{\mathrm{eff}}\le 0\\ 1 & \text{卡龄}\le 0\\ 2^{-\text{卡龄}/h_{\mathrm{eff}}} & \text{否则}\end{cases}$$

**两个分支都不是数学上的必要，是防御性的**：

- $h_{\mathrm{eff}}\le 0$ 返回 0 而不是抛错：半衰期来自配置，配置可能被写成 0 或负数。
  返回 0 让这张卡自然沉底，而不是让整条召回路径崩掉。
- 卡龄 ≤ 0 返回 1 而不外推：时钟回拨、写入时刻在将来（跨机器时钟不同步）都会出现负卡龄。
  指数函数在负半轴会给出 $>1$ 的值，而**一个大于 1 的分量会污染加权和**。

**有效半衰期**（情绪与访问频次延长寿命，服务「情绪强的记得更久」）：

$$h_{\mathrm{eff}}=h\cdot\Bigl(1+\mathrm{clip}(e)\cdot(\beta-1)\Bigr)\cdot\Bigl(1+\min\bigl(1,\tfrac{\ln(1+k)}{\ln 21}\bigr)\Bigr)$$

$h=14$ 天，$\beta=2.0$。

| 情形 | $e$ | $k$ | $h_{\mathrm{eff}}$ | 含义 |
|---|---|---|---|---|
| 平静、没被用过 | 0 | 0 | 14 天 | 基准 |
| 情绪满值 | 1 | 0 | 28 天 | 翻倍 |
| 情绪满值 + 访问饱和 | 1 | 20 | 56 天 | 四倍 |
| 卡龄 = 半衰期 | 任意 | 任意 | — | $r=0.5$ |

**【推导】** 上限是 $4h=56$ 天：两个乘数各自封顶 2，乘起来封顶 4。
**这个上限很重要**：它保证「感受卡」不会因为情绪高就永不衰减——
56 天之后它仍然只剩一半。**「留得久」不等于「不消失」**，
后者会让「细节会忘、只留感受」退化成「什么都不忘」。

**为什么做成半衰期的乘数，而不是额外加分**：「忘得慢」和「分得高」是两件事。
前者影响它**多久之后仍然可见**，后者影响它**排第几**。
做成乘数才能实现「感受留得久」；做成加分只是让感受卡排得靠前，
而它照样会在一周后沉底。

### 3.5 目标分：缺席时贡献 0，但权重留在分母

$$g=\mathrm{cov}(A_{\text{卡}},Q_{\text{目标}})$$

**关键约定：目标缺席时 $g=0$，而 0.10 这个权重仍然留在分母里。**

这是一个真实踩过的坑。最初的做法是「没目标就把 0.10 从分母里摘掉」，
理由是「不知道不该算 0 分」。后果：

```text
分母从 1.00 变成 0.90 ⇒ 所有卡的归一化分数统一放大 1/0.9 ≈ 11%
一张语义相关为 0 的死卡：0.168 → 0.187
0.187 > 0.18 阈值 ⇒ 无关的卡开始进焦点包
```

**【实测】** 上面这组数字是本篇最值得记住的一次「改得更精确，结果更糟」。

**取「缺失即中性」的真正理由不是数学，是防御性**：
「目标文本为空」曾经是一个真实的上游漏传。按摘分母的写法，这个漏传会让
**每张卡都涨 11%、更容易进包**——于是**缺陷反而让召回看起来更好，没有人会去修它**。

> **原则**：一个分数如果要在不同输入之间比较，它的计算结构就必须与输入无关。
> 「某些输入下换一个公式」等于让同一个阈值在不同轮次指代不同含义。

这条原则的推论是：**分母恒等于全部正向权重之和，即使某个分量本轮为 0。**
它在架构上被列为一条硬边界，因为违反它不会报错。

### 3.6 冲突惩罚：饱和值 3 未标定

$$p=\mathrm{clip}\Bigl(\min\bigl(1,\ \tfrac{\lvert\text{冲突集合}\rvert}{3}\bigr)\Bigr)$$

冲突数越多扣分越重，但封顶，避免一张卡因多处冲突被彻底埋掉。

**必须诚实标注两件事**：

1. **饱和值 3 没有任何标定。** 它不是从分布里算出来的，也不是从场景里调出来的。
   它只是「三个冲突已经很多了」这个直觉。**【未标定】**
2. **产生冲突集合的判据当前方向是错的**（见 10 的 OP-06）。
   所以这个惩罚项**在惩罚一个不可信的量**。它数学上没问题，前提是假的。

第二条的严重性在于：**一个坏判据的产出被当成事实消费**。惩罚项本身会正常计算、
正常扣分、正常出现在可解释输出里——**每一步都成功，只是前提是错的。**

## 四、第三层：两个合成量

打分最终压成**两个数**，这是全篇最重要的结构决定。

### 4.1 为什么要两个数而不是一个

| 量 | 公式 | 用途 | 是否随查询变 |
|---|---|---|---|
| 总分 $T$ | 五个分量加权后减惩罚 | **排序**、相对闸 | 部分（语义、目标随查询变） |
| 相关分量 $R$ | 只用语义与目标两个分量 | **绝对闸**、种子判据 | 完全随查询变 |

**一个数不够，是因为它必须同时干两件相反的事。**

- **排序**要综合所有信息：内容相关、这条本身重要、它还新鲜、它可信。
  这四件事都对「该先看哪张」有贡献。
- **判断相关性**只能看内容：一张卡再重要、再新鲜，如果跟当前问题无关，
  它就**不该被注入**。而「重要」和「新鲜」是**与查询无关**的，
  把它们算进相关性判据，等于让「这条很重要」成为「这条与当前问题相关」的证据。

**一个标量很难同时保留这两种可解释的判据**，所以必须拆成两个数。
这也是全篇唯一一处「同一个打分算两遍」的地方——**重复计算是为了让判据纯粹**。

### 4.2 总分的完整推导

$$T=\mathrm{clip}\Bigl(\ \underbrace{\frac{0.42s+0.18i+0.20r+0.10g+0.10c}{1.00}}_{\text{归一化}}\ -\ 0.25p\Bigr)$$

**五个权重之和恰好是 1.00**，所以归一化的分母就是 1.00——但这不代表可以省略它，
理由见 3.5：**分母必须显式写成「全部正向权重之和」，即使某分量为 0。**

| 分量 | 权重 | 与查询有关 | 说明 |
|---|---|---|---|
| 语义 $s$ | 0.42 | **是** | 正文 / 标签 / 实体三路覆盖 |
| 重要性 $i$ | 0.18 | 否 | 显著性 + 情绪 + 访问 |
| 新鲜度 $r$ | 0.20 | 否 | 指数衰减 |
| 目标 $g$ | 0.10 | **是** | 与目标文本的覆盖 |
| 置信度 $c$ | 0.10 | 否 | 写入时定 |

**【推导】与查询无关的权重合计 = 0.18 + 0.20 + 0.10 = 0.48。**
这个 0.48 是全篇被引用最多的一个派生数字，因为它是**一切「总分不能当相关性用」的论证起点**。

### 4.3 相关分量的完整推导

$$R=\mathrm{clip}\Bigl(\frac{0.42s+0.10g}{0.52}\Bigr)$$

**分子为什么只取这两项**：它们是仅有的两个「随查询变化」的分量。
$i$、$r$、$c$ 三个量在查询进来的那一刻就已经定了，它们无法区分「这一轮问什么」，
所以它们不能进相关性判据。

**分母为什么是 0.52 而不是 1.00**：这是一个必须解释清楚的选择。

```text
若分母用 1.00：R = 0.42s + 0.10g ∈ [0, 0.52]
              ⇒ R 的数学上限是 0.52，任何阈值都要在这个缩小的区间里选
              ⇒ 0.5 仍可达，但接近上限；它不代表相关概率 50%

若分母用 0.52：R = (0.42s + 0.10g) / 0.52 ∈ [0, 1]
              ⇒ s = 1, g = 1 时 R = 1.00，区间被拉满
              ⇒ 阈值可以在 [0,1] 全区间标定
```

**这个选择有一个必须承认的代价**：$R$ 把 0.52 的权重区间拉伸到 $[0,1]$，
相当于**放大了 1/0.52 ≈ 1.92 倍**。所以 $R$ 不是「相关性的绝对度量」，
而是「在相关维度上的归一化位置」。固定分母只保证尺度定义一致，不保证不同查询长度、词项分布与目标条件下的质量可比；它也不是经过校准的相关概率，不能与 $T$ 直接比较大小。

### 4.4 相关分量的收缩：无目标时的 0.8077

目标缺席时 $g=0$：

$$R=\frac{0.42s}{0.52}=0.8077\,s$$

**【推导】** $0.42/0.52=0.80769\ldots$，即所有卡的 $R$ 统一打 **8.08 折**。

**这就是「无目标时系统性更严」的精确含义**。而绝对闸 0.06 是对 $R$ 标定的，
所以无目标时过闸需要：

$$s\ \ge\ \frac{0.06}{0.8077}=0.0743$$

**【推导】** 0.0743 是「无目标时通过绝对闸所需的最低语义分」。

| 情形 | 过闸所需 $s$ | 严格程度 |
|---|---|---|
| 有目标且 $g=1$ | $\max(0,(0.06\times0.52-0.10)/0.42)=0$（已过） | 最松 |
| 有目标但 $g=0$ | 0.0743 | 与无目标相同 |
| 无目标 | 0.0743 | — |

**注意第二行**：有目标但内容完全不搭时，$g=0$，要求与无目标完全一样。
所以「有目标」本身不放松判据，**只有目标真的命中才放松**。这是对的。

### 4.5 冲突惩罚为什么只扣总分不扣相关分

$$T\ \text{减}\ 0.25p,\qquad R\ \text{不减}$$

**理由与 3.5 同源，但方向相反**：冲突是「这条记忆与另一条记忆矛盾」，
它**不改变这条记忆与当前查询的相关性**。两张互相矛盾的记忆可以都与当前问题高度相关
——而那恰恰是最该被同时看到的情形（用户需要知道自己的说法前后不一）。

**如果冲突也扣 $R$**：一张与当前问题高度相关但存在冲突的卡会被绝对闸挡掉，
于是用户**看不到自己前后矛盾**，而这正是记忆系统最该帮他发现的事。
**惩罚应该降低它的排序，不应该让它消失。**

### 4.6 总分相对范围被压平：口径与范围

原稿在两批样本中报告总分最小值除以最大值分别为 0.9059 与 0.9655。这是最小/最大比，不能称“最大/最小”或笼统称统计离散度；值不超过 1，越接近 1 说明范围越窄。相应相关分量的比值分别为 0.7237 与 0.8158。

**【推导】** 在这两批候选上，用总分的最高值乘 0.85 选种子会使所有候选成为种子，排除种子后的受益集因此为空。原因是这批数据与门槛的关系，不是“采用两把尺子必然恒空”。0.48 只是查询无关正向权重的合计上界；各分项可以为 0，并非数学上的共同分数地板。

种子改看相关分量能修复该反例，但不能保证每轮都有受益者。零相关、并列相关或护栏高于非种子区间时，无加分是合法结果，必须记录具体原因。推荐定义见第 7.8 节。

## 五、第四层：三道闸与装包

### 5.1 三道闸，两种尺子，一个硬上限

**【设计决策·待验证】** 令 C 为已通过授权与存活检查、并按本轮内容域策略取出的有限候选，E={v∈C:Rᵥ≥0.06}。E 为空直接返回空包；否则先冻结 B=maxᵥ∈ᴱ Tᵥ，其中 T 是未扩散总分。扩散后按实际总分降序与稳定标识定序，保留 T′≥0.55B 的卡，再受 7 张上限与最终长度预算约束。这样未过相关闸的卡不能抬高相对门槛，扩散也不能靠抬高基准间接赶走别卡。

| 闸 | 判据 | 尺子 | 职责 |
|---|---|---|---|
| 绝对闸 | R≥0.06 | 词项相关分量 | 去掉低于相关代理下限的候选 |
| 相对闸 | T′≥0.55B | 总分 | 过滤相对于本轮合格基线明显偏弱者 |
| 硬上限 | 张数≤7 | 计数 | 控制密度，允许少于 3 张或为空 |
| 最终预算 | 完整序列化文本计数≤预算 | 目标模型词元 | 控制注入长度，不能被“至少一张”绕过 |

相对闸没有“全都很弱时必为空”的性质：只要非空集合的最高分非负，最高分就一定不低于自己的 0.55 倍；所有卡同为零也会通过比例比较。绝对质量由相关闸与独立验收承担，不能让相对闸替它作保证。

### 5.2 绝对闸为什么必须在 $R$ 上

这是一次真实修错的结果，必须完整记录。

**修错前**：绝对闸架在 $T$ 上，阈值 0.18。问题是这批样本中 $T$ 带有较大的**查询无关贡献**——
原稿的已测无词项重合样本约为 0.33（$i$、$r$、$c$ 各贡献一份）。
于是 0.18 在这批样本中未能过滤；这不是任意合法卡都具有的数学下界。

**【实测】** 12 个样本的最低 $T$ 是 0.3295，无一低于 0.18。

**更糟的是第二层**：当时还有一个「冲突惩罚封顶」的逻辑，它把 $T$ **精确钳在阈值上**。
于是分数分布出现了「10 张卡全部挤在 0.18」的形状，而**分差从 0.031 缩到 0.000**。
一个把所有人压到同一分的打分，排序退化成按标识取——**排序机制实际失效**。

| 缺陷形态 | 症状 | 为什么难发现 |
|---|---|---|
| 阈值当分数地板 | $T$ 被钳在 0.18，分差归零 | 分数看着合理，只是全都一样 |
| 判据恒真 | 0.18 低于已观测样本的最低分 | 「全低分时不硬塞」这条断言永不失败 |

**修法**：删掉封顶 + 新增 $R$ 分量 + 绝对闸换尺子。**推荐基线的相对闸留在 $T$ 上，并冻结未扩散合格集合的基准；其他尺度需独立标定。**

### 5.3 相对闸为什么不能也换到 $R$ 上

**统一尺子看起来更干净，但会误杀真相关卡。**

**【实测】** 某验收场景的目标卡：

| 卡 | $R$ | 相对闸（$R$ 尺度） | $T$ | 相对闸（$T$ 尺度） |
|---|---|---|---|---|
| 目标卡 | **0.1113** | 闸 0.1121 ⇒ **被挡（差 0.0008）** | 0.3925 | 闸 0.2522 ⇒ 轻松通过 |

**差 0.0008 被挡**——这个量级说明 $R$ 的相对判据**余量极小**，
任何微小改动都会翻转结果。

**现有局部比较揭示了不同取舍**：

- 相对闸在 $T$ 上 ⇒ 淘汰「旧而相关」的卡（$R$ 高但 $T$ 低）。
- 相对闸在 $R$ 上 ⇒ 淘汰「真相关但分数贴近」的卡（如上表）。

**0.55 是在两者之间选的，而且它没有分布级标定**——它是某个场景手工调出来的。
这条必须诚实标注为**【未标定】**。

### 5.4 「旧而相关」被淘汰：97% 的查询受影响

**【实测】** 随机 2000 组有效试验：

```text
出现「R 高于已选最低卡却被丢弃」的组数：1940 / 2000 = 97.0%
平均每组被丢弃的高 R 卡数：6.29
```

原稿的“新而无关 T=0.85、R=0.07；旧而相关 T=0.30、R=0.95”无法由本篇公式产生。因为未扣惩罚的查询相关贡献恰为 0.52R，其他正向贡献在 [0,0.48]、最大惩罚为 0.25，所以：

$$\max(0,0.52R-0.25)\le T\le\min(1,0.52R+0.48).$$

R=0.07 的 T 最大只有 0.5164，不能达到 0.85；此时相对门槛最大 0.28402，T=0.30 的卡也不会被它挡掉。一个可实现的反例是：卡甲 R=0.2、查询无关贡献为 0.48、无冲突，得 T=0.584；卡乙 R=0.4、其他贡献与惩罚皆为零，得 T=0.208，低于 0.55×0.584=0.3212。二者均过绝对闸，甲的相关代理更低但总分更高。

97% 观察只说明“相关分量更高的未选卡”很常见；没有逐条丢弃原因，不能全部归因于相对闸，条数、长度与冲突也可能参与。排序包含重要性与新鲜度本来就允许这种权衡；是否违反任务需求，要看人工任务标签与完整反事实，而非只按 R 排名判断。

### 5.5 装包：token 预算与两级截断

```text
单卡预算 = 900 − 100 = 800
逐卡：文本截到 160 字 → 估 token → 超预算就跳过
若第一张就超预算：文本再截到 max(8, 160/2) = 80 字   ← 两级截断
最终 token = 空包 ? 0 : 已用 + 100
```

**两级截断的含义**：$160$ 是「常规上限」，$80$ 是「连一张都放不下时的退让」。
所以调低常规上限会**同时**影响两级——这是一处容易漏的耦合。

**空包 token 为 0**，不是 100。这不是省事：头尾开销只在真的有内容时才产生。
但它有一个副作用——**不能从空包反推开销值**。

### 5.6 【实测】哪个闸门真的生效

| 卡文本长度 | 实际装入 | 包 token | 单卡成本 | 受限于 |
|---|---|---|---|---|
| 20 字 | 7 | 268 | 24 | **张数上限** |
| 50 字 | 7 | 478 | 54 | **张数上限** |
| 80 字 | 7 | 688 | 84 | **张数上限** |
| 100 字 | 7 | 828 | 104 | **张数上限** |
| 120 字 | **6** | 844 | 124 | token 预算 |
| **160 字** | **4** | 756 | 164 | token 预算 |
| 200 字 | 4 | 752 | 163 | token 预算 |

**结论：哪个是真闸门取决于卡文本长度，不是一个固定答案。**

典型卡文本 40～100 字，所以**多数情况下张数上限 7 才是生效的闸门**。
而 160 字是截断上限，**不是典型长度**——这两件事在文档里必须分开写，
否则读者会把「上限 160」读成「通常 160」。

**这条结论的来历值得记**：本节第一版算的是「单卡最多约 160 token，
$800/160=5$，所以满配装 5 张」。**实测是 4 张**——因为还有固定字段开销，
单卡实际成本 164 而非 160。**推算值必须回探针核。**

### 5.7 原稿估算口径：头尾预留量为 100

```text
一张 60 字卡：包 token = 164
两张 60 字卡：包 token = 228
差值 = 64          ← 单卡增量成本
开销 ≈ 164 − 64 = 100   ← 与配置值 100 精确相等
```

该差分只能证明这两条输入在原计数口径下呈现 100 的截距；若原计数本来就主动加了 100，它更是记账自洽检查，不是对真实分词器的独立标定。它同时是一个**固定预留风险**：
头尾文案（标题 / 当前时间 / 免责尾注）一变，它就失真，而 token 上限是**硬上限**。
**一个准确的硬编码常量仍然是一个会过期的常量。**

## 六、第五层：图谱

图谱有四类边。它们的**建法完全不同**，而这个不对称本身就是一处结构问题。

### 6.1 四类边一览

| 边 | 语义 | 建法 | 度数上限 | 权重 |
|---|---|---|---|---|
| 同话题 | 「说的是一件事」 | k 近邻 | **每端 ≤ 3** | 杰卡德相似度 |
| 同实体 | 「提到同一个东西」 | 共享实体全连 | **无** | 交集 / 并集 |
| 取代 | 「新的推翻旧的」 | 修正记录派生 | — | 1.00 |
| 蒸馏 | 「由这些聚合而来」 | 巩固时派生 | — | 1.00 |

### 6.2 同话题边：k 近邻 + 下限

```text
候选对：(i, j) 满足 下限 0.08 ≤ 相似度 < 去重阈值 0.86
排序键：相似度降序 → from 升序 → to 升序
贪心取边，同时维护双向度数：
    任一端已达 3 ⇒ 跳过
```

**为什么上限是 0.86 而不是 1.0**：相似度 ≥ 0.86 的对是**重复卡**，
它们应该被去重合并，而不是连一条边。**两条边的语义会打架**——
如果既合并又连边，图谱里会出现「一张卡指向自己」的形态。

这里实际采用的是“双端限度贪心选边”，不是普通的逐点 k 近邻。普通每点提名 k 个再取无向并集只保证边数≤nk，单点度数可达 n−1；互为近邻或双端限度才保证度数≤k、边数≤⌊nk/2⌋。推荐使用现有确定排序后的双端限度，保留相似度下限，承认它可能造成孤点且不保证全局最优总权重。

绝对下限负责去掉“最近但仍无关”的对，限度负责控制图规模。二者都要检验，不能声称相对量天然稳定、绝对阈值必然失效。卡文本或实体更新后，旧派生边应失效重建；“只新建不改旧”不能维持度数和相似度契约。

### 6.3 【实测】下限 0.08 的标定

| 下限 | 平均度数 | 说明 |
|---|---|---|
| 0.05 | 10.09 | 图近似完全连通，扩散失去意义 |
| **0.08** | **3.75** | 选定值 |
| 更高 | < 3 | 图稀疏，孤立卡增多 |

原稿称此表来自参数扫描，但平均度数 3.75 与 10.09 都大于每端上限 3，不能是同一双端限度图的度数。它只能说明限度前阈值候选图的稠密度；缺少探针契约时不能用于证明限度后图质量，也不能把 10.09 直接称作完全图。0.08 是工程下限，高于它仍须竞争有限边预算。

### 6.4 同实体边：无度数上限，因此是二次的

```text
对每对共享实体的卡：权重 = |共享| / |并集|
无度数上限
```

**两类边处理不对称的原因不是疏忽，是语义**：「同话题」是一个**连续量**（相似度），
可以排序取前 k；“共享实体”虽是二值判据，实体边的杰卡德权重仍是连续排序信号，因此“无法排序”不是不设上限的理由。

**但这个不对称有代价，而且这个代价随规模爆炸**：

**【实测】** 每卡 3 实体、实体池 = $n/10$：

| $n$ | 实体池 | 实体边 | 总边数 | 耗时 |
|---|---|---|---|---|
| 500 | 50 | 12250 | 12999 | 85 ms |
| 1000 | 100 | 24500 | 26000 | 223 ms |
| 2000 | 200 | 49000 | 52000 | 761 ms |
| 3000 | 300 | 73500 | 78000 | 1526 ms |
| **5000** | 500 | **122500** | **130000** | **3621 ms** |

**单次夜整理光建图就 3.6 秒，产出 13 万条边。**

**【实测】** 边数随规模的增长（每卡 3 实体、实体池固定 40）：

| $n$ | 实体边 | 话题边 | 总边数 | 最大总度数 | 边数比 |
|---|---|---|---|---|---|
| 50 | 138 | 74 | 212 | 10 | — |
| 100 | 579 | 150 | 729 | 15 | ×3.44 |
| 200 | 2400 | 300 | 2700 | 27 | ×3.70 |
| 400 | 9800 | 600 | 10400 | 52 | ×3.85 |
| 800 | 39600 | 1200 | 40800 | **102** | ×3.92 |

**边数随 $n$ 翻倍增长约 3.9 倍 ⇒ 二次。**

**极端场景**：实体池 = 5（所有人共享同一批实体），$n=400$ 时最大总度数 **242**，
接近完全图。此时扩散的排序分辨力归零（见 7.5）。

第二张固定实体池表接近平方增长；第一张实体池随规模扩大的表中，实体边数与 n 成正比。二者不能混为同一个增长律。一般地，枚举量为 Σₑ dₑ(dₑ−1)/2，去重后的唯一卡对最多为 n(n−1)/2，dₑ 为包含实体 e 的卡数；实现若仍比较全部卡对，即使输出线性也可能花平方时间。

**【设计决策·待验证】** 保留卡片—实体成员关系，在有限存活候选内按需计算实体权重，按双端限度贪心投影为传播边。先复用每端 3 条预算；话题与实体两种图合并后每卡至多 6 条，来源关系另计。候选数 400 时最多比较 79800 对，只是工作量上界，是否满足召回时延仍需实测。完整成员事实仍保留，不需要物化全部实体团。

### 6.5 权重量化：101 个格点

$$q(w)=\frac{\mathrm{round}(100w)}{100},\qquad w\in\{0,0.01,\dots,1\}$$

**输出只有 101 个格点，是一种精度与存储策略，不是确定性的必要条件。** 若要精确比较，应保存整数格号 0～100，展示时除以 100；不能把十进制 0.01 在二进制浮点中天然精确作为理由。

高精度内部状态也能确定重放，前提是固定事件顺序、运算路径、舍入规则和算法版本。不同公式之间的浮点末位差异不等于同一路径重复执行不确定。每次更新都量化会丢失弱证据并制造不动点；连续模型结论也不能未经误差界就套到 101 状态系统。推荐的可塑性契约见第 10.9 节。

## 七、第六层：扩散激活

这是「类似神经的突触效果」在数学上的全部内容。它只有 20 行公式，
历史观测显示部分输入会被封顶抹平差异；这不能推导成“一半机制无效”，更不能替代对完整可达集合的检查。

### 7.1 算法：种子 → 一跳 → 两跳 → 聚合 → 截断

```text
① 历史基线种子：本轮 R ≥ 本轮最高R × 0.85 的卡（零值边界见7.8）
        能量 E = 该卡的 T

② 一跳：raw₁ = E × 边权 × 0.5
③ 两跳：raw₂ = E × 第一条边权 × 第二条边权 × 0.25

④ 聚合：同一目标被多条路径触达时，raw 累加
⑤ 护栏：目标自身的 R ≥ 0.06 × 1.0 才允许加分
⑥ 加分：boost = min(0.12, raw)，只加到 T 上
⑦ 截断：按 raw 降序 → 自身 T 降序 → 标识升序，取前 5
```

| 常量 | 值 | 含义 |
|---|---|---|
| 每跳能量乘数 | 0.5 | 每多一跳，能量乘一次 |
| 最大跳数 | 2 | 只走两跳 |
| 单卡加分上限 | 0.12 | 一张卡最多被推高多少 |
| 种子门槛比例 | 0.85 | 种子 = 本轮最高 R 的 85% |
| 最多影响张数 | 5 | 截断 |
| 护栏倍数 | 1.0 | 校验强制 ≥ 1 |

### 7.2 判据用相关分量，能量用总分

```text
种子判据：R ≥ 本轮最高R × 0.85
种子能量：E = 该卡的 T
```

**两个用途不同，用不同的量是刻意的**：

- **判据**问「这张卡够不够格把自己的激活撒出去」——这是**相关性**问题，
  必须用 $R$。
- **能量**问「它能撒多少」——这是**总量**问题，用 $T$。

**这个分工是修了一个真缺陷的结果。** 原来判据也用 $T$，而 $T$ 的离散度
被 0.48 的查询无关权重压平到 0.9059～0.9655，$0.85$ 落在其下
⇒ **所有卡都是种子 ⇒ 受益者恒为空 ⇒ 扩散在数学上恒为空**。

**【实测】** 修复前后，三种模式（关 / 只观察 / 生效）的总分**逐位相同**，
观察值 0 条。**这是「机制完整实现、单元测试全绿、配置齐备、生产零调用方」
之外的第二种静默失效：全部接线正确，但数学上恒为空。**

### 7.3 扩散为什么绝对不能改相关分量

```text
新 T = clip(旧 T + boost)
R 不变                        ← 关键
```

**因为绝对闸架在 $R$ 上。** 若扩散能改 $R$，一张本来不该进包的卡
就能靠「被邻居带出来」绕过绝对闸，而绝对闸正是 R2（专注当前位置）的唯一实现。

> **护栏不能和它要守的判据用同一个通道。**

这条规则有一个反例值得记：曾经为了「让扩散真的能改变成员」，
加过一条「被扩散推动的卡豁免相对闸」的补丁。它**已删除**——
因为相对闸在 $T$ 上，而扩散加分直接进 $T$，天然就能改变成员，
不需要豁免。**少一个未测分支比多一个「看起来更安全」的分支好。**

### 7.4 两跳贡献相同不等于跳数失效

**【推导】** 旧公式下，链 a—b—c 的边权均为 1、种子能量 0.5，b 原始加分 0.25、c 为 0.125；单卡上限 0.12 会把二者截成同一值。但 H=1 时 c 不可达，H=2 时 c 得到 0.12，跳数参数仍能改变成员。低权边两跳贡献 0.00125 是否影响排序，也取决于排序分差，而非仅由量级决定。

取代与蒸馏边的权重本来可为 1，因此不能由“话题相似度低于去重阈值”推出“所有真实图的边权永不到 1”，也不能推出“跨层次关联数学上只有一跳”。

### 7.5 对称性与访问规则

在等权三角形 a—b—c—a 上，种子 a、能量 0.5、封顶放到 1，枚举所有长度至多两跳的简单路径时，b 与 c 都得 0.25+0.125=0.375。若每种子每目标只记首次到达，则二者都得 0.25；这两种算法不能混称“多路径累加”。原稿一处给 b=0.25、c=0.375，另一处给 c=0.25 却解释为两路径相加，都不成立。

原稿报告环图有两种加分值、完全图只有一种，但没有完整列出种子位置、访问规则和权重，不能概括为“图形决定输出档数”。能证明的性质是：保持种子、权重、方向的图对称变换，应保持对应节点的输出；不能凭空破坏对称性。均匀图适合测试此不变量，真实语料用于判断任务收益。

### 7.6 四种聚合方式的真实边界

| 聚合 | 数值有界条件 | 对称图 | 主要代价 |
|---|---|---|---|
| 路径求和 | 原始值无统一上界，需独立预算 | 对称节点仍可能并列 | 路径条数重复放大证据 |
| 每目标取最大 | 输入贡献≤1时输出≤1 | 同样可能并列 | 丢弃较弱的其他来源 |
| 1−∏(1−贡献) | 每项在[0,1]时输出在[0,1] | 同样可能并列 | 类似概率并集的解释需要独立性，相关路径不能据此当独立事件 |
| 除以路径数 | 每项有界且路径集合有限明确定义 | 同样可能并列 | 可丢失来源数量信息；路径集合与环规则必须先固定 |

没有一种对称聚合能保证在完全对称输入上创造区分度；这不是四种方法分别“能否塌缩”的优劣项。推荐方案保留不同种子贡献，种子内去掉重复路径放大，并加全轮预算，见第 7.8 节。

### 7.7 影子模式：算出来没人看得见等于没算

扩散有三种模式：关 / 只观察 / 生效。

| 模式 | 改不改 $T$ | 产出什么 | 用途 |
|---|---|---|---|
| 关 | 否 | 无 | 基线 |
| 只观察 | **否** | 观察记录（谁被谁带出来） | 验证机制是否真的在起作用 |
| 生效 | 是 | 加分 + 观察记录 | 生产 |

**「只观察」模式的价值在于它让「扩散恒为空」这件事可见。**
它产出的是「因为想起了 A，所以想起 B」这样的观察值。
如果观察值恒为 0 条，说明机制恒为空——**而这个信号只能靠这个模式拿到**。

**【实测】** 修复种子判据之后：$b$ 从 0.4807 到 0.6007，$c$ 从 0.3295 到 0.4495，
种子 $a$ 不变；影子模式产出 3 条观察值而总分逐位相同。

**但「只观察」模式本身也踩过一个坑**：它照搬了生效模式的加分字段，
于是「影子模式下的加分」被算出来并展示了，而它**并没有真的加到总分上**。
观测值看着像事实，其实是一个假设。**影子的输出必须标明「这是如果生效会怎样」。**

---

### 7.8 推荐契约：最强路径、种子归一、全轮有界

**【设计决策·待验证】** 目标是消除重复路径放大、种子数放大和加分总量失控；不声称它已经优于基线。令 C 为已通过授权与存活检查、并按本轮内容域策略取出的有限候选，τ=0.06、ρ=0.85、护栏倍数 a≥1、最大跳数 H=2、跳折扣 γ=0.5、全轮预算 b=0.12、受益数上限 M=5。

$$E=\{v\in C:R_v\ge\tau\},\quad S=\{s\in E:R_s\ge\rho\max_{u\in E}R_u\},\quad V=\{v\in E\setminus S:R_v\ge a\tau\}.$$

E 为空时不取最大值，直接返回无扩散；S 为空、总种子能量为零或 V 为空时同样返回。种子均为并列最相关卡时，所有合格卡都可能是种子，V 为空是合法结果，不应用标识任意删种子来伪造收益。非种子受益区间必须满足 aτ≤Rᵥ<ρ max R；区间没有交集时，应报告“受益区间为空”。

对同一种子 s、同一目标 v，只保留长度 1～H 的最强可走路径：

$$L_{sv}=\max_{p:s\leadsto v,\ 1\le |p|\le H}\left(\gamma^{|p|-1}\prod_{e\in p}w_e\right),\qquad L_{sv}=0\ \text{（无路径）}.$$

边还必须携带源卡修订和关系依据，读取时验证当前修订仍支持该关系；仅端点存活与有权访问不足以证明旧边仍相关。依据失效或版本不匹配的边先排除并待重建。所有权重在 [0,1]；同方向的平行关系取最大有效权，避免同一事实因边类型多就重复计证。只在 C 的诱导图内传播，方向遵守关系契约；目标为种子时不加分。每跳从上一跳的冻结结果更新，不能把本轮最终加分再作为传播输入。

$$\alpha_s=\frac{T_s}{\sum_{u\in S}T_u},\qquad r_v=\sum_{s\in S}\alpha_s L_{sv}\in[0,1].$$

从 V 中按“r 降序 → 相关分量降序 → 未扩散总分降序 → 稳定标识升序”选最多 M 个正收益目标，记为 Q⊆V；再分配预算：

$$\Delta_v=\begin{cases}\displaystyle\frac{b\,r_v}{\max(1,\sum_{u\in Q}r_u)}&v\in Q\\0&\text{其他}\end{cases},\qquad T'_v=\min(1,T_v+\Delta_v),\qquad R'_v=R_v.$$

**【推导】** 0≤Δᵥ≤b，且 ΣᵥΔᵥ≤b，因此真实总分增量之和也不超过 b；单卡不会因多路径、多种子数或图密度增长而无限加分。重复同一条边不会改变结果。复制全部种子且保留成对相同的路径贡献时，加权平均不变；只复制某一个种子会改变权重，不能声称对任意重复都不敏感，重复卡应先在上游去重。全轮预算会使受益者互相竞争，这正是有限联想预算的代价。

**算例（全部推导）**：两个等能量种子，目标甲的路径强度分别为 0.6、0.2，目标乙为 0.4、0.4，则 r 皆为 0.4，Δ 皆为 0.048，总加分 0.096。若两个目标的 r 都为 1，则各得 0.06，总加分仍为 0.12。对单种子链且两边权均为 1，第一跳 L=1、第二跳 L=0.5；两目标并存时分别加 0.08、0.04，跳差不会被同一单卡封顶抹掉。

**计算界**：在固定 H 的诱导图上，逐种子、逐跳进行最大乘积松弛，时间 O(H·|S|·(|C|+|边|))、工作空间每种子 O(|C|)，另计构建投影、排序与归因输出。因 γw≤1，绕环不能增强路径，可用此松弛得到相同的有界最强路径值；不能仅凭“两跳”断言线性于节点数，稠密图的边数本身可为平方级。浮点归约按稳定种子序进行，并持久化算法版本。

**与召回衔接**：相对闸基准冻结为 E 中未扩散最高总分的 0.55 倍；扩散后重新排序，再做条数与长度预算。推荐方案先跑影子，对照相关性人工标签、同实体难负例、成员变化、时延和最终长度，达标后才可生效。0.12 在这里换成了全轮预算，旧上限扫描不构成新预算的标定。


## 八、第七层：遗忘

遗忘有两个动作：**降强度**（连续）与**归档**（离散）。两者都不删除任何东西。

### 8.1 强度必须按已结算区间衰减

**【设计决策·待验证】** 保存独立的强度结算时刻 t₀，不能用通用更新时间或最后访问时间代替；只有实际结算强度才推进此时钟。固定半衰期 h 时：

$$x(t)=x(t_0)\,2^{-\max(0,t-t_0)/h}.$$

若情绪或访问变化使半衰期在 t₁ 变为 h₂，应先按旧 h₁ 结算到 t₁，再计算新区间。分段形式为：

$$x(t_n)=x(t_0)\prod_{j=1}^{n}2^{-(t_j-t_{j-1})/h_j}.$$

同一参数下，不同分批间隔的乘积数学上等于一次结算；工程重放仍须固定事件顺序、浮点运算路径与舍入规则。时钟倒流不增加强度、不回拨结算时刻。重复提交同一结算操作不得再次衰减。

新鲜度与存储强度可以共享半衰期策略，但起点与用途不同：新鲜度参与排序，强度参与归档；当前扩散能量来自总分，不是直接来自强度。不能仅因强度趋近零就推导卡片的排序分也趋近零，其他分量仍可能贡献。

### 8.2 归档容量：活跃卡少于 20 张时永远为 0

$$\text{容量}=\Bigl\lfloor\ \lfloor\text{活跃卡数}\rfloor\times\mathrm{clip}(0.05)\ \Bigr\rfloor$$

活跃卡数本来是非负整数时，内层取整冗余；比例上限导致以下结果：

```text
活跃卡 = 19 张 ⇒ 19 × 0.05 = 0.95 ⇒ 取整 0 ⇒ 一张都不归档
活跃卡 = 39 张 ⇒ 39 × 0.05 = 1.95 ⇒ 取整 1
活跃卡 = 20 张 ⇒ 20 × 0.05 = 1.00 ⇒ 取整 1
```

**【推导】** 阈值在 20 张：**活跃卡少于 20 张时，归档容量恒为 0。**

**这是有意的，不是缺陷。** 小库上按比例归档会让库被清空——
一个只有 10 张卡的系统，每夜归档 0.5 张（取整 1 张），十夜之后就空了。
**一个会把自己清空的记忆系统，用户用两天就会卸载它。**

**这条设计有一个必须承认的代价**：小库上自动归档这一动作不会发生，
强度会一直降但卡片永不归档。于是强度在 0 附近的卡会长期堆着，
只是排不上来。**这是用「库不变小」换「库不被清空」。**

### 8.3 归档排序键：强度 → 创建时刻 → 标识

```text
候选按 强度升序 → 创建时刻升序 → 标识升序
取前「容量」个
```

**三级排序键的作用是让结果完全确定**：强度相同的卡按创建时刻定序，
创建时刻也相同的（同一次写入的多张卡）按标识定序。

**为什么第二键是「创建时刻升序」而不是降序**：同强度时先归档**更旧**的。
这与直觉一致——两样一样弱的东西，留新的。但**这条选择没有标定**，
它只是「更旧的东西更该被忘」这个常识。**【判断】**

### 8.4 四类永不归档

| 类别 | 理由 |
|---|---|
| 感受 | 「细节会忘、感受要留」的直接实现 |
| 承诺 | 承诺是必须履行的，忘了就是违约 |
| 概念 | 概念是长期有效的知识，不随时间失效 |
| 经验 | 经验是可复用的判断，比单次事件更耐久 |

**这四类是从需求里直接推出来的，不是从数据分布里算出来的。**
它们的共同点是：**「旧」不构成遗忘它们的理由。**

**但这里有一个必须说清的边界**：这四类卡的**强度仍然会衰减**，
只是不参与归档。于是会出现「强度 0.001 的感受卡」——
它在归档上永远不被选中，但打分还包含语义、重要性、新鲜度和置信度，不能由强度低直接推出“几乎拿不到分”。

这是「留」与「可见」的分离。**归档不是遗忘的唯一形态，不可见也是遗忘。**
需求里的「感受要留」只保证了前者，后者没人保证。

## 九、第八层：巩固

巩固是夜整理的七个步骤。**顺序是约束，不是风格**——三条顺序约束每一条
都对应一次真实的「机制恒为空」。

### 9.1 去重合并

```text
判据：杰卡德相似度 ≥ 0.86
分组：候选连通组件 → 全对达标核验，未决者保留
代表：组内最早创建的那张（同龄按标识升序）
```

**0.86 是很严的阈值**，它的含义是「几乎逐字相同」，不是「说的是一件事」。
理由：合并是**不可逆的破坏性动作**（视图上两张变一张），
**宁可漏合并，不要错合并**——错合并会把两件不同的事永久粘成一件。

**相似度达标关系不具有传递性。** 取 A={1,…,10}、B={1,…,11}、C={2,…,11}，则 J(A,B)=J(B,C)=10/11≈0.9091，J(A,C)=9/11≈0.8182；前两对达到 0.86，第三对未达到。原稿的 0.91、0.88、0.62 甚至违反杰卡德距离的三角约束，不能作为可实现反例。

**【设计决策·待验证】** 并查集仅生成候选连通组件，实际合并组必须所有卡对相似度均≥0.86。按稳定标识定序分组，加入新卡前逐对核验，比较预算耗尽则保留未决卡并延后，不把“可通过一串相似边连通”当作同一事实。来源、时间、极性或修正状态不同仍可能禁止合并，文本相似度不是事实等价的证明。



**组内相似度取最小值，不取平均也不取最大**：它要回答「这一组有多确定是重复的」，
只要有一对不够像，整组的确定性就是那一对。

**合并时「取最大」与「求和」的区分是刻意的**：

| 字段 | 取法 | 为什么 |
|---|---|---|
| 强度 / 显著性 / 情绪 / 置信度 | **取最大** | 它们是状态量，代表「这组里最强的那次经历」 |
| 访问计数 | **求和** | 它是累计量，代表「这件事总共被想起过多少次」 |

**取最小是错的**：一张强卡和一张弱卡合并后变弱，等于「因为重复，所以更容易被忘掉」——
方向反了。

### 9.2 摘要预算：压缩必须是算术上的必然

$$\text{预算}=\min\bigl(\text{层级上限},\ \lfloor\text{来源总字符}\times\text{压缩比}\rfloor\bigr)$$

| 层级 | 字符上限 | 压缩比 |
|---|---|---|
| 日 | 180 | 0.5 |
| 周 | 140 | 0.5 |
| 月 | 110 | 0.5 |

**两道闸缺一不可**：

- **算术闸**保证摘要永远显著短于来源（预算同时受两个上限约束，取小者）。
- **配置闸**保证「假压缩」配不出来：压缩比必须 < 1、层级必须越高越短、
  下级展示数量门槛为正整数；配置只校验正层级上限与 0<压缩比<1，预算依赖运行时来源，过小就在运行时跳过并报告。

**为什么配置闸比代码自律更硬**：

| 做法 | 假压缩能不能被配出来 | 谁来发现 |
|---|---|---|
| 只在实现里自律 | 能（改一行就配出来了） | 靠人读代码，或靠测试断言 |
| 配置层拒绝 | **不能**（加载期就失败） | 加载期自己 |

> **配置层的拒绝把「不可能」写进了可配置空间的边界，而不是写进某一段代码的行为。
> 代码可以改，边界不会自己松掉。**

**预算不足就跳过。** 来源总字符 N≥2、压缩比 r∈(0,1)、层级上限为正整数时，B=min(上限,⌊Nr⌋) 满足 B/N≤r；B 小于一个完整语义单元所需长度就跳过，不再强制保底 1。否则 N=2、r=0.1 会被保底改成 B=1、实际比值 0.5，违反比例。N≤1 同样跳过。公式只证明长度，摘要事实支持与关键信息保留须另验。



**本模板选择输出统计量与关键词，避免机械拼接；这是取舍，不是压缩成立的唯一形式。** 抽取式摘要也能选择完整原句，真正保证长度压缩的是最终预算。无论抽取式还是生成式，都要验证来源支持、关键事实保留和可追溯性，不能只凭“不是原文”证明它更好。

**【推导】** 一天 12 张卡、每张约 30 字，来源约 360 字，
日摘要预算 $=\min(180,\ 180)=180$，压缩比 0.5。若来源只有 100 字，
预算 $=50$，压缩比仍是 0.5。**预算与来源之比不超过目标比例，触及绝对上限后继续下降，实际输出也可更短。**

### 9.3 感受蒸馏

```text
① 筛候选：情绪强度 ≥ 0.28，且不是蒸馏自己的产物
② 分桶：按主题词项聚成桶
③ 达标：桶内张数 ≥ 2
④ 渲染：取情绪最强的 3 个桶，各渲染一句
```

**候选门槛 0.28 与写入侧的情绪通道阈值是同一个数，这不是巧合。**
它们回答同一个问题——「这一轮够不够算有感受」。两处取不同的数，
会在「能进来」和「能被蒸馏」之间留出一条**谁都不负责的缝隙**。

**「≥ 2 次」是「反复」的下限**：一次是经历，两次是模式。
门槛取 2 而不取 3，因为一夜里达到 3 次同主题的概率不高，
门槛太高会让蒸馏在稀疏使用下恒为零——**那是另一种形态的机制恒空**。

**它明确做不到什么，必须写进产出文本**：

```text
做不到：不知道「被领导夸」和「被领导骂」情绪相反（只测浓度不测极性）
        不做因果推断（共现是相关性，不是因果）
        不随时间改变对同一件事的看法
做得到：留下「哪些处境反复牵动过我」这一层
        让细节衰减后仍有东西可回忆
```

**所以产出文本刻意写成「X 这件事反复牵动我的情绪」，
绝不写「我对 X 感到难过」。** 后者是它给不出的判断——
**写一个判断不出的情绪名，就是让文本撒谎。**

### 9.4 蒸馏曾经恒为 0：两个坑

**坑一：主题词的粒度。** 归一化把所有标点替换成空格，于是「按空格切分」
得到的是**整段长句**：

```text
归一化：我今天特别开心 这个项目终于跑通了 感觉超级爽
切出来：["我今天特别开心", "这个项目终于跑通了", "感觉超级爽"]
```

两张不同的情绪卡之间几乎不可能共享一个整段长句 ⇒ **桶数恒为 0**。
正确粒度是二元组：中文按相邻两字切，英文按整词切，再过停用词表。

**坑二：程度副词碎片成了主题词。** 停用词表没收「有点 / 有些 / 非常 / 感觉 / 觉得」
这类程度副词与感知动词，二元组分词把它们当独立词项漏出来。
它们区分度为零、却高频出现在情绪句里，于是「有点烦」和「有点慌」
被聚成同一件事，产出「『有点』这件事反复牵动我的情绪」。

**为什么第二个坑比第一个更危险**：修好坑一之后，产出**非零且格式完全正确**，
只有读文本才能发现它在说假话。

> **「产出变多」和「产出变对」是两件事。** 蒸馏产出数非零
> 只证明链路通了，不证明内容对。

### 9.5 夜整理的数据依赖与日账本

推荐基线为：固定输入快照与水位 → 区间衰减 → 蒸馏 → 全对去重 → 日账本与周/月视图 → 归档 → 失效派生边重建 → 索引发布。摘要消费固定历史快照，不因本批归档而漏掉来源；物理执行能否并行，取决于读取哪一版输入，不能据此声称存在唯一合法顺序。

**【设计决策·待验证】** 每个自然日都维护来源身份与计数的日分区账本，即使当天未达展示日摘要的门槛也存在。周与月分别由对应日期范围内的日账本聚合，不让周摘要再进入月汇总，以免自然周跨月重复计数。相同来源身份在同一统计口径只计一次；更正或删除会替换账本修订并使两种上级视图失效。

压缩展示文本与可加总统计量必须分离。只汇总可见日文本会丢掉单条事件日；只凭关键词文本也不能恢复准确计数。完整溯源成员集合可按预算外存保存，但聚合时的去重身份不能被截断。

## 十、第九层：可塑性（全篇数学最重的一节）

这一层是「突触效果」的完整形态：**边被用一次就变强，不用就变弱**。
它的公式只有三行，但它**当前没有接线**；默认粗量化方案有明确问题，但有限参数扫描不能证明所有可塑性模型数学上不可行。

本节是全篇最长的部分，因为它记录了**四次推导修正**——其中三次是真正的推导错误，
另一次（档数上界）**只是漏了取整，却被我判成了「被证伪」**，那一次判错本身
比原推导更值得记。
把这些留下来不是为了自我批评，是因为**每一次修正都改变了问题的性质**。

### 10.1 两个算子

$$R(w)=q\bigl(\min(1,\ w+\delta)\bigr)$$

$$D(w)=\begin{cases}0 & w\le 0\\ q(w\cdot f) & \text{若}\ q(w\cdot f)<w\\ q\bigl(\max(0,\ w-0.01)\bigr) & \text{否则（地板步长）}\end{cases}$$

$$q(x)=\frac{\mathrm{round}(100x)}{100},\qquad \delta=0.01,\qquad f=0.98$$

**「地板步长」是做什么的**：它保证「衰减一定降一格」。
没有它，$q(w\cdot f)$ 在小权重上会圆整回原值，于是**衰减停摆**。

**【实测】** 停摆的规模：$0.02\times w$ 小于半格 $0.005$ 时圆整回原值，
于是 $w\in[0.01,0.25]$ 共 **25 个权重全是不动点**。机制在数学上停摆，
不报错、不崩溃、日志正常。

**所以地板步长不是可选优化，它是修一个真缺陷的补丁。** 这一点在 10.5 会变得关键。

### 10.2 核心事实：强化增量与地板步长精确相等

$$\delta=0.01\quad\text{与}\quad\text{地板步长}=0.01\quad\text{精确相等}$$

于是「一次共激活」的净变化是：

```text
w ← R(w) = q(w + 0.01)
w ← D(w) = q(w × 0.98)，若没变小则 w − 0.01
```

**【实测】对 101 个格点逐一迭代一夜**：

| $\delta$ | $f$ | 上升 | 不变 | 下降 |
|---|---|---|---|---|
| 0.01 | 0.98 | **0** | 75 | 26 |
| 0.02 | 0.98 | 74 | 25 | 2 |
| 0.01 | 0.95 | **0** | 29 | 72 |
| 0.01 | 0.914 | **0** | 17 | 84 |

**默认参数下，「这张边被用过一次」是零变化，且 101 个格点里 0 个上升。**
「不变」区间是 $[0,\ 0.74]$，连续 75 个格点。

**【推导】** 明确格号整数 k=100w、正半值向上舍入，设强化后的格号 j=min(100,k+1)。衰减后格号为：

$$d=\min\left(\left\lfloor0.98j+0.5\right\rfloor,\ \max(0,j-1)\right).$$

当 k≤74 时 j≤75，有 ⌊0.98j+0.5⌋≥j−1，故 d=k；当 75≤k≤99 时 j≥76，舍入结果≤j−2，故 d<k；k=100 时强化已封顶、衰减得到 98。因此恰有 75 个不变、26 个下降、0 个上升。这是固定舍入规则下的格点推导，不是“连续误差累计了 0.25”。

一次使用与一次衰减抵消，说明该夜没有净增长；不说明“使用与未用不可区分”。未使用仍执行衰减，例如 w=0.10 不用会降到 0.09，用一次会维持 0.10。维持与下降已经是不同信号；是否符合产品期望，要比较这两条轨迹。


### 10.3 第二层：档数（分辨率）

即使不管抵消问题，还有一个更根本的限制：**能分出多少档。**

**「档数」这个词有歧义，必须先定义再报数。**

```text
定义 A：固定初值 w0 = 0.5，扫「一夜里共激活 n 次」，n = 1..30，
        各自迭代 2000 夜到稳态，数能到达多少个不同终值。
        → 问的是「用 1 次 / 2 次 / … / 30 次，最终强度分不分得开」

定义 B：固定 n = 1，扫初值 w0 = 0.01..1.00，各自迭代到稳态，数终值个数。
        → 问的是「起点不同，最终强度分不分得开」
```

| 定义 | $f=0.98$ | $f=0.95$ | $f=0.914$ |
|---|---|---|---|
| **A**（本篇其余各节一律用这个） | **3** | **6** | **10** |
| B | 74 | 28 | 16 |

**两个定义差 25 倍，所以报数必须注明扫的是哪个维度。**

**为什么定义 A 才是与「可塑性有没有用」相关的量**：可塑性要区分的是
「这条边被用过几次」，不是「这条边从哪个权重起步」。
定义 B 数字更大，但它衡量的是另一件事——**拿它来反驳「分辨率不足」会得出相反结论**。

**【实测】档数随 $f$ 的变化（定义 A）**：

| $f$ | 实测档数 |
|---|---|
| 0.995 | 2 |
| 0.99 | 2 |
| 0.98 | 3 |
| 0.95 | 6 |
| 0.93 | 8 |
| 0.914 | 10 |
| 0.914 附近已报告扫描点 | 10；不能外推到所有更小 f |

**换算成半衰期**（半衰期 $=\ln 0.5/\ln f$ 夜）：

| $f$ | 半衰期 | 档数 |
|---|---|---|
| 0.99 | 69.0 夜 | 2 |
| 0.98 | 34.3 夜 | 3 |
| 0.97 | 22.8 夜 | 4 |
| 0.95 | 13.5 夜 | 6 |
| 0.93 | 9.6 夜 | 8 |
| **0.914** | **7.7 夜** | **10** |

这些反查只在已扫描的参数家族与范围内成立，不是所有 f 的必要充分条件。例如 f=0 时每次衰减后都为零，档数反而只有 1，足以否定“所有 f≤0.914 都有 10 档”。

> **这是固定粗格家族的局部扫描限制，不能推成可塑性不可行。** 连续因子的半衰期也不等于包含量化与地板扣格后实际轨迹的半衰期。

这证明已测默认机制的分辨率有限，不能证明更高精度状态、不同输入语义或连续时间模型同样失败。

### 10.4 第一次推导错误：档数上界漏了取整

我先推出三个界：

$$\Delta w^*=\frac{\delta f}{1-f}\quad\text{（相邻档中心的间距）}$$

$$\delta>\frac{0.01}{f}\quad\text{（要跨过量化格）}$$

$$\delta<\frac{1-f}{Nf}\quad\text{（要不撞顶）}$$

两式联立得：

$$N<\frac{1-f}{0.01}$$

**然后我声称「这个界经过全参数空间实测验证」。它是错的。**

先把两个量分开，因为下面整张表都在这件事上翻过车。记 $c=\left\lceil(1-f)/\delta\right\rceil$：

- **带数** $N_{\text{带}}$：不动点带的条数，夹逼 $c\le N_{\text{带}}\le c+1$，**带宽 1**。
- **档数** $N_{\text{档}}$：从初值 $0.5$ 扫共激活次数得到的**可达终值个数**，
  夹逼 $c-1\le N_{\text{档}}\le c+1$，**带宽 2**。

| $f$ | 半衰期 | 实测档数 $N_{\text{档}}$ | 档数夹逼 $[c-1,\,c+1]$ | 带数实界 $c$ | 实测带数 $N_{\text{带}}$ | 带数夹逼 $[c,\,c+1]$ |
|---|---|---|---|---|---|---|
| 0.99 | 69.0 夜 | **2** | $[0,\,2]$ | 1 | 2 | $[1,\,2]$ 上端 |
| 0.98 | 34.3 夜 | **3** | $[1,\,3]$ | 2 | 3 | $[2,\,3]$ 上端 |
| 0.97 | 22.8 夜 | 4 | $[2,\,4]$ | 3 | 4 | $[3,\,4]$ 上端 |
| 0.95 | 13.5 夜 | 6 | $[4,\,6]$ | 5 | 6 | $[5,\,6]$ 上端 |
| 0.93 | 9.6 夜 | **8** | $[6,\,8]$ | 7 | 8 | $[7,\,8]$ 上端 |
| 0.914 | 7.7 夜 | 10 | $[8,\,10]$ | 9 | 10 | $[9,\,10]$ 上端 |
| *0.985* | *45.9 夜* | *2* | *$[1,\,3]$* | *2* | *2* | *$[2,\,3]$ **下端*** |

**最后一行是故意加的反例**：上面六行的带数全部取上端 $c+1$，看起来像
$N=c+1$ 成立；换个 $f$ 立刻掉到下端。**这不是巧合，是抽样偏差**：

| 扫法 | 区间 | 样本 | 上端 | 居中 | 下端 | 出界 |
|---|---|---|---|---|---|---|
| 带数 $N_{\text{带}}$ | $f\in[0.850,0.999]$ | 150 点 | 75 | — | 75 | **0** |
| 档数 $N_{\text{档}}$ | $f\in[0.850,0.999]$ | 150 点 | 69 | 73 | 8 | **0** |

扩到 $f\in[0.501,0.999]$ 共 499 点：带数 **499/499** 落在 $[c,c+1]$
（上端 154、下端 345），档数 **499/499** 落在 $[c-1,c+1]$
（上端 104、居中 250、下端 145）；且 **$N_{\text{档}}\le N_{\text{带}}$ 恒成立**
（304 点相等、195 点差 1，差从不大于 1）。

所以正确结论是**两条带主语的夹逼**，不是一个等式，也不是一条夹逼管两个量：

$$c\le N_{\text{带}}\le c+1\qquad c-1\le N_{\text{档}}\le c+1$$

写成 $N=c+1$ 只在带数上成立 154/499、在档数上成立 **104/499**，
其余分别取下端或居中。**没有单一闭式等式能同时覆盖两端。**

**这里我判错过三次，前两次方向相反，第三次是主语错**：
第一次拿严格不等式 $N<(1-f)/0.01$ 去判一个整数关系，必然全部不成立，
而我把「全不成立」读成了「界被证伪」；第二次改写成等式、声称 499 点全中，
是把带宽 1 的区间当成了等式；**第三次把带宽 1 的那条（带数）说成档数的界**
——154/499 这个数是真的，只是它数的不是档数。
**真数字配上错主语，比编一个数字更难被推翻**，因为核对的人会去重跑那个数、
确认它成立，然后跳过主语。

**崩坏区在哪里**：$f\le 0.5$ 时公式与实测才真正脱节（$f=0.5$ 算得 50、实测 14），
那时半衰期不足一夜，量化把权重抹平了。产品参数 $f\ge 0.95$ 离那里很远。

**诚实结论**：量级是对的，问题在「3 档太少」，不在「算不出来」；
而**要 10 档需 $f\le 0.914$（半衰期 7.7 夜）这条是直接实测的，不依赖上面任何公式**。

**根本原因**：连续域推导被当成了离散系统的结论。
$q(x)=\mathrm{round}(100x)/100$ 只有 101 个状态，**必须用状态机分析**。
在连续域里「相邻档中心差 $\Delta w^*$」是有意义的；在离散域里，
档的存在取决于**哪几个格点自己是周期点**，而这是一个纯组合问题。

### 10.5 同一 $n$ 有多个吸引子：稳态不是函数

**【实测】** $\delta=0.01,\ f=0.98$：

| 一夜共激活次数 $n$ | 迭代后落到的不同终值数 |
|---|---|
| 1 | **75**（其中 74 个是自身不动点） |
| 2 | 25 |
| 3 | **1**（全部收敛到 0.98） |

**注意这张表数的是定义 B**（固定 $n$、扫 $w_0$）。所以它和 10.3 的「3 档」不矛盾——
那张表固定 $w_0=0.5$、扫 $n$。**同一个系统，换一个维度扫，数字差 25 倍。**

> 只写 w*(n) 省略了初值与吸引域，因此不足以唯一决定终值；固定 n、初值与规则后的轨迹仍是确定的。有限状态系统也可以严格分析不动点和周期，不能把“离散”当作教科书分析一概无效的理由。

**另外两个必须记录的性质**：

| 性质 | 实测 | 意义 |
|---|---|---|
| 单调性 | 101 个格点，**0 违反** | 「用得多不会变弱」成立 |
| 最大环长 | **1** | 系统无振荡，只有不动点 |

**所以「单调性」这条需求是满足的，「分辨力」这条不满足。**
10.3 的档数就是分辨力的精确度量。

**还有一层：档数依赖初值。** $f=0.98$ 时 $w_0\in\{0.1,0.3,0.5,0.8\}$ 都是 3 档，
**$w_0=1.0$ 只有 2 档**——因为撞顶之后没有上升空间。

### 10.6 第三层：饱和式也不是出路

我试过换成指数逼近：

$$w\leftarrow w+\delta(\text{上限}-w)$$

**【实测】**：

| $f$ | $\delta$ 从 0.02 扫到 0.30 的档数 |
|---|---|
| 0.95 | **这五点上是 5**（0.30 时 4） |
| 0.98 | 这五点上是 2～3 |

**但「恒为 5」这个总结是错的**——那五个点是抽样。把 $\delta$ 从 0.01 扫到 0.30
全 30 个格点：

| $f$ | 30 个格点的档数取值集合 | 极差 | 相邻下降处 | 分布 |
|---|---|---|---|---|
| 0.95 | $\{2,4,5,6\}$ | **4** | 4 | 5 档 17 点、6 档 11 点、2 档 1 点、4 档 1 点 |
| 0.98 | $\{1,2,3\}$ | 2 | 0 | 3 档 28 点、1 档 1 点、2 档 1 点 |

**它对 $\delta$ 是敏感的，只是非单调**（$f=0.95$ 有 4 处相邻下降）。
所以「对 $\delta$ 完全不敏感」这句话不成立。

真正站得住的结论要换一个说法：把每个 $f$ 下 $\delta$ 全扫一遍取**最好**档数，
饱和式相对加性在 $f\in[0.850,0.999]$ 的 150 个点上
**85 点持平、7 点高 1、58 点更低**——**它没有系统性地抬高上限**；
在 $f=0.98$ 上两者最好都只有 3 档。

**所以「换公式没换掉那个真正的约束」这个结论仍然成立，但证据不是「恒为 5」。**
这是一次典型的「表格数字全对、旁边那句总结写错」：五个采样点恰好落在 5 上，
就把它写成了「恒定」。**采样点少的时候只能报「这五个点的值」，不能报「恒定」。**

### 10.7 卡在哪：两条需求互相排斥

```text
「较多终值档数」⇒ 已扫描家族偏向较小 δ（不证明0.01普遍唯一）
「一次使用有效」⇒ 需要 δ > 地板步长
```

**在已测粗格参数家族中存在取舍，而地板步长来自特定补丁**——它是修「衰减停摆」的补丁（10.1）。

**【实测】** $\delta=0.02$ 抵消消失（74 个上升），但档数立刻从 3 降到 2。

**所以「δ 取多少」不是一个标定问题。真正要解耦的是 δ 与地板步长。**
这是 10 的 OP-07 的题面，也是「不修比修错好」的一处应用。

### 10.8 指数移动平均：周期轨道而非常数稳态

令 wₜ=f wₜ₋₁+(1−f)uₜ，0<f<1。常数输入 u 时唯一不动点为 u；周期脉冲输入一般收敛到周期轨道。若每 K 夜出现一次幅度 A 的脉冲，则：

$$w_{\max}=\frac{(1-f)A}{1-f^K},\qquad w_{\min}=f^{K-1}w_{\max},\qquad\overline{w}=A/K.$$

**【推导】** f=0.98、K=30 时，A=0.1 的峰值约 0.004400、均值 0.003333；A=1 的峰值约 0.04400、均值 0.03333。旧表实际用了 A=0.1，不能同时说 u 是“用了=1”的二元指示。

“每月一次在任意 f 下必被 0.05 剪掉”不成立：A=1、f=0.5 时峰值接近 0.5。二元使用的均值超过 0.05 只要求长期每周平均超过 0.35 次，不是 4 次；是否某夜剪枝还取决于谷值、检查时刻与宽限规则。

频率与重要性仍应分开。这个模型能估计近期频率，却不能保证罕见的重要偏好或承诺存续；内容保护与使用频率必须承担不同职责。不能用这个语义局限证明指数移动平均在数值上不可实现。

### 10.9 推荐契约：高精度证据与固定输出边界

**【设计决策·待验证】** 保留内部高精度证据，按显式事件时刻进行连续时间衰减，只在决策输出边界量化；不要每个无事件的夜晚强制扣一格。稳定的内容关联证据与暂时的使用证据分离，前者随内容修订重建，后者仅由明确、可审计且按使用事件身份去重的确认驱动。无合法确认信号时，使用通道保持关闭，不拿召回次数代替使用次数。

同一路径、同事件序列可以确定重放。逐次迭代得 0.38914008079019、闭式计算得 0.38914008079019013，只证明浮点加乘不满足实数等式，不能证明同一算法跨次不确定。应固定计算路径、事件顺序、运行精度、舍入和算法版本；若声明跨运行时逐位一致，还需固定数值实现或以整数刻度和明确误差界定义。惰性衰减是可选实现方式，不是删除量化的唯一合法搭档。

高精度仍不能补出缺失的使用信号，也不保证新模型质量更好；需要比较单次使用与未使用的轨迹、稀疏使用的周期峰谷、重复确认、漏夜重放和归因闭环。

### 10.10 更深一层：这套系统已经有一个使用频次信号

这是本节最重要的一段，因为它改变了问题的解法方向。

**打分里已经有一个访问计数项**（见 3.2）：

$$i\ \text{含}\ 0.20\cdot\min\bigl(1,\ \ln(1+k)/\ln 13\bigr)$$

**【实测】** 它的力度：

| 变化 | 总分变化 |
|---|---|
| 访问计数 $0\to12$ | 0.036 |
| 显著性 $0\to1$ | 0.099（**2.75 倍**） |

**并且它在 12 次就饱和**（12 与 50 逐位相同）。

**这三件事合起来说明**：

1. 卡片级的使用频次机制**已经存在且已接线**。
2. 它的力度只有静态重要性的 $1/2.75$。
3. 它在 12 次饱和，之后不再区分。

**⇒ 卡片级的频次通道与边级的可塑性机制同生同死**：两者都依赖
「这条记忆真的被用了」这个信号，而那个信号当前的唯一入口**零调用方**。

> **所以正确动作是「先修入口，不要加机制」。** 在一个只有 $1/2.75$ 力度、
> 且 12 次就饱和的通道上，再叠一个边级的频次机制，
> 得到的仍然是一个弱通道——**而且它会让「我已经加了可塑性」成为不加频次入口的理由。**

### 10.11 五条可带走的结论

| # | 结论 | 依据 |
|---|---|---|
| 1 | $\delta=0.01$ 与地板步长相等 ⇒ 一次使用零变化 | 实测 75/101 格点不变，0 上升 |
| 2 | 档数受限于 $f$，10 档需半衰期 7.7 夜 | 实测定义 A 表 |
| 3 | 档数依赖扫法，两个定义差 25 倍 | 实测 3 vs 74 |
| 4 | 已测粗量化饱和方案未解决分辨率；指数移动平均估计频率 | 前者是局部扫描，后者是模型语义，不能合并为数学不可能 |
| 5 | 频次信号已存在但只有 1/2.75 力度 | 实测 0.036 vs 0.099 |

**第 1、2 条是已定义参数家族的可验证限制，不能外推为所有模型不可行；第 5 条是信号可得性约束。两类问题的解法不同**（见 10 的横向分类）。

## 十一、第十层：时间数学

时间数学看起来最琐碎，但它有两处**几乎所有人第一次都会写错**的地方。

### 11.1 到期推进：为什么必须推进

一条每日提醒响过之后，必须把到期时刻推进到下一次。否则：

```text
第一天 09:00 提醒响过，到期时刻仍是 09:00
第二天 09:00，到期查询返回同一个到期时刻
        → 被「这条已经提醒过」的过滤掉
        → 第二天永远不响
        → 每日提醒在响过一次之后永久静默
```

**这是「到点无需用户输入自行接力」在重复场景下的真实形态**，
也是这条需求最容易被漏掉的一半：**单次提醒很容易测对，
重复提醒的失败方式是「第二次之后全部静默」，而第一次是成功的。**

### 11.2 五种重复方式

| 重复方式 | 推进规则 |
|---|---|
| 一次性（或缺省） | 响过即结束，没有下一次 |
| 每日 | 按本地自然日 + 1 天，保留原钟点 |
| 每周 | 按本地自然日 + 7 天，保留原钟点 |
| 定时表达式 | 重新解析表达式，从当前时刻起求下一次 |
| 表达式无法解析 | 没有下一次（不抛错） |

**为什么按本地自然日推进，而不是加固定的 86 400 000 毫秒**：

夏令时切换日一天可能是 **23 或 25 小时**。加固定毫秒数会让
「每天早上九点」在切换后变成八点或十点，**且此后永久偏移**——
因为偏移量不会自己消失，它会一直累积。

**为什么推进用循环而不是单次判断**：宿主可能停摆数天，重新上线时
到期时刻已经落后好几轮。单次判断只推进一天，于是接下来几天会**连续补发**
同一批提醒。循环一次跳到「严格晚于当前时刻」的下一次，只提醒一次。

**循环必须有上限**（默认 400 轮）：防止时钟异常（例如当前时刻被设成 1970 年）
时死循环。超过上限返回「没有下一次」，当作放弃。

### 11.3 cron 四条语义

| 语义 | 规则 | 为什么容易错 |
|---|---|---|
| 日与周同时受限 | **或**关系（任一匹配即命中） | 与直觉相反：多数人以为是「与」 |
| 周字段的 0 与 7 | **都是周日** | 两个值同义，漏一个就少一天 |
| `a/n` 形式 | 从 a 起、到最大值、步长 n | 不是「每 n 个单位」 |
| 搜索窗口 | 366 天内找不到就返回「没有下一次」 | 不是抛错 |

**「日与周同时受限取或」是标准语义，但几乎所有人第一次都会写错。**
写成「与」的话，`0 9 1 * 1`（每月 1 号**且**周一）会变成一个几乎永不触发的
表达式，而它的本意是「每月 1 号**或**每周一」。

**为什么搜索窗口是 366 天**：最稀疏的合法表达式是「2 月 29 日」（闰年才有），
间隔最长 8 年。但 8 年的窗口会让一次解析耗时不可控。366 天覆盖绝大多数真实用法，
超出的返回「没有下一次」——**宁可承认解析不出来，也不要卡住。**

**窗口不够与参数错位是两件事**：曾经把「没说钟点时按几点算」误当成
「向后找多少天」传进来，于是 `0 9 29 2 *` 只找 9 天就放弃，
用户看到「解析不出来」，而真正的原因是搜索窗口被另一个参数顶掉了。

> **参数含义错位不会报错，只会让功能在一个看似无关的场景里失效。**

### 11.4 自然日聚合

日摘要按**本地自然日**分组，不是按「距今 24 小时」。

| 做法 | 后果 |
|---|---|
| 按自然日 | 「今天」从本地 00:00 到 23:59:59，符合直觉 |
| 按 24 小时滚动 | 每天的分界线随运行时刻漂移，摘要范围不可复现 |

**这条选择与确定性直接相关**：滚动窗口的边界依赖「什么时候跑夜整理」，
而那是外部输入；自然日边界只依赖时区与日期。**前者会让同一份日志
在不同运行时刻产出不同摘要。**

### 11.5 时间数学的三条边界

| # | 边界 | 说明 |
|---|---|---|
| 1 | 时区必须显式传入 | 不允许读系统本地时区，否则同一份数据在不同机器上算出不同结果 |
| 2 | 找不到下一次不抛错 | 返回「没有」是一个合法结果，不是异常 |
| 3 | 所有推进都有上限 | 循环上限 400、搜索窗口 366 天，都是防死循环 |

**第 1 条是全篇唯一一处「环境依赖」的显式排除。** 它与「核心层零 IO」是同一个原则：
纯函数不能读环境，环境必须作为参数进来。**读系统时区会让重放不确定**，
而重放不确定意味着**日志不再是真相源**。

## 十二、常量总表

这一章是**查表用**的。五列分别是：名称、默认值、含义、标定依据、是否已验证。

**「标定依据」这一栏其实装了两类东西，读的时候要分清**：

| 栏里写的是 | 说明 | 典型措辞 |
|---|---|---|
| **为什么取这个值** | 有理由，但理由无法验算 | 「语义应是最大单项」「两周是常识刻度」 |
| **实测发现了什么** | 有观测值，但**它证明的往往不是「这个值最优」** | 「固定扫描中只有3档」「给定输入的12与50结果逐位相同」 |

「半衰期34.3夜、只有3档」是在报告一个受限模型的现象，不能自动变成默认参数的背书。
理由说明选择动机，观测说明发生过什么，效果结论还需要独立对照；不得依靠行数比例或列名暗示三者等价。

**「是否已验证」这一列的读法**：

| 标记 | 含义 |
|---|---|
| **实测** | 历史材料报告过探针观测；是否充分标定、是否可复现须另查证据 |
| **推导** | 由其他常量或需求推出，没有独立标定 |

## 十三、本篇的诚实边界

这一章列出**这篇文档本身做不到的事**。它的目的是让读者知道
「读完之后你仍然不能判断什么」，而不是给一个自信的收尾。

### 13.1 标【实测】的数字，你无法复核

这是本篇最大的弱点。**「实测」这两个字意味着「我跑过探针」，
而不意味着「你也能跑出这个数」。** 你只能做两件事：

1. **检查它与周围公式是否自洽**——比如「访问计数 $0\to12$ 使总分变 0.036」
   应该恰好等于 $0.18\times0.20$。若不等，那这个数就错了。
2. **检查它被用在哪里**——一个实测值如果被用在它没测过的场景里，
   那它在那里的身份其实是【判断】。

**本篇历史上就有过「实测」标签用错的地方**：10.4 那张档数上界表，
每一行的实测值都是真的，**但紧挨着它的结论「这个界经过全参数空间验证」是假的**。
表格正确、结论错误，而结论比表格更容易被引用。

### 13.2 推导值可能看起来比实测值更可信

这是本篇最需要警惕的一处认知陷阱。

$$\Delta w^*=\frac{\delta f}{1-f}$$

这个式子有推导、有符号、有量纲，读起来比「实测 3 档」可信得多。
**而它是错的**——它假设了连续域，而系统是 101 个状态的离散机。

> **公式的形态不构成它的可信度。** 一个带分式的推导和一个整数观测值，
> 前者并不更可信；它们只是**不同种类的证据**，而混淆种类就是错误。

### 13.3 本篇没有覆盖的部分

| 未覆盖 | 为什么 |
|---|---|
| 真实语料的分布 | 只有零星探针，没有系统采样 |
| 多用户 / 长周期行为 | 全部观测都是单机短周期 |
| 参数的交互效应 | 只做过单参数扫描，没做过二维网格 |
| 时区与夏令时的真实覆盖 | 只做了构造用例，没在真实切换日验证 |
| 性能随规模的曲线 | 只测到 5000 张，之后是外推 |

**最后一条要特别说明**：第六章那张边数表在 $n=5000$ 是实测的，
「5000 以上会怎样」是**按二次关系外推的**。外推值不能当实测用——
如果建边在某处撞上内存或日志轮转的边界，曲线会拐弯，而**外推看不见拐点**。

### 13.5 三件本篇坚持要做的事

| # | 做法 | 为什么 |
|---|---|---|
| 1 | 每个数字带标注 | 不标注就等于把判断伪装成事实 |
| 2 | 每个「显然」都验算 | 本篇四次推导错误全部出在「显然」处 |
| 3 | 每个机制都问「它真的在起作用吗」 | 机制恒为空是本系统最高频的失效形态 |

**第 3 条值得最后说一遍。**

这套系统里出现过四次「机制完整实现、测试全绿、生产零效果」：

| 形态 | 表现 | 怎么发现的 |
|---|---|---|
| 生产零调用方 | 函数齐全，没人调用 | 全局搜索调用方 |
| 阈值落分布之外 | 判据恒假或恒真 | 打印分布分位数 |
| 两个阈值互相抵消 | 受益集合恒为空 | 三种模式总分逐位比较 |
| 产出非零但内容错 | 观测值正常，文本在说假话 | **读产出文本** |

**前三种可以靠探针发现，第四种只能靠读产出。**

> 不是读日志、不是读指标、是读那几句它写给用户看的话。
> 本篇记录的两处最严重的「假话」（主题词碎片、影子模式的假设值）
> 都是这样发现的，而不是靠任何数字。
